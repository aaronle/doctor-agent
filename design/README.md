# Doctor Agent 设计资产

**这里是 UI/UX 设计的唯一入口。** 之前设计图散在两个 Figma 文件和若干次会话里，
找一张图要翻聊天记录 —— 现在每一张都在 `exports/` 下，并由本文件索引到
「它对应哪条需求、实现了没有、原始文件在哪」。

> **为什么合并的是仓库而不是 Figma。** 本项目接的 Figma MCP 只能读
> 桌面端**当前选中的节点**，没有跨文件搬运的能力，两个文件要合成一个
> 得在 Figma 界面里手工搬。而真正会被人查的是「这张图对应哪条需求、
> 实现了没有」—— 那件事在仓库里做更准：PNG 和代码同一个 commit，
> 改了界面没换图会在 review 里露出来。Figma 文件保持原样，作为可编辑源。

## 改了界面要同步什么

一次界面改动的完整落点是四处，**少任何一处都会在下次找图时咬回来**：

1. `exports/` 下加导出图，并在上面的索引里补一行（含状态）
2. 对应需求文档（多数在 `docs/product/10-…` 或 `14-…`）
3. 还原度门禁 `scripts/compare-v43-fidelity.mjs` 的场景与选择器 ——
   **复刻原件的界面必须进那张表**，否则它落在门禁之外
4. `docs/testing/01-…` 的用例表

> 第 3 条有个例外：**有意偏离原件的东西不进那张表，改由单测把守**。
> 那张表比的是「同名 class 的计算样式」，而新做的类在原件里根本不存在，
> 三个选择器会全部落进「原件中不存在，跳过」——
> **一个什么都不比的场景比没有场景更糟**：它在输出里占一行 ■，
> 看起来像是有人在管。D1 卡通、＋菜单、「语」标记都是这么处理的。

功能**下线**时同样是这四处：图标为「已撤」、文档标存档、门禁场景删掉、
测试用例连着删。留一个永远红的门禁场景，下一个人只会给它加 skip。
