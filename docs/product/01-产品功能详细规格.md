# Doctor Agent 一期产品功能详细规格

版本：`v0.1-draft`
主责：产品功能开发条线
协作：Agent 集成条线、Agent 岗位定义和调优条线、临床与医务

## 1. 产品目标

Doctor Agent 是嵌入 AI-HIS 门诊工作流的临床辅助工作台。它不以聊天为主界面，而是在患者身份、就诊过程、病历编辑、诊断维护、风险提示和共病管理中提供可编辑、可拒绝、可追溯的 AI 结果。

一期产品成功的判断标准：医生能够在一个完整门诊流程中完成七个功能的调用与处理，即使底层暂时是 Mock，页面、任务状态、操作闭环、权限和审计也应按正式产品实现。

## 2. 目标用户与角色

| 角色 | 主要任务 | 一期权限 |
| --- | --- | --- |
| 门诊医生 | 接诊、问诊、病历、诊断、风险和共病处理 | 调用 Agent、编辑、采纳、拒绝、提交反馈、确认模拟写回 |
| 科室负责人 | 查看科室使用与问题、参与专科规则验收 | 查看任务与评测摘要，不直接修改单次医生结论 |
| 临床评测专家 | 标注金标准、评审误差和安全问题 | 使用去标识化评测工作台，不能访问无授权患者 |
| 产品/研发测试人员 | 验证功能、状态和异常路径 | 仅使用 Mock 或隔离测试患者 |
| 平台管理员 | 配置租户、科室、功能开关和运行版本 | 不拥有临床内容确认权 |

## 3. 从原 Demo 继承的体验语言

原 `AI-HIS门诊模块V4.3.html` 展示了以下可保留的产品体验：

- 本地演示打开后直接显示候诊列表；点击患者即进入医生智能体和该患者工作站。
- 顶部固定患者身份与安全信息条。
- 左侧患者队列、中间病历/诊断/医嘱、右侧 AI 工作区的高密度桌面布局。
- 门诊病历与 AI 智能笔记并排，支持快速回填。
- 诊断候选包含主次顺序、ICD 编码、概率/置信提示和依据。
- 检验检查阳性结果集中显示，支持进入详情。
- 医生智能体抽屉包含常用 Skill、语音入口、快捷动作和对话补充。
- 面板可收起、可调整宽度，支持键盘快捷键切换。

生产产品需要在此基础上增加：统一任务状态、来源证据、数据时间、风险等级、澄清、采纳/部分采纳/拒绝、医生修改差异、失败降级和审计入口。

## 4. 核心用户旅程

### 4.1 接诊前

1. 本地演示无需登录，打开系统即进入候诊列表。
2. 医生点击患者卡或“进入医生智能体”，系统绑定该患者与本次就诊并进入工作站。
3. 系统锁定 `patient_id`、`encounter_id`、科室和操作者，加载主诉、既往诊断、风险和数据新鲜度。
4. 医生智能体自动展开，并默认并行生成病情概况和鉴别诊断；智能笔记先显示“等待语音问诊”，不得提前生成病历草稿。
5. 正式环境启用医院 SSO 后，认证发生在候诊列表之前；认证方式不改变患者点击后的产品流程。

### 4.2 接诊中

1. 医生开启语音问诊或人工录入。
2. 语音结果以逐句转写和结构化信息并行展示，医生可纠错。
3. 病情概况在关键数据变化后刷新，但不覆盖医生正在编辑的内容。
4. 风险管理持续旁路运行，高危风险可打断流程。
5. 医生完成语音问诊后，系统自动调用病历生成；医生也可调用诊断管理和共病管理。
6. 所有 AI 内容先进入草稿态，医生可查看依据、编辑、部分采纳或拒绝。

### 4.3 接诊结束

1. 系统检查必填字段、未处理高危风险和身份一致性。
2. 医生确认病历、诊断和需写回内容。
3. 一期 Mock 阶段返回模拟写回回执；真实阶段由写回适配器执行。
4. 系统记录 AI 原文、医生修改、最终采纳结果、版本和写回回执。

## 5. 全局产品状态

| 状态 | 产品文案 | 允许动作 |
| --- | --- | --- |
| `idle` | 尚未运行 | 调用、查看触发条件 |
| `unavailable` | 当前不可用 | 查看缺少的身份、权限或数据 |
| `preparing` | 正在准备患者资料 | 取消、查看正在读取的数据源 |
| `running` | 正在生成 | 取消；页面不展示模型内部思维过程 |
| `needs_clarification` | 需要补充信息 | 回答问题、跳过非必填项、取消 |
| `ready` | 结果已生成 | 查看依据、编辑、采纳、部分采纳、拒绝 |
| `edited` | 医生已修改 | 查看差异、保存、恢复 AI 原文 |
| `accepted` | 已采纳 | 撤销、进入待写回队列 |
| `rejected` | 已拒绝 | 记录原因、重新生成 |
| `written_back` | 已写回 | 查看目标系统和回执 |
| `failed` | 执行失败 | 查看安全提示、重试、转人工 |
| `degraded` | 已降级 | 使用规则或静态模板结果、查看降级原因 |

## 6. F01 语音问诊

### 6.1 目标

把门诊对话转成可复核的逐句转写和结构化病史，识别医学实体、否定、时间、主体和最少必要的追问。

### 6.2 入口与触发

- 工作站顶部工具栏“语音问诊”。
- 医生智能体抽屉中的主按钮。
- 病历字段为空时的“从问诊生成”入口。

仅医生主动开始录音；不得默认后台录音。

### 6.3 界面组成

- 录音状态条：未开始、录音中、已暂停、设备异常、已结束。
- 实时转写区：说话人、时间戳、原文、低置信标记、纠错按钮。
- AI 追问提示框：医患对话承载在最右侧“医生智能体”内；提示框紧贴医生智能体左侧悬浮，随对话轮次动态显示已覆盖项、漏问项和下一句建议，不得另建一套中间问诊页面。
- 结构化提取区：主诉、症状、时间、严重程度、伴随症状、既往史、用药、过敏、家族史和特殊状态。
- 待澄清问题区：阻断问题与建议问题分开。
- 操作区：暂停、继续、结束、纠错、删除本段、生成结构化记录。

### 6.4 关键规则

- 未说过的内容不得自动填成“否认”或“无”。
- 低置信转写必须保留音频时间戳，并阻止自动进入已确认病历。
- 患者、家属和医生的陈述必须区分主体。
- 妊娠状态、过敏、急危重症状等关键缺口使用阻断式澄清。
- 医患对话逐条完成前不得自动生成病历；结束问诊后先完成转写结构化，再调用病历生成并显示可复核草稿。

### 6.5 验收标准

- 可完成开始、暂停、继续、结束和重新录制。
- 对话按医生/患者逐条出现，AI 追问提示会随问诊进展更新并标记已覆盖问题。
- 转写条目可逐条纠错且保留修改记录。
- 结构化结果能写入病历草稿区，但必须由医生确认。
- 无麦克风权限、网络中断和 Agent 失败均有明确降级路径。

## 7. F02 病情概况

### 7.1 目标

用问题导向方式汇总本次问诊与历史资料，帮助医生快速识别主要问题、变化趋势、关键证据、冲突和缺失数据。

### 7.2 触发

- 打开患者工作站后自动准备，默认不阻塞页面。
- 问诊结束、关键检验检查回传或诊断变更后提示刷新。
- 医生主动点击“刷新概况”。

### 7.3 卡片结构

- 一句话病情摘要。
- 当前主要问题，按临床优先级排序。
- 本次与历史变化。
- 关键检验、检查、用药和生命体征证据。
- 数据冲突与缺失。
- 数据截至时间和来源清单。

### 7.4 交互

- 点击证据定位到原始病历、检验或检查结果。
- 展开/收起历史时间线。
- 标记“与本次就诊无关”“数据错误”“需要补充”。
- 刷新时保留旧版本，可查看差异。

### 7.5 验收标准

- 每个关键事实均可定位来源与时间。
- 数据冲突不被静默合并。
- 概况刷新不覆盖医生正在编辑的病历。
- 患者身份或数据时间不明时不得显示为可采信结果。

## 8. F03 病历生成

### 8.1 目标

把已确认的问诊信息和临床事实组织为符合专科模板的门诊病历草稿。

### 8.2 病历字段

- 主诉。
- 现病史。
- 既往史。
- 个人史、婚育史或月经史等专科字段。
- 家族史。
- 过敏史。
- 生命体征和体格检查。
- 辅助检查。
- 初步诊断与处理建议草稿。

### 8.3 交互

- 全部生成、按段生成和重新生成。
- 逐段采纳、部分采纳、直接编辑和拒绝。
- 显示字段来源、AI 原文与医生修订差异。
- “恢复 AI 原文”不能覆盖医生未保存修改，必须二次确认。
- 提交病历前执行事实一致性和必填字段校验。

### 8.4 硬约束

- 不生成未证实的阳性或阴性体征。
- 不把推测诊断写成确定诊断。
- 不把过期检验结果描述为本次结果。
- 未经医生确认不得进入正式写回。

### 8.5 验收标准

- 支持原 Demo 中病历字段与智能笔记的并行编辑体验。
- 支持段落级来源与变更追踪。
- 失败时保留医生已输入内容。
- 可生成模拟写回回执和完整审计记录。

## 9. F04 鉴别诊断

### 9.1 目标

提供候选诊断、支持证据、反对证据、缺失信息和下一步建议，帮助医生扩大或收敛诊断范围。

### 9.2 卡片字段

- 候选名称、ICD 编码和排序。
- 状态：首选、次选、备选、必须排除。
- 支持证据与反对证据。
- 关键缺失信息。
- 建议补充问诊、检查或检验。
- 置信度只作为模型自评提示，不作为临床概率。

### 9.3 医生动作

- 加入诊断列表。
- 加入待排诊断。
- 标记“不考虑”并选择原因。
- 查看依据与原始数据。
- 触发最少必要的澄清问题。

### 9.4 验收标准

- 候选诊断不能直接变成确诊。
- 必须明确支持/反对证据和证据时间。
- 高风险漏诊项同步进入风险通道。
- 医生选择结果后能联动诊断管理，但保留独立操作记录。

## 10. F05 诊断管理

### 10.1 目标

维护主诊断、次诊断和待排诊断，记录诊断新增、删除、排序、合并和状态变化的原因。

### 10.2 交互

- 从鉴别诊断卡加入。
- 医生手工新增诊断并检索 ICD。
- 设置主诊断、调整顺序、标记确诊/待排。
- 删除或合并前填写原因。
- 保存前检查诊断与病历、用药、检验检查之间的明显冲突。

### 10.3 验收标准

- 诊断列表的每次变化均有操作者、时间、来源和原因。
- 鉴别诊断与诊断管理使用同一个诊断 Agent，但产品入口和结果形态独立。
- Mock 阶段只做模拟保存；真实写回适配器未启用时不能伪装成功。

## 11. F06 风险管理

### 11.1 目标

在接诊全程识别急危重红旗、身份冲突、过敏、用药、检验检查异常、妊娠/年龄特殊状态和关键数据冲突。

### 11.2 风险级别

| 级别 | 展现 | 行为 |
| --- | --- | --- |
| 红色/阻断 | 原界面的预警评估、风险卡或异常结果区域，明确证据与动作 | 必须确认或处置后继续关键流程 |
| 黄色/警示 | 原界面既有警示样式，不遮挡主体 | 可继续，但需记录已阅或忽略原因 |
| 蓝色/信息 | 原界面既有普通提示样式 | 可采纳、稍后处理或关闭 |

### 11.3 医生动作

- 确认已阅。
- 记录已采取动作。
- 标记误报并选择原因。
- 跳转原始证据。
- 红色风险的忽略必须二次确认并形成审计事件。

### 11.4 验收标准

- 风险状态跨页面保持，不因收起 AI 面板而消失。
- 强制红线 Mock 用例全部正确阻断。
- 风险卡显示规则/模型来源、证据、数据时间和版本。
- 风险 Agent 失败时，确定性规则仍可独立运行或明确告警。

## 12. F07 共病管理

### 12.1 目标

识别影响当前诊疗的慢病、长期用药和特殊状态，形成问题清单、管理目标、建议动作、随访和转诊建议。

### 12.2 卡片结构

- 共病名称与当前状态。
- 与本次主诉/诊疗的关联。
- 当前证据和数据时间。
- 管理缺口。
- 建议动作、随访周期和转诊/会诊提示。
- 优先级：本次必须处理、建议处理、长期随访。

### 12.3 医生动作

- 加入本次诊疗计划。
- 标记已管理、暂不处理或与本次无关。
- 发起转诊/会诊建议草稿。
- 查看纵向趋势和长期用药。

### 12.4 验收标准

- 不以泛化健康建议淹没本次主问题。
- 每条建议说明与本次就诊的关联。
- 内分泌 Mock 患者可展示糖尿病、高血压、血脂异常和肾病协同管理。
- 骨科和妇科 Mock 患者有各自专科相关共病与特殊状态。

## 13. 全局操作与审计

所有 Agent 结果至少支持以下动作：

- 查看依据。
- 编辑。
- 全部采纳。
- 部分采纳。
- 拒绝并选择原因。
- 重新生成。
- 提交错误/误报反馈。
- 查看任务详情和版本。

每个动作生成审计事件，最小字段包括：`task_id`、`patient_id`、`encounter_id`、`user_id`、`action`、`before_version`、`after_version`、`reason`、`occurred_at`。

## 14. 权限与患者安全

- 患者和就诊身份必须在顶部持续显示。
- 切换患者时取消或隔离前一患者未完成任务，禁止结果串用。
- 所有 API 同时校验用户、科室、患者和就诊范围。
- 医生不能看到无授权患者数据。
- 管理员不能替医生确认临床结果。
- Mock 数据必须明确显示“测试患者/模拟结果”，不能与真实数据混淆。

## 15. 产品验收矩阵

每个功能至少覆盖以下用例：

1. 正常成功。
2. 缺少非关键数据后降级成功。
3. 缺少关键数据，进入澄清。
4. 数据来源冲突。
5. 红色风险阻断。
6. Agent 超时。
7. Agent 返回非法 Schema。
8. 医生编辑并部分采纳。
9. 医生拒绝并反馈。
10. 患者切换时任务隔离。
11. 无权限调用。
12. 模拟写回成功和失败。

## 16. 产品线 Definition of Done

一个功能只有同时满足以下条件才算完成：

- 入口、可用条件和权限正确。
- `idle` 到终态的全部状态可见且可恢复。
- 成功、空数据、澄清、失败和降级页面齐全。
- 医生可查看依据并执行编辑、采纳、拒绝和反馈。
- 患者/就诊身份、数据时间、Agent/Mock 版本和医生确认状态可见。
- 前端不直接依赖 Mock 文件或 AgentScope 内部字段。
- 关键事件有审计记录。
- 通过桌面端 UI 检查、接口契约测试和医生 UAT 脚本。
