# F01/F03 语音问诊与病历生成 UI 需求规格说明书

版本：`v1.0-draft`  
日期：`2026-08-29`  
状态：进入产品、设计、开发和测试联合评审  
适用范围：Doctor Agent 一期，内科、骨科、妇科  
关联功能：F01 语音问诊、F03 病历生成

## 1. 文档目的

本文件将已确认的 UI 画面转化为可开发、可测试、可追踪的需求规格，明确：

- 对话出现在哪里、以什么顺序出现；
- AI 追问提示何时显示、更新和消失；
- 问诊在什么条件下完成；
- 病历何时开始生成，以及生成到哪些字段；
- 医生能够执行什么操作，系统必须阻止什么操作；
- Mock 演示与真实 AgentScope 集成必须遵守的共同接口边界。

本文不替代 F01、F03 的临床规则，而是它们的 UI、状态和交互权威细化说明。

## 3. 范围与非范围

### 3.1 一期范围

- 右侧“医生智能体”内呈现医生与患者的逐轮对话；
- 问诊进行时，在右侧面板左侧显示“AI 追问提示”；
- 追问提示随对话动态更新已覆盖项、待追问项和优先建议；
- 支持开始、暂停、继续、结束和重新问诊；
- 问诊完成后自动顺序调用语音问诊任务与病历生成任务；
- 在中间智慧诊疗的“智能笔记/病历”区域生成八类病历字段；
- 支持字段编辑、单字段送回医生草稿、失败重试和 Mock 回执；
- 内科、骨科、妇科共用同一套布局，以专科包切换问诊脚本、追问规则和字段内容。

### 3.2 一期非范围

- 不另建中间“语音问诊工作台”；
- 不自动签名，不正式写回 HIS/EMR，不自动生成处方或医嘱；
- 不展示模型思维过程；
- 不将未提及信息推断成“无”“否认”或正常；
- 不以 Mock 的固定播放时间作为生产性能承诺；
- 不因专科不同改变三栏主布局。

## 4. 页面结构与区域边界

| 区域 | 位置 | 一期职责 | 禁止行为 |
| --- | --- | --- | --- |
| A 主病历区 | 页面左侧 | 承载医生正式病历、医嘱及既有 HIS 内容 | AI 不得静默覆盖医生文本 |
| B AI 助手区 | 页面中间 | 承载智慧诊疗、病情概况、鉴别诊断和智能笔记 | 不新建第二套语音对话页 |
| C 医生智能体 | 页面最右侧 | 承载医患对话、问诊控制和问诊完成提示 | 不把完整问诊迁移到弹窗或独立页 |
| D AI 追问提示 | 紧贴 C 的左侧悬浮 | 显示问诊覆盖度、漏问项和下一句建议 | 不遮挡关键病历操作，不在问诊完成后残留 |

`UI-VR-001` 三栏布局、导航、卡片圆角、字体层级、间距和色彩以最早 HTML 为基线。  
`UI-VR-002` 医生智能体可收起；收起后必须保留问诊中的可见状态提示和停止入口。  
`UI-VR-003` 医生智能体重新展开后，必须恢复本次会话的对话、滚动位置和任务状态。  
`UI-VR-004` 页面不得出现“惠每”，不得显示“Mock 效果”作为面向医生的独立功能标签；Mock 身份只进入开发信息、审计或结果元数据。

## 5. 屏幕 S01：语音问诊进行中

视觉基线：[Figma 节点 7:2](https://www.figma.com/design/o9ZgZ6ujTK03MGOWQ2yQeC?node-id=7-2)（AI 追问提示）和 [Figma 节点 16:2](https://www.figma.com/design/o9ZgZ6ujTK03MGOWQ2yQeC?node-id=16-2)（补充观察展开）。

### 5.1 进入条件

1. 已绑定唯一 `patient_id` 和 `encounter_id`；
2. 医生点击语音按钮或“开始问诊”；
3. 系统清除当前就诊旧的未确认语音结果与旧病历生成结果；
4. 成功创建新的 `session_id` 后进入 `recording`。

未绑定患者、患者/就诊不一致或没有操作权限时，不得启动问诊。

### 5.2 右侧医生智能体元素

| 元素 ID | 元素 | 内容与行为 |
| --- | --- | --- |
| `VR-S01-01` | 标题栏 | 显示在线状态、“医生智能体”、收起与关闭入口 |
| `VR-S01-02` | 患者条 | 姓名、性别、年龄；必须与当前工作站患者一致 |
| `VR-S01-03` | 医生消息 | 绿色气泡，标签“医生”，保留原始顺序和时间戳 |
| `VR-S01-04` | 患者消息 | 蓝色气泡，标签“患者”；家属参与时必须显示“家属” |
| `VR-S01-05` | 流式状态 | 当前片段识别中可显示省略号/波形，不得伪装成已确认文本 |
| `VR-S01-06` | 暂停/继续 | 暂停后停止新增语音片段，已显示对话保留 |
| `VR-S01-07` | 结束问诊 | 停止收音，锁定本次转写版本并进入生成流程 |
| `VR-S01-08` | 补充输入 | 医生可键入或补录事实；必须标识为医生补充，不冒充患者原话 |
| `VR-S01-09` | 滚动区 | 新消息默认滚动到最新；医生向上查看时不得强制抢回滚动位置 |

`UI-VR-005` 对话必须逐条出现，不能打开后一次性把完整脚本全部铺出。  
`UI-VR-006` 新对话到达时，对应说话人、原文、时间戳与置信状态必须作为同一个消息对象保存。  
`UI-VR-007` 低置信片段必须提供纠错入口；纠错保留原文和修改审计。  
`UI-VR-008` 问诊进行中，中间智能笔记只能显示等待或处理中状态，不得提前展示完整病历。

### 5.3 AI 追问提示

| 元素 ID | 状态 | 表现 |
| --- | --- | --- |
| `VR-COACH-01` | `pending` | 尚未覆盖，显示正常文字和待问标识 |
| `VR-COACH-02` | `active` | 当前最优先追问，视觉突出并给出一句可直接使用的建议 |
| `VR-COACH-03` | `done` | 已由对话覆盖，显示完成标记并降低视觉权重 |
| `VR-COACH-04` | `blocking` | 影响安全或生成完整性的关键缺口，明确说明为什么必须补问 |

`UI-VR-009` 提示框固定在医生智能体左侧，不随对话内容在中间区域漂移。  
`UI-VR-010` 每当产生新对话片段或医生纠错后，重新计算覆盖状态。  
`UI-VR-011` 同一时刻只突出一个最高优先级建议，其他待问项按优先级排列。  
`UI-VR-012` 已覆盖项不得因 UI 刷新退回待问；只有相关原始信息被删除、改正或失效时才能回退。  
`UI-VR-013` 内科、骨科、妇科必须使用不同专科追问集，不能只把糖尿病问诊脚本复制到所有患者。  
`UI-VR-014` 问诊完成后提示框自动消失；若仍有阻断项，则不得进入“完整问诊”，而是进入 `needs_clarification`。

### 5.4 补充观察

“补充观察”是医生在问诊中主动补入的结构化临床事实，与患者语音转写、医生口头提问、AI 追问提示均为不同数据类型。

| 元素 ID | 元素 | 内容与行为 |
| --- | --- | --- |
| `VR-OBS-01` | 补充观察按钮 | 仅在 `recording` 或 `paused` 状态显示，位于暂停/继续按钮附近 |
| `VR-OBS-02` | 观察浮层 | 紧贴医生智能体左侧、位于追问提示下方；列表可滚动且不遮挡右侧对话 |
| `VR-OBS-03` | 动态候选项 | 由通用观察、专科包、当前诊断/主诉和已获得对话共同生成 |
| `VR-OBS-04` | 已选状态 | 选择后显示完成标记并防止重复写入；允许医生继续选择其他项 |
| `VR-OBS-05` | 对话回显 | 以医生来源的 `【补充观察】内容` 插入当前对话，并显示“补充观察”标签 |

`UI-VR-021` 补充观察不是 AI 自动结论，必须由医生点击选择或主动输入后才能进入上下文。  
`UI-VR-022` 观察候选项必须随内科、骨科、妇科和患者已知问题变化，不得为全科固定同一列表。  
`UI-VR-023` 选中的观察保存 `observation_id`、正文、来源、操作者、发生时间和当前 patient/encounter/session。  
`UI-VR-024` 补充观察在对话中标为医生内容，但不得冒充医生口述的 ASR 转写，也不生成虚假的语音置信度。  
`UI-VR-025` 插入补充观察不得改变固定模拟对话的播放索引，不得跳过医生或患者的下一轮对话。  
`UI-VR-026` 同一观察在同一会话内默认去重；医生需要修改时应形成更正版本并保留原记录审计。  
`UI-VR-027` 问诊结束后观察浮层自动关闭，已选观察保留在对话和结构化问诊结果中。  
`UI-VR-028` 病历生成必须消费已确认补充观察，并在对应病历字段的 `source_refs` 中引用观察 ID。  
`UI-VR-029` 观察内容若与患者陈述、既有检查或其他记录冲突，必须标记冲突并交由医生判断，不得静默覆盖任一来源。

### 5.5 专科提示与补充观察最低覆盖

| 专科 | 一期至少覆盖的追问主题 | 补充观察示例 |
| --- | --- | --- |
| 内科/内分泌 | 症状变化、用药依从、血糖/血压、低血糖、并发症、饮食运动 | 主食偏多、漏服降糖药、足部麻木、视力变化、睡眠和二便 |
| 骨科 | 部位、起病与诱因、疼痛性质、活动受限、外伤、麻木无力、大小便红旗 | 步态、活动范围、肢体肿胀、肌力、助行器、疼痛对睡眠影响 |
| 妇科 | 出血/疼痛、末次月经、月经与婚育史、妊娠可能、分泌物、贫血/休克红旗 | 面色、晕厥表现、出血量、下腹压痛、生命体征、乏力 |

具体临床阻断问题和表述必须由专科临床专家签字后进入生产规则包。

## 6. 屏幕 S02：问诊完成并生成病历

视觉基线：[Figma 节点 8:2](https://www.figma.com/design/o9ZgZ6ujTK03MGOWQ2yQeC?node-id=8-2)。

### 6.1 进入条件和视觉变化

最后一轮有效对话结束后：

1. 右侧保留完整医患对话；
2. AI 追问提示消失；
3. 右侧显示“问诊对话已完成，正在自动生成病历”或成功状态；
4. 系统先确认 `voice_interview` 结果，再调用 `record_generation`；
5. 中间智能笔记从等待态切换到生成态，成功后呈现八类字段；
6. 右侧提供“重新问诊”，但不得自动清除医生已编辑的正式草稿。

### 6.2 八类病历字段

| 顺序 | 字段 ID | 显示名称 | 生成规则 |
| --- | --- | --- | --- |
| 1 | `chief_complaint` | 主诉 | 核心症状/问题与主要时长；无时长时标记待补充 |
| 2 | `history_present_illness` | 现病史 | 起病、演变、伴随症状、诊疗经过；阴性事实仅限明确确认 |
| 3 | `past_history` | 既往史 | 既往疾病、手术、长期用药等；无记录不得写“无” |
| 4 | `personal_history` | 个人史 | 烟酒、职业、暴露及专科相关个人信息；未问则留空/待补 |
| 5 | `allergy_history` | 过敏史 | 只写已确认药物/食物/其他过敏；“未询问”不得改成“无过敏” |
| 6 | `physical_exam` | 体格检查 | 仅使用本次已录入体征和医生检查文本，不根据对话虚构检查 |
| 7 | `auxiliary_exam` | 辅助检查 | 带日期、数值、单位和来源；历史结果明确历史时间 |
| 8 | `preliminary_diagnosis` | 初步诊断 | 明确确诊、考虑或待排状态；不得作为正式诊断自动写回 |

`UI-VR-015` 八个字段必须全部拥有固定标签和独立编辑区域；无可靠内容的字段显示“待补充”或留空，不虚构。  
`UI-VR-016` 每个字段显示生成/已编辑/需补充/冲突等状态，并能追溯 `source_refs`。  
`UI-VR-017` 每个字段提供“回”或等义动作，将该字段送入左侧医生草稿；动作不代表正式 HIS 写回。  
`UI-VR-018` 医生编辑后的字段优先级高于后续 Agent 结果；重新生成不得静默覆盖。  
`UI-VR-019` 字段生成失败时保留完整对话和医生现有草稿，可按字段重试或人工填写。  
`UI-VR-020` 所有正式提交按钮在一期必须明确显示“模拟写回”或在回执中明确 `mode=mock`。

## 7. 状态机

| 当前状态 | 触发条件 | UI 表现 | 允许操作 | 下一状态 |
| --- | --- | --- | --- | --- |
| `idle` | 尚未开始 | 语音入口可用，无新会话 | 开始问诊 | `recording` |
| `recording` | 会话创建成功 | 对话逐条出现，追问提示可见 | 暂停、结束、纠错、补充 | `paused` / `finishing` |
| `paused` | 医生暂停 | 不新增片段，已显示内容保留 | 继续、结束 | `recording` / `finishing` |
| `finishing` | 医生结束或脚本完成 | 停止收音，确认最后片段 | 等待、取消生成 | `generating` / `failed` |
| `needs_clarification` | 存在阻断缺口 | 突出必须追问项，不生成完整病历 | 继续问诊、人工补充 | `recording` / `generating` |
| `generating` | 语音结果有效 | 对话保留，智能笔记显示生成中 | 查看对话、取消/重试 | `ready` / `failed` |
| `ready` | 八字段结果通过 Schema 校验 | 追问提示隐藏，字段可编辑 | 编辑、单字段送回、重新问诊 | `ready` / `recording` |
| `failed` | ASR/Agent/Schema/网络失败 | 显示失败范围和可恢复动作 | 重试、人工填写、重新问诊 | 原状态 / `idle` |

`BR-VR-001` `record_generation` 只能消费同一患者、同一就诊且状态为可用的 `voice_interview` 结果。  
`BR-VR-002` 任务调用顺序固定为 `voice_interview → record_generation`，不得并行抢跑。  
`BR-VR-003` 患者切换立即停止当前会话，清空可见 AI 结果；迟到响应只进入审计，不得显示。  
`BR-VR-004` 重新问诊创建新 `session_id` 和结果版本；旧版本可审计但不与新结果混为“最新”。  
`BR-VR-005` 问诊完成不等于病历确认，病历生成成功也不等于医生采纳或正式写回。

## 8. Agent 集成和数据契约

### 8.1 调用输入

```json
{
  "task_type": "voice_interview | record_generation",
  "patient_id": "string",
  "encounter_id": "string",
  "session_id": "string",
  "specialty_package_id": "internal_medicine | orthopedics | gynecology",
  "template_id": "string",
  "template_version": "string",
  "context_version": "string",
  "interaction_context": {
    "supplemental_observations": [
      {
        "observation_id": "OBS-1",
        "text": "近期足部偶有轻微麻木感",
        "source": "doctor_selected",
        "occurred_at": "date-time"
      }
    ]
  },
  "mode": "mock | runtime"
}
```

### 8.2 问诊结果最低字段

```json
{
  "status": "ready | needs_clarification | failed",
  "segments": [
    {
      "segment_id": "string",
      "speaker": "doctor | patient | family | unknown",
      "text": "string",
      "started_at_ms": 0,
      "confidence": 0.96,
      "corrected_text": null
    }
  ],
  "followup_items": [
    {
      "id": "string",
      "status": "pending | active | done | blocking",
      "question": "string",
      "reason": "string"
    }
  ],
  "result_version": "string"
}
```

### 8.3 病历结果最低字段

```json
{
  "status": "ready | partial | failed",
  "sections": [
    {
      "field_id": "chief_complaint",
      "title": "主诉",
      "text": "string",
      "state": "generated | edited | needs_input | conflict",
      "source_refs": ["segment_id-or-clinical-record-id"]
    }
  ],
  "record_version": "string",
  "mode": "mock | runtime"
}
```

`INT-VR-001` 返回结果在展示前必须校验 Schema、patient/encounter/session 和版本。  
`INT-VR-002` 缺少 `source_refs` 的临床事实不得进入可采纳状态。  
`INT-VR-003` AgentScope、Skill、MCP 或数据源超时必须标明失败环节，不得伪造成功结果。  
`INT-VR-004` Mock Adapter 与真实 Adapter 使用同一结果 Schema，切换运行模式不改变页面结构。  
`INT-VR-005` 前端只展示结果和依据，不展示模型内部推理链。
`INT-VR-006` 补充观察必须随 `interaction_context` 或等价的受控上下文引用传给 F01/F03，并进入结果证据链。

## 9. Mock 演示要求

`MOCK-VR-001` 点击语音问诊后直接播放对应患者和专科的模拟对话，不再要求用户点击“生成 Mock 效果”。  
`MOCK-VR-002` 对话必须逐轮播放并触发追问提示更新；不得一次性显示最终状态。  
`MOCK-VR-003` 最后一轮完成前，中间病历保持等待态；完成后模拟顺序调用两个任务。  
`MOCK-VR-004` 内科、骨科、妇科至少各有一套典型脚本和一套安全/澄清脚本。  
`MOCK-VR-005` Mock 结果仍需通过与真实 Agent 相同的 Schema、患者隔离和状态机校验。  
`MOCK-VR-006` 面向医生的主界面不需要反复出现“Mock”标签；运行模式可在结果详情或开发信息中查看。
`MOCK-VR-007` Mock 问诊允许选择补充观察；选中后立即回显，并在最终问诊结果和病历现病史中可追溯。

## 10. 异常、降级与恢复

| 异常 | 必须行为 | 禁止行为 |
| --- | --- | --- |
| 麦克风无权限 | 说明开启方式；允许文字补充或固定脚本演示 | 假装正在真实录音 |
| ASR 中断 | 保留已有片段，重连后去重 | 清空已显示对话 |
| 说话人不确定 | 标记“主体待确认”并允许人工指定 | 自动把未知主体归为患者 |
| 问诊 Agent 超时 | 原始转写可继续使用，追问降级为人工模板 | 阻断医生继续记录 |
| 病历 Agent 超时 | 保留对话和医生草稿，允许按字段重试 | 清空正式草稿 |
| Schema 非法 | 不展示不可信临床字段，提示重试/人工填写 | 尽力渲染未知临床字段 |
| 患者切换 | 停止会话并清空旧患者可见结果 | 将未完成会话带到新患者 |
| 版本冲突 | 显示 AI 新版、医生版及差异 | 静默覆盖医生内容 |

## 11. 可用性与无障碍

- `A11Y-VR-001` 医生/患者不能只靠颜色区分，同时显示说话人文字标签。
- `A11Y-VR-002` 新对话和状态更新使用合适的 `aria-live`，但不得连续打断屏幕阅读器。
- `A11Y-VR-003` 开始、暂停、继续、结束、纠错、重新问诊和字段送回可由键盘操作。
- `A11Y-VR-004` 提示完成/阻断状态同时使用图标、文字与颜色。
- `A11Y-VR-005` 1280px 及以上工作站视口不出现关键按钮被裁切；小于目标宽度时允许横向布局降级但不得丢失功能。
- `A11Y-VR-006` 长对话、长病历字段和 200% 浏览器缩放下不发生文字遮挡。

## 12. 审计与埋点

至少记录以下事件，并携带 patient、encounter、session、result version、operator 和时间：

- `voice_interview_started`、`paused`、`resumed`、`finished`、`restarted`；
- `transcript_segment_received`、`corrected`、`deleted`；
- `followup_item_activated`、`completed`、`skipped`；
- `record_generation_started`、`succeeded`、`failed`；
- `record_field_edited`、`accepted`、`rejected`、`sent_to_draft`；
- `late_result_discarded`、`schema_validation_failed`、`patient_context_mismatch`。

审计日志不得存储不必要的模型内部推理，不得把真实患者数据写入开发日志。

## 13. 验收标准

- `AC-VR-001` 对话只在最右侧医生智能体逐条出现，医生绿色、患者蓝色且均有文字标签。
- `AC-VR-002` 问诊进行中，左侧悬浮追问提示至少随对话更新两次，并显示待问、当前建议和完成状态。
- `AC-VR-003` 问诊结束前，中间智能笔记无完整病历结果。
- `AC-VR-004` 问诊完成后，完整对话保留、追问提示消失，病历生成自动开始。
- `AC-VR-005` 成功结果严格包含八类字段，过敏史不得缺失于字段结构。
- `AC-VR-006` 未被问及的事实不生成“无”“否认”或正常结论。
- `AC-VR-007` 医生编辑字段后重新生成，医生文本不被静默覆盖。
- `AC-VR-008` 患者切换、迟到响应、非法 Schema、任务超时不产生跨患者展示或内容丢失。
- `AC-VR-009` 内科、骨科、妇科在相同布局中播放各自脚本并生成各自内容。
- `AC-VR-010` 一期所有写回只产生 Mock 回执，不调用真实 HIS/EMR。
- `AC-VR-011` 实现与 Figma `7:2`、`16:2`、`8:2` 在结构、状态和核心视觉关系上可逐项对照。
- `AC-VR-012` 问诊进行中或暂停时可打开补充观察浮层，选择项以医生补充观察回显且不会跳过后续对话。
- `AC-VR-013` 补充观察进入 F01 结构化结果、F03 病历文本和 `source_refs`，患者切换后不会带入新患者。
