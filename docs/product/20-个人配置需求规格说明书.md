# 个人配置需求规格说明书

版本：`v1.0`
日期：`2026-09-07`
状态：待评审
适用：桌面端 `/settings`、移动端「我的 · 配置」

## 0. 一句话

让医生把界面调成自己顺手的样子，并且**下次打开还是那样**。

现在的实际情况是：全仓只有 4 个持久化点，真正算偏好的只有字号一项；浮窗拖完的尺寸、
位置、合并态**刷新即丢**（`useDockedWindows` / `useResizable` 全是纯内存）；移动端连字号
都不接。医生每天重复调一遍窗口，是当前最磨人的一项。

## 1. 范围

| 配置项 | 取值 | 默认 | 现状 |
| --- | --- | --- | --- |
| 界面色调 | `default` / `eyecare` / `contrast` | `default` | **全新**，当前无任何主题机制 |
| 界面字号 | `small` / `normal` / `large` / `xlarge` | `normal` | 已有（`useFontScale`），本次并入统一模型 |
| AI 追问初始状态 | `auto` / `always` / `manual` / `off` | `auto` | **全新**，当前恒为 auto 且不可改 |
| 记住浮窗布局 | 开 / 关 | 开 | **全新**，当前拖完刷新即丢 |

不在本期：深色主题、自定义取色、问诊播放节奏、减弱动画、默认标签页。
理由分别见 §3.5 与 §8。

## 2. 存储：双写

```
医生操作 → localStorage（立即生效，不闪屏）
         ↘ PUT /api/preferences（跨设备同步，可审计）
进入页面 → 先读 localStorage 上屏 → 再拉后端，不一致以后端为准并回写 localStorage
```

**为什么不只用后端**：每次开页要等一轮请求才能应用偏好，医生会看到默认样式闪一下。
**为什么不只用 localStorage**：换浏览器换电脑就没了，且你要求的「数据库调整」这条交付物落不了地。

### 2.1 「个人」以什么为键

一期没有 SSO。唯一在产品语义上成立的「当前医生」是前端 `stores/session.ts` 里的
`doctorName`（默认「张医生」）。后端表以它为主键。

**这个键是不可信的，任何人都能伪造。** 所以：

- 个人配置**不做访问控制**，也不作为访问控制依据。伪造的后果仅限于读到或改掉
  别人的界面颜色与字号 —— 真正需要保护的东西（岗位配置、写回门禁）不在这条路径上。
- 不引入 cookie/session 中间件。那会凭空造出一层**假的**身份边界，
  正是 `session.ts` 与 `config.py` 两处注释都在反对的东西。
- 接入医院 SSO 后把 `actor` 换成真实工号即可，表结构与本文件的逻辑都不变，
  与 `audit.DEMO_ACTOR` 是同一条演进路径。

### 2.2 只存差异

库里保存的是**与默认值不同的项**，读取时才与 `DEFAULTS` 合并。

这样以后调整默认值（比如把 `follow_up` 从 `auto` 改成 `manual`），所有没有显式设过
该项的医生会跟着变，显式设过的人不受影响。存全量做不到这件事 —— 每个存过全量的人
都会被钉死在他第一次打开配置页那天的默认值上，而他从未表达过这个偏好。

「恢复默认」是**删行**，不是写一份等于当前默认值的记录，同理。

## 3. 色调

### 3.1 约束：默认主题必须与 V4.3 逐像素相同

还原度门禁（`npm run fidelity`）逐元素比对 V4.3 原件的计算样式，146 个元素零差异。
主题功能**不允许**破坏这条基线，也不打算给门禁加一个「主题维度」——
那等于把一道已经稳定的闸放松。

### 3.2 障碍：主色不是一个颜色

扫描全部 scoped 与全局 CSS（不含只读参照文件）：

| 语义分组 | 出现次数 | 占比 | 色值种数 |
| --- | --- | --- | --- |
| 蓝（品牌色系） | 445 | 32.4% | 89 |
| 浅色底（各色淡背景） | 424 | 30.9% | 122 |
| 白 / 近白 | 118 | 8.6% | 4 |
| 中灰（次要文字） | 97 | 7.1% | 6 |
| 红（风险 / 危急） | 85 | 6.2% | 22 |
| 橙 / 琥珀（警告） | 63 | 4.6% | 25 |
| 深灰 / 墨（正文） | 55 | 4.0% | 12 |
| 绿（正常 / 通过） | 38 | 2.8% | 13 |
| 其余 | 47 | 3.4% | 10 |
| **合计** | **1372** | **100%** | **303** |

两个关键事实：

1. **`:root` 里那套 CSS 变量基本没被消费。** 设计令牌写着 `--blue: #3b6ef5`，
   但代码里用得最多的蓝是 `#1677ff`（111 次），令牌那个只有 27 次。
   深色文字同样分裂：`#1a2a4a` 用了 74 次，而令牌 `--ink` 是 `#1f2937`（12 次）。
2. **长尾极重。** 蓝色系 159 种色值里，前 12 种只覆盖 50.7%，前 30 种也只到 67.8%。
   逐个枚举替换做不完，而且做一半的话换主题会**花掉**：一部分跟着变、一部分不变。

### 3.3 解法：带回退值的变量替换，默认主题不定义任何变量

不做「归一到 12 档色阶」（那必然改变默认主题的像素）。改为**一色一变量、原值作回退**：

```css
/* 替换前 */  .btn-primary { background: #1677ff; }
/* 替换后 */  .btn-primary { background: var(--t-1677ff, #1677ff); }
```

- **默认主题不定义任何 `--t-*` 变量**，全部走回退值 → 计算样式与今天**逐字节相同**
  → 还原度门禁零差异，且这个性质是结构性保证的，不靠人工核对。
- 其他主题在 `[data-theme="eyecare"]` 下定义全部 `--t-*` → **100% 覆盖**，
  不存在「换了主题但有些地方没跟着变」。

替换与主题生成都由脚本完成，不手工改 CSS：

```sh
npm run themes    # scripts/build-themes.mjs
```

脚本做三件事：扫描 CSS 找出品牌色系色值 → 就地替换为 `var(--t-<hex>, #<hex>)` →
按各主题的色彩变换函数生成 `apps/web/src/styles/theme-<name>.css`。
**产物不手改**，与 `design/logo/` 下的图标产物同一条纪律。

### 3.4 什么不参与主题

**状态色锁死，不随主题变。**

红（风险 / 危急）、橙（警告）、绿（正常 / 通过）这 60 种色值排除在替换范围之外。
理由是临床安全，不是审美：**红色风险在任何主题下都必须是红色**。
一个医生把主题换成护眼绿之后，危急值提示也变成绿的 —— 这是会出人命的缺陷。

这条同时受 `docs/product/09` §F06 的既有约束保护：「颜色不得为唯一信息载体」，
风险等级必须并列文字与图标。主题化不得削弱它。

中性色（白 / 灰 / 墨，23 种）本期同样不参与 —— 它们只在深色主题下才需要变，
而深色主题不在本期。

### 3.5 三套预设

| 主题 | 定位 | 变换（HSL） |
| --- | --- | --- |
| `default` 默认蓝 | V4.3 原样 | 恒等（不定义变量，走回退值） |
| `eyecare` 护眼 | 长时间门诊、屏幕偏亮的诊室 | `h-14°`，`s×0.78`；`l>0.92` 时 `l-0.012` |
| `contrast` 高对比 | 强光诊室、视力欠佳的医生 | `s×1.22`；`l<0.5` 时 `l×0.82`，`l>0.90` 时 `l×0.985`，其余 `l×0.94` |

实算样例（`scripts/build-themes.mjs` 的输出，Figma `PREF-02` 用的就是这组值）：

| 令牌 | 默认 | 护眼 | 高对比 |
| --- | --- | --- | --- |
| primary | `#1677ff` | `#30a6e5` | `#056dff` |
| blue | `#3b6ef5` | `#4f99e1` | `#1f5cff` |
| blue-soft | `#eaf1ff` | `#e7f3fc` | `#e3ecff` |
| blue-soft2 | `#f2f6ff` | `#eef6fd` | `#ebf1ff` |

**两条边界条件是踩出来的，不要简化掉**：

1. `l>0.90` 时几乎不动明度。第一版 `contrast` 写的是「`l>0.5` 一律 `+0.05`」，
   结果把 `#eaf1ff` 这类浅蓝底纹**推成了纯白** —— 卡片底纹整块消失。
2. `eyecare` 的色相只挪 14°。第一版挪了 20°，`#1677ff` 变成 `#2bbaea` 的亮青色，
   已经不像同一个产品了。

改这两个函数后必须回看这四个值：**浅色底与纯白的差值要 >0.02**（RGB 三通道绝对差之和），
否则底纹被抹平。

**深色主题不在本期。** 它需要额外处理阴影、边框、状态色在深底上的可读性、
以及图片与图标的底色，且必须等中性色也纳入变量体系之后才可能做对。
在此之前上深色，结果一定是大面积不可读。

### 3.6 主题不改这三样

`--radius: 10px`、`--el-border-radius-base: 6px`、`--el-font-size-base: 12px` 不随主题变。
最后一条尤其重要：它是整个界面显得紧凑的根本原因，改了所有间距和行高全部走样。
字号由独立的字号档位控制，见 §4。

## 4. 默认大小

分两件事，配置页上分两组。

### 4.1 界面字号

沿用已有的四档（`useFontScale` 的 zoom 0.9 / 1 / 1.15 / 1.3），本次把它并入统一偏好模型。

**迁移**：现存的 `localStorage['doctor-agent:font-level']` 在首次进入时读一次，
写入新模型后即不再使用。不删除旧 key —— 万一要回滚，旧版本还能读到。

**本次修复一个既有缺陷**：移动端完全不接 `useFontScale`，字号偏好在手机上失效。
统一模型后两端共用一份取值。

### 4.2 浮窗布局记忆

开（默认）时：医生拖完的尺寸、位置、合并/分离态、分栏比例自动记住，下次进工作站恢复。
关时：每次都回到默认布局。

上下界必须与前端 `useResizable` 的钳位一致：

| 参数 | 范围 |
| --- | --- |
| `panel_width` | 260 – 560 |
| `drawer_width` | 640 – 1800 |
| `panel_height` / `drawer_height` | 320 – 2000 |
| `split_ratio` | 25 – 75 |

**两边必须一致。** 后端放行了前端也会钳回去，医生会以为设置没生效 ——
比直接报错更难查。

几何值由前端在拖拽结束后自动写入，**不是配置页上手填的**；配置页只提供
「恢复默认布局」把它清空。

## 5. AI 追问初始状态

| 取值 | 行为 | 适用 |
| --- | --- | --- |
| `auto`（默认） | 现状：满 3 条消息后自动浮出 | 多数医生 |
| `always` | 进入工作站即显示 | 依赖追问清单的医生 |
| `manual` | 默认关闭，点按钮才唤出；**照常计算** | 嫌打扰但偶尔要看 |
| `off` | 完全不出，**且不发起模型调用** | 完全不用这个功能 |

`manual` 与 `off` 的区别就在最后半句：`off` 是真的省一次调用，不是只把结果藏起来。

**一条安全约束**：`off` 只关闭「追问清单」这一个浮层，
**不影响风险预警、硬规则红线与写回门禁**。医生可以选择不看追问建议，
不能选择不看危急值。配置页上这一项的说明文字必须写明这一点。

## 6. 页面

### 6.1 入口与路由

- 桌面：`/settings`，从右上角医生名下拉进入。**不占用 V4.3 定义的五个医生端页面**，
  与 `/admin`、`/delivery` 同类。
- 移动：`/m/settings`，从「我的」进入。

因此两道界面闸（`fidelity` / `coverage`）**不比对本页** —— 它不在 V4.3 原件里，
靠单测守。这条与 `/admin`、`/delivery` 的处理一致，见 HANDOVER §2.1 的例外说明。

### 6.2 桌面端布局

单列卡片，宽 720px 居中。四个分组，每组一张卡：

```
┌────────────────────────────────────────────┐
│  个人配置                    [恢复全部默认]  │
├────────────────────────────────────────────┤
│  外观                                       │
│    界面色调   ( ) 默认蓝  ( ) 护眼  ( ) 高对比 │
│               ┌──────────────────────────┐  │
│               │  实时预览：按钮/标签/卡片   │  │
│               └──────────────────────────┘  │
│    界面字号   [ 小 ][ 标准 ][ 大 ][ 特大 ]    │
├────────────────────────────────────────────┤
│  医生智能体                                  │
│    AI 追问初始状态  [下拉：自动/始终/手动/关闭] │
│    └ 说明文字（随选项变）                     │
├────────────────────────────────────────────┤
│  工作区布局                                  │
│    记住浮窗尺寸与位置        [开关]           │
│    └ 当前已记住：面板 320×600、抽屉 900×720   │
│                            [恢复默认布局]    │
└────────────────────────────────────────────┘
```

要点：

- **色调必须有实时预览。** 三个色板色块不足以让人判断换完长什么样；
  预览区放按钮、标签、风险条、卡片各一个，**其中风险条用于证明状态色不跟着变**。
- 改动**立即生效并保存**，没有「保存」按钮。偏好是低风险、可逆、单人操作，
  加一步确认是多余的。保存失败时行内提示并保留本地值。
- 「恢复全部默认」二次确认，因为它会清掉浮窗布局记忆。

### 6.3 移动端

移动端是另一套信息架构（见 `12-移动端需求规格说明书.md`），配置页按其规范做：
整屏纵向列表、每项一行、点进去选，不用桌面的卡片布局。

**移动端不显示「工作区布局」整组** —— 移动端没有可拖拽浮窗，那组对它没有意义。
显示一个「桌面端布局已记住，可在电脑上重置」的说明即可。

### 6.4 状态与异常

| 情况 | 表现 |
| --- | --- |
| 后端不可达 | localStorage 值照常生效，页头提示「未能同步到服务器，本机设置仍有效」 |
| 后端返回 400 | 行内标红该项并回滚为改前的值，不整页报错 |
| 两端不一致 | 以后端为准，静默回写 localStorage |
| 首次进入 | 读到 `DEFAULTS`，与没设过表现一致 |

## 7. 数据与接口

### 7.1 表

`user_preferences`，一行一人，不版本化。

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `actor` | `String(64)` PK | 医生标识，见 §2.1。**不可信** |
| `prefs` | `JSON` | 只存与默认值不同的项 |
| `updated_at` | `DateTime(tz)` | `default=utcnow, onupdate=utcnow` |

沿用项目既有的「单键配置表」范式（`eval_dataset_states`、`knowledge_entries`），
不用自增主键 + 唯一索引 —— `database.py` 的补列机制加不了唯一索引。

整体存 JSON 而不是一项一列：唯一能做的迁移是 `ALTER TABLE ADD COLUMN`，
而偏好项在产品早期一定会反复增删，一项一列会把表长成一堵墙。
校验靠 `app/preferences.py` 的白名单，不靠数据库列约束。

### 7.2 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/preferences/options` | 取值集合与默认值。**前端不要自己硬编码枚举** |
| `GET` | `/api/preferences?actor=` | 永远返回一份**完整**偏好（已合并默认值） |
| `PUT` | `/api/preferences` | PATCH 语义，只传要改的项；幂等 |
| `DELETE` | `/api/preferences?actor=` | 恢复默认（删行） |

`GET` 必须返回完整偏好，否则前端要自己判断「没设过」和「设成了默认值」的区别。

`options` 由后端下发的理由：后端加了一档主题、前端没跟着改，界面上就永远少一个选项，
**且没有任何测试会失败**。

不挂在 `/api/config` 下 —— 那个端点返回的是服务端运行时事实，它的 PUT 刻意不写入
只回显；把个人偏好塞进去，那个语义立刻又变含糊，正是删掉 `voice_mode` 时
反复强调的错误类型。

### 7.3 审计

改偏好写 `update_preferences`，恢复默认写 `reset_preferences`，
`entity="user_preference"`，`entity_id=actor`。

**`detail` 只记改了哪些项的键名，不记取值。** 对齐审计表「不存正文」的口径。

## 8. 验收标准

| 编号 | 标准 |
| --- | --- |
| `AC-PREF-001` | 默认主题下 `npm run fidelity` 仍然 146 元素零差异零缺失 |
| `AC-PREF-002` | 切换到 `eyecare` / `contrast` 后，品牌色系**全部**跟着变，无遗漏色块 |
| `AC-PREF-003` | 任何主题下，红色风险条、危急值标记、警告色**保持原色不变** |
| `AC-PREF-004` | 任何主题下 `--el-font-size-base` 仍为 12px，间距与行高不变 |
| `AC-PREF-005` | 改任一项后刷新页面，设置仍在；换浏览器登录同一医生名，设置仍在 |
| `AC-PREF-006` | 关闭「记住浮窗布局」后，拖动窗口再刷新，回到默认布局 |
| `AC-PREF-007` | `follow_up=off` 时追问清单不出现，且**不产生模型调用**（查 `agent_runs`） |
| `AC-PREF-008` | `follow_up=off` 时风险预警与写回门禁**照常工作** |
| `AC-PREF-009` | curl 直接 PUT 非法取值（越界、未知项、拼写错误）一律 400，不静默丢弃 |
| `AC-PREF-010` | 后端不可达时配置页仍可打开、仍可改、本机生效并有明确提示 |
| `AC-PREF-011` | 移动端字号偏好生效（修复既有缺陷） |
| `AC-PREF-012` | 「恢复全部默认」后库里该行被删除，而不是写入一份等于默认值的记录 |

## 9. 分期

**一期（本规格）**：上表四项 + 三套主题 + 双写 + 配置页两端。

**后续候选**（按呼声排序，不做承诺）：

1. 深色主题 —— 需先把中性色纳入变量体系。
2. 默认标签页与默认展开态 —— 不同科室医生关注点不同，骨科可能想直接落在病历管理。
3. 问诊播放节奏（`TURN_INTERVAL_MS`，现写死 1400ms）—— 熟练医生嫌慢、新手嫌快。
4. 减弱动画 / `prefers-reduced-motion` —— 现在零支持，满屏 transition 硬编码。
5. 自定义取色 —— 需要先给医生一个不会调出不可读配色的取色器，成本不低。
