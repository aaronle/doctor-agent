# 移动端需求规格说明书

适用范围：`https://da.aaronhealth.cn` 在 **≤ 768px 视口**下的全部页面。
设计稿：Figma **AI 门诊工作站 · 一期设计系统**
`https://www.figma.com/design/c79Yrkq4MOgwjN3dulIvO7`
→ `04 · 移动端`（医生端六屏）、`05 · 控制台移动端`（控制台五屏）

判断标准与其他规格一致：**只读这份 Markdown 就能预期到界面的样子和行为。**

---

## 1. 为什么需要单独一份规格

移动端不是桌面端的响应式重排，是**另一套信息架构**。三条实测事实决定了这一点：

1. 桌面工作站是三层为 1600px 设计的固定宽度面板叠在一起。390px 里一次只能显示一个。
2. 设计令牌里 `html,body{overflow:hidden}`（取自 V4.3）。超出视口的内容不是「要横滑」，
   是**被裁掉、够不着**。适配前实测：AI 助手抽屉的八个标签页整个在屏幕外，
   医嘱面板根本不存在，患者管理的九列表格有五列点不到。
3. 桌面把 Copilot 放在右侧固定栏。那条栏在 390px 里放不下，
   而对话恰恰是手机上最顺手的交互。

## 2. 两条不可协商的产品规则

### 2.1 落地即对话

进入某个患者，**第一屏是对话，不是表单**。

AI 的分析不藏在标签页里等医生去点：打开工作站时算好的病情概要与风险，
开场就以结构化卡片推进对话流，卡片自带跳转动作。医生往下读、随手追问。

这些卡片不是伪造的聊天记录 —— 内容来自 `report-summary` 的真实产出，只是换了呈现位置。

### 2.2 移动端不写 HIS/EMR

以下三类动作在移动端**一律不提供**：

| 动作 | 桌面端位置 | 移动端 |
| --- | --- | --- |
| 提交病历 / 暂存病历 | 病历面板标题栏 | 不提供 |
| 确认并回写诊断 | 诊断管理标签页 | 不提供 |
| 开立医嘱 / 开立检查检验 | 医嘱面板「开嘱」 | 不提供 |

理由：手机上误触写进病历的代价太大，而「看 + 问 + 分析」正是手机擅长的部分。

**表现方式有三处，缺一不可：**

1. 顶栏常驻「👁 只读」徽标；
2. 记录页顶部黄色横幅写明「提交病历、回写诊断、开立医嘱请在门诊工作站完成」；
3. ＋ 菜单里这三项**列出来但灰显**，角标「工作站专属」。

第 3 点是刻意的：删掉的话医生会以为系统没有这些能力，而不是「这里不做、去工作站做」。

**不在此列**（写的是本系统状态，不落 HIS/EMR，移动端保留）：
患者提醒、重新接诊、语音问诊记录落库、红色风险的查看。

> 红色风险的**处置**需要留痕，仍留在工作站；移动端只展示待处置条数与提示。

## 3. 页面清单

| 页面 | 移动端形态 | 组件 |
| --- | --- | --- |
| 门诊工作站 | 对话 / 分析 / 记录 三档切换 | `mobile/MobileWorkstation.vue` |
| 候诊列表 | 单列卡片 + 筛选抽屉 | `mobile/MobileOutpatientList.vue` |
| 患者管理 | 统计 2 列 + 表格转卡片 | `mobile/MobilePatientManage.vue` |
| Agent 控制台 | 顶部岗位切换 + 底部四档 | `mobile/MobileAdminConsole.vue` |

**登录页已于 2026-09-01 移除。** 一期没有医院 SSO，那道「任意账号密码都能进」的门
是纯摆设 —— 既拖慢演示，又让人误以为这里有身份边界。根路径直接进候诊列表；
`/login` 保留为重定向（演示链接可能已经发出去了，硬 404 比重定向糟）。
「退出」按钮一并移除：没有登录态，那就是个假控件。

`styles/admin.css` 里仍保留一段 media query，作为**可达性兜底** ——
移动端组件万一没挂上，桌面控制台至少还能滚动、够得着。

## 4. 工作站三档

### 4.1 底部标签栏

`💬 对话（默认） / 📊 分析 / 📁 记录`

- 「分析」带角标：**未处置的红色风险条数**。为 0 时不显示。
- 底部固定区留 `env(safe-area-inset-bottom)`，否则按钮压在 iPhone 手势条下。

### 4.2 对话页

| 区域 | 内容 |
| --- | --- |
| 开场卡片 | 病情概要（含矛盾信息，并列不合并）+ 风险提示（**只列条目名**） |
| 对话流 | 医生提问 / AI 回答；回复完成后挂命中的知识库词条按钮 |
| 快捷动作 | 🎙 语音问诊 · 📄 报告解读 · 🔍 鉴别诊断 · ➡️ 接诊下一位（横向滚动） |
| 输入区 | ＋ 菜单 · 输入框 · 发送 |

风险卡片只列条目名：模型给的 `summary` 常有两三行，几条铺下来开场卡片就变成长文。
开场卡片的作用是让医生一眼看到「有几件事」，细节点「逐条查看」。

**换患者时清空对话上下文** —— 留着会把上一位的病情带进追问。

**诊断命令（`添加诊断：…`）不在移动端提供**：它读写的是诊断面板的勾选状态，
移动端没有那个面板，执行了也看不见。桌面端通过 `useCopilotChat` 的 `onCommand`
钩子注入，移动端不接。

### 4.3 分析页

桌面 AI 助手八个标签页的全部内容，折叠成手风琴，**每块带条数角标**：

`病情概要 · 鉴别诊断 · 预警评估 · 共病管理 · 专项评估 · 阳性结果 · 处置建议 · 病历质控`

- **默认只展开「病情概要」**，其余七块收着。
  首屏因此是一张带条数的目录，点哪块看哪块。
- 病情概要内部，「问题清单 N 项」与「疗效评估」再各自收一层 ——
  实测这两段合起来能有二十行，铺开的话后面七块要滚三屏才看得见。
- 鉴别诊断的 ICD 与置信度**另起一行**：跟诊断名挤一行会把长诊断名压折。
- 风险色点用后端给的 `color` 内联着色，不在前端另排一套映射。
- 处置建议末尾明写「开立医嘱与检查请在门诊工作站完成」，且不给按钮。
- 处置建议只列**推荐复查**与**推荐用药**；AI 处置单已于 2026-09-01 撤下
  （见 `10-V4.3反向需求规格说明书.md` §10.2.1），角标随之只数这两类。

### 4.4 记录页（只读）

分段控件：`病历 / 医嘱 / 检查检验 / 时间轴 / 健康档案`

- 病历字段用**纯文本**呈现，不做成输入框的样子。
  外观即承诺：长得像输入框就一定会有人去点，点了没反应比没有输入框更糟。
- 优先显示最近一次提交/暂存的病历，并标注「已提交 · 第 N 版」或「上次暂存 · 第 N 版」。
- 检查检验段列**完整记录**（含正常项），与只列异常的「阳性结果」区分开。
- 体征拼成一行。注意种子里 `bp` 有的写 `142/88`、有的写 `142/88 mmHg`，
  直接拼会出现 `mmHgmmHg`。

### 4.5 ＋ 菜单

三组，共 15 项：

| 组 | 项 |
| --- | --- |
| 问诊与分析 | 语音问诊、报告解读、鉴别诊断、预警评估、共病管理、专项评估 |
| 资料查阅 | 健康档案、就诊时间轴、常用提示词、检查检验、病历质控、患者管理 |
| 写入 HIS / EMR | 提交病历、回写诊断、开立医嘱 —— **全部灰显 + disabled + 「工作站专属」** |

菜单本质是导航器：点「健康档案」直达记录页那一段，点「预警评估」跳分析页并展开那一块。

### 4.6 语音问诊面板

复用桌面端同一个 `useVoiceInterview` —— 状态机、追问清单的语义覆盖判定、
补充观察的去重，全是同一份实现。手机上只换呈现：桌面的两个悬浮层改为面板内两段。

「结束问诊」落库问诊记录并重算分析（写本系统的库，不触达 HIS/EMR）。
**不在手机上重新起草病历** —— 那是要写进病历的动作。

## 5. 候诊列表与患者管理

### 5.1 候诊列表

- 页头压成一行；筛选收进按钮，点开底部抽屉。
- 卡片按钮叫**「接诊」不叫「进入工作站」**：手机上点进去是只读对话页，
  叫「工作站」名不副实。**桌面端仍是「进入工作站 →」，那是 V4.3 原件文案，不得改动。**

### 5.2 患者管理

- 九列表格 → 卡片。四张统计卡按 2 列排。
- 「提醒」「一键提醒高风险」「重新接诊」全部保留（见 §2.2）。
- 「重新接诊」只对已出队的患者显示 —— 它是给不可逆出队操作的退路。

## 5.3 Agent 控制台（移动端）

桌面是「240px 岗位侧栏 + 主区五标签」。390px 里侧栏放不下，改成
**顶部岗位切换 + 底部四档**：`⚙ 配置 / ▶ 试运行 / ✅ 回归集 / 📜 日志`。

**这里保留写入动作**，与 §2.2 的医生端规则不同 —— 改的是 Agent 配置，不是病历。

| 屏 | 关键约束 |
| --- | --- |
| 岗位切换 | 点顶部岗位名弹出底部选择器；**成功率摆在每行右侧，低于 90% 标红** —— 切岗位时最该先看到「哪个在掉」 |
| 配置 | 平台安全层**默认折叠**（24 行，铺开会把可编辑的岗位层挤出屏幕），但「不可编辑」这个事实始终可见，且该区不给任何输入控件 |
| 配置 | 「存草稿 / 发布」**固定在底部操作条**，不藏在长表单末尾 —— 手机上滚到底才发现按钮，等于让人多滚一屏才敢确认 |
| 回归集 | 数据集开关摆在结果**上方**：通过率必须有分母，关掉半个数据集也能把百分比刷上去 |
| 回归集 | 加载失败的数据集照样列出来并带原因，开关禁用 —— 静默藏起来等于少跑一集却看不出来 |
| 日志 | 八列表格 → 卡片。成功 / 降级 / 失败三色区分 |

状态全部来自 `composables/useAdminConsole.ts`，桌面与移动共用同一份 ——
抄一份的话以后改一个必漏一个（与 `useCopilotChat` 同样的理由）。

## 6. 技术约束

| 约束 | 理由 |
| --- | --- |
| 断点 `(max-width: 768px)` | iPad 竖屏及以上算桌面；768px 以下三层面板必溢出 |
| `matchMedia` 缺失时按桌面处理 | 无条件调用会让组件挂载失败 —— 那不是退化，是白屏 |
| 输入控件字号 ≥ 16px | iOS Safari 对更小字号在聚焦时自动放大整页，且不会缩回 |
| 底部固定区留 safe-area | 否则按钮压在 iPhone 手势条下 |
| 移动端类名一律 `m-` 前缀 | 桌面 DOM 里不出现，不可能与 V4.3 的作用域样式打架 |
| 登录/控制台的 media query 写在各自 scoped 样式表 | 全局规则优先级低于 scoped 的 `[data-v-*]`，写在 `mobile.css` 不生效 |
| 视口分流用 `v-if` 整块替换 | 移动端是另一套 IA，不是重排；桌面分支必须一字未动 |

**还原度门禁与类名覆盖率检查都在 1600×1000 下跑**，移动端组件不会挂载，
两道闸的结论不受影响。改完实测：146 元素零差异零缺失、八个标签页零类名缺失。

## 7. 测试

| 文件 | 覆盖 |
| --- | --- |
| `composables/useMediaQuery.spec.ts` | 断点、`matchMedia` 缺失、转屏、旧 Safari `addListener`、卸载退订 |
| `mobile/MobileWorkstation.spec.ts` | 落地即对话、开场卡片、只读徽标、角标、＋ 菜单、快捷动作、视口分流 |
| `mobile/MobilePanes.spec.ts` | 分析八块与折叠策略、记录五段与只读呈现、列表与患者管理 |
| `mobile/MobileAdminConsole.spec.ts` | 控制台四档、岗位选择器、安全层折叠与只读、数据集开关、日志卡片、视口分流 |
| `router.spec.ts` | 无登录后的路由与会话 store |
| `logging.spec.ts` | 前端结构化日志：关闭仍入缓冲、失败也记耗时、环形上限、`__da` 调试句柄 |

**最重要的一条**：`三个面板里没有任何可点的写入动作` ——
扫全部 `button/a/[role=button]`，而不是列举已知按钮；后者漏掉将来新加的那个就测不出来。
断言落在可点元素上而非整页文本，因为只读横幅里本就写着「提交病历…请在工作站完成」。

## 8. 已知取舍

1. **诊断命令**不在移动端提供，理由见 §4.2。
2. 移动端主色用项目自有令牌 `--blue (#3b6ef5)`，与 Figma 稿里的 `#1677ff`
   有细微色差 —— 后者是 V4.3 的组件色，前者是本项目全站主色，取后者更一致。
3. 控制台的**版本回滚**在移动端只给「回滚到上一版」一个入口，完整版本列表留在桌面。
   手机上摆一张可回滚的历史列表，误触代价太高。

> §8 原有的前两条（控制台没做专属 IA、登录页沿用桌面版）已于 2026-09-01 解决：
> 控制台有了 `MobileAdminConsole.vue`，登录页整个移除。
