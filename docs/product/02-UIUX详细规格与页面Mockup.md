# Doctor Agent 一期 UI/UX 基线规格

版本：`v0.3-confirmed`
确认日期：`2026-08-28`
原始 HTML：[`references/ui-demo/AI-HIS门诊模块V4.3.html`](../../references/ui-demo/AI-HIS门诊模块V4.3.html)
当前产品基线：原始 HTML 的视觉与主体交互，以及当前 Vue 实现的候诊列表直达流程

## 1. 已确认结论

一期产品沿用最早的 `AI-HIS门诊模块V4.3.html`。当前产品基线包含以下已确认差异：

1. 删除界面内所有“惠每”文字。
2. 本地演示不显示登录页，打开后直接进入 `/outpatient/list` 候诊列表。
3. 点击任一患者卡或“进入医生智能体”后进入 `/outpatient`，自动展开医生智能体和该患者的智慧诊疗结果。
4. 正式环境仍保留医院 SSO 接入边界；关闭自动进入配置后可恢复认证前置流程。

- 页面布局不重新设计。
- 信息架构不重新设计。
- 导航层级、操作路径和交互方式不改变。
- 颜色、字体、圆角、间距、卡片、表格、弹窗和面板样式沿用原 HTML。
- 不以此前制作的新版原型或 Figma 探索稿作为开发、测试或验收依据。
- 7 个产品功能以增量方式接入原界面的既有区域，不为了容纳 Agent 能力改造整套工作台。

除上述三项差异外，不改变原页面结构、控件样式或操作路径。正式机构名称和 Logo 是否加入界面，等待后续单独确认。

## 2. 开发基线

### 2.1 必须直接继承

- 候诊列表、医生工作站和患者管理的页面结构；登录页只作为正式 SSO 接入时的身份边界参考。
- 医生工作站现有主临床区、AI 辅助区、医生智能体区和智能笔记区。
- 原有顶部导航、患者信息、标签页、按钮位置、卡片形式和弹窗形式。
- 原有桌面端信息密度、响应式行为和主要操作反馈。
- 原 HTML 中已经存在的候诊、接诊、病历、诊断、检验检查、预警及患者管理流程。

### 2.2 一期不得自行改变

- 不合并或拆分原有面板。
- 不新增一套“统一 Agent 工作区”替换现有区域。
- 不将现有交互改造成聊天优先、抽屉优先或卡片优先的新模式。
- 不调整主栏、侧栏的宽度关系和展开/收起逻辑。
- 不引入新的设计令牌替换原 HTML 的视觉体系。
- 不以个人审美调整字号、色值、阴影、圆角或留白。
- 不因技术框架迁移而改变用户可见行为。

## 3. 七个功能在原界面中的承载位置

下表描述功能接入位置，不代表新增导航或重做页面。最终实现应优先复用原 HTML 已有入口、区域和交互控件。

| 功能 | 原界面主要承载区域 | 一期增量内容 |
| --- | --- | --- |
| F01 语音问诊 | 医生智能体/问诊相关入口 | 录音、转写、结构化提取和澄清状态 |
| F02 病情概况 | AI 辅助或医生智能体结果区 | 综合病情摘要、主要问题、缺失与冲突 |
| F03 病历生成 | 门诊病历、病历管理、智能笔记 | 分字段生成、采纳、编辑和保存状态 |
| F04 鉴别诊断 | 智慧诊疗/诊断建议区域 | 候选诊断、支持依据、反对依据和待补信息 |
| F05 诊断管理 | 原诊断列表及智慧诊疗区域 | 主次诊断、待排诊断、排序和模拟写回 |
| F06 风险管理 | 风险预警、风险卡和异常结果区域 | 风险分级、依据、处置状态、查看详细和闭环记录 |
| F07 共病管理 | 智慧诊疗、医生智能体或患者管理相关区域 | 共病状态、相互影响、管理缺口和行动建议 |

如原 HTML 中同一位置需要承载多个功能，应复用其既有标签、卡片、弹窗或切换方式，不得未经确认创建新的一级界面。

## 4. 功能文档与 UI 的关系

各功能 Markdown 中的 `UX-Fxx-nnn` 用于规定需要展示的业务信息、调用状态、医生操作、人工确认及安全规则，不授权修改原 HTML 的视觉设计或页面结构。

文档中出现“卡片”“抽屉”“工作区”“侧边栏”等词时，应理解为逻辑承载形式；开发时必须首先映射到原 HTML 已存在的对应组件。确实无法承载时，先形成差异说明并由产品负责人确认，不得直接重做 UI。

## 5. 品牌替换边界

当前确认删除浏览器标题、顶栏及页面内的“惠每”两字，不自动补入新的品牌前缀。本地演示不展示登录页。正式机构名称、产品名称和 Logo 由院方后续确认。

品牌替换不改变原 HTML 的主色调、辅助色、控件、卡片、背景、风险色、状态色、字体、圆角、边框、阴影和间距。

## 6. UI 状态补齐原则

为了让 Mock Agent 和真实 Agent 可切换，可以在原组件内补齐未调用、数据准备中、执行中、需要补充信息、结果就绪、结果过期、失败/降级、医生已采纳/编辑/拒绝及模拟写回结果等业务状态。

新增状态必须复用原 HTML 已有的加载、标签、提示、弹窗和消息反馈样式。

## 7. UI 验收基准

一期 UI 验收以原始 HTML 与实现页面逐屏对照为主：

1. 页面区域、导航和主要控件位置与原 HTML 一致。
2. 原有主要操作路径没有被改变或额外增加不必要步骤。
3. 原 HTML 已有功能没有因为 Agent 接入而退化。
4. 7 个产品功能能够在既有界面区域被找到和使用。
5. Mock 与真实 Agent 切换不改变界面结构。
6. 医生输入不会被 Agent 刷新或迟到结果覆盖。
7. 风险、来源、人工确认和模拟写回状态可识别。
8. 页面不得残留“惠每”的名称、Logo 或产品归属。

## 8. 变更控制

后续任何布局、导航、控件样式、颜色、交互路径或新页面变更，都必须先列出相对原 HTML 的差异和业务原因，获得产品负责人明确确认后，再同步修改需求、设计、测试和实现。

在未获得新确认前，本文件、最早 HTML 原件及当前派生 HTML 共同构成一期 UI/UX 的有效基线；实现以当前派生 HTML 为直接对照。
