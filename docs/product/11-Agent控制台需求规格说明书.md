# Agent 控制台需求规格说明书

版本：`v1.0`
日期：`2026-08-31`
定位：面向**产品管理员与调优人员**，挂在 `/admin`，**不是医生端的第八个功能**

---

## 0. 要解决的问题

控制台第一版已经能改配置、能发布回滚、能看运行日志。但它缺了最要紧的一环：

> **改完提示词只能盲发。**

管理员改一句话，点发布，然后去医生端刷新页面看效果 —— 这中间没有任何反馈。
更糟的是改动**已经生效了**：判断"改坏了"的时候，坏的版本正在给医生用。

所以这一版的主线不是"补更多配置项"，是**把发布前的反馈补上**。

### 0.1 四件事，按价值排序

| # | 能力 | 解决什么 |
| --- | --- | --- |
| 1 | **试运行** | 不发布就能看到草稿配置的真实输出 |
| 2 | **并排对比** | 草稿 vs 线上，判断改好了还是改坏了 |
| 3 | **回归集** | 修好 A 常常弄坏 B，单次试运行看不出来 |
| 4 | **参数与失败样本** | 温度/长度可调；解析失败时看得到模型到底吐了什么 |

排在最后的两项不是不重要，是**没有前两项时它们没用** —— 调了温度也不知道调好没有。

## 1. 试运行

### 1.1 契约

```
POST /api/admin/agents/{agent_key}/dry-run
{ "patient_id": "P001", "use": "draft" | "published" }
→ { output, provider, degraded, elapsed_ms, total_tokens,
    model, model_tier, config_source, prompt_hash, schema_valid, violations[] }
```

### 1.2 硬约束

**试运行必须完全不影响生产。** 具体是四条：

1. **不写缓存。** 否则一次试验会把聚合结果污染半小时，医生端跟着受影响。
2. **不落病历草稿、不产生医嘱、不留业务审计。** 试运行是看，不是做。
3. **不计入运行统计。** 运行日志的定位是「生产运行的可追溯记录」；
   把试验混进去，成功率这个数字就废了 —— 调优期间大量试错会把它拉到很低，
   而那恰恰是最需要靠它判断线上健康度的时候。
4. **只允许演示病例。** 一期本来就只有虚构数据，但这条要写死在服务端，
   不能只靠界面不给入口。

### 1.3 为什么试运行可以显示完整输出

运行日志刻意不返回 `output`（日志不该成为病历副本）。试运行相反 ——
看输出就是它的全部意义。两者不矛盾，因为：

- 试运行只跑演示病例，`data_classification` 是 `MOCK_ONLY_NO_REAL_PATIENT_DATA`
- 输出**只在本次响应里返回，不落库**

接真实患者数据后这条要重新评估：那时试运行要么改用脱敏样本，要么加操作审计。
**已在第 5 节列为待决事项，不要默认沿用。**

## 2. 并排对比

同一个病例，草稿与线上各跑一次，两栏并排。

**不能只给两坨 JSON。** 输出动辄几十个字段，人眼比不出来。要给的是：

| 维度 | 呈现 |
| --- | --- |
| 结构差异 | 逐字段标 `新增` / `删除` / `变化`；数组比长度与逐项 |
| 降级 | 两边各自是否降级 —— 一边降级时的对比没有意义，要显式提示 |
| 耗时 / Token | 并列。提示词变长会同时抬高两者，这是发布前该知道的成本 |
| 红线 | 两边各自触发了哪些红线（见 3.2） |

**并排的两次调用要并发发起**，否则调优一次要等两倍时间。

## 3. 回归集

### 3.1 为什么必须有

改提示词修好一个病例、弄坏另一个，是这类工作最常见的失败模式。
单次试运行只能看到你正在看的那个病例。

### 3.2 校验必须是确定性的

**不做「看起来不错」这种校验，也不用模型给模型打分** —— 那只会得到好看的分数。
能确定性判定的有这些：

| 检查 | 判定方式 |
| --- | --- |
| Schema 合法 | 按岗位的 `output_schema` 校验 |
| 必填字段非空 | 字段在且不是空串/空数组 |
| 闭集取值合法 | 如推荐科室必须来自科室字典、风险等级必须是三档之一 |
| 不编造查体 | 输出里出现查体结论，但上下文没有对应体征 |
| 未问诊不写否认 | 出现「否认/未见异常」类表述，而对话全文没问过 |
| 逐例断言 | 该病例特有的期望，由人写（见下） |

### 3.3 期望值由人写

逐例断言的形式是**"输出里必须/不得包含某个字符串或满足某个条件"**，写在用例里。

**系统不自动生成期望值。** 拿当前输出当基线，等于把今天的行为固化成正确答案 ——
今天的行为如果是错的，回归集会忠实地保护这个错误。

### 3.4 契约

```
GET  /api/admin/eval-cases                        → 用例清单
POST /api/admin/agents/{agent_key}/eval
     { "use": "draft" | "published" }
→ { total, passed, failed, cases: [{ case_id, patient_id, passed,
                                     checks: [{ name, passed, detail }],
                                     elapsed_ms, degraded }] }
```

一次跑完全部用例，**逐例并发**但**限制并发数** —— 网关有速率限制，
一次打十几个并发只会换来一片 502，那看起来像"改坏了"，其实是打太急。

## 4. 参数与失败样本

### 4.1 可调参数

`params` 字段早就有，界面没暴露。开放两个，**都带上下限**：

| 参数 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| `temperature` | 0 – 1 | 0 | **临床岗位默认 0**。调高会让同一份病历每次生成不同，无法复核 |
| `max_tokens` | 512 – 8192 | 4096 | 太小会截断 JSON，导致整个岗位降级（一期真踩过） |

界面上要写清楚这两条后果，不是干放两个滑块。

### 4.2 失败样本

现在解析失败只留一句 `error`，调优的人根本不知道模型吐了什么。

【增强】`AgentRun` 增加 `raw_excerpt`：**仅在失败时**保存模型原始输出的前 500 字符。

- 只在 `status != 'ok'` 时写 —— 成功的输出不留，避免日志变成病历副本
- 截断到 500 字符 —— 定位格式问题够用，不足以复原一份病历
- 一期只有虚构病例；接真实数据前要重新评估（见第 5 节）

这条的价值在一期已经验证过：早先「模型返回未转义的半角双引号导致 JSON 解析失败」
就是靠人工抓原始输出才定位的，当时日志里什么都看不到。

## 5. 安全边界与待决事项

**不变的**：

- 平台安全层仍不可编辑，只随代码发布。控制台只读展示。
- 自定义提示词不能绕过安全层 —— 安全层在服务端拼接，不由岗位配置决定。
- 控制台不下发密钥，健康接口与所有 admin 响应都不含 `AI_API_KEY`。

**接真实患者数据前必须重新评估的**（不要默认沿用一期的做法）：

1. 试运行返回完整输出 —— 届时要么改用脱敏样本，要么加操作审计与权限。
2. 失败样本 `raw_excerpt` —— 真实数据下即使 500 字符也可能含患者信息。
3. ~~控制台没有登录与权限~~ —— **产品已明确：演示阶段 `/admin` 允许任何人访问**（2026-08-31 决定）。
   接真实患者数据时这条要重新拿出来评估：届时控制台能改提示词、能发布，
   等于能改变所有医生看到的 AI 输出，必须接 SSO 并做角色隔离。

## 6. 验收

### 6.1 实施中修正的三处校验缺陷

回归集第一次跑就把**自己的**问题挑了出来，这正是它该干的事 —— 先证明期望值本身是对的。

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| 病历七段裹在 `fields` 里 | 病历岗位每条用例都挂在「缺字段」 | 加 `sections()` 兼容两种形状 |
| 期望值按人的说法写 | 断言「含 HbA1c」，而模型输出中文「糖化血红蛋白」 | 期望值按模型实际用语写 |
| 读错上下文键 | 读 `ctx['dialog']`，实际键名是 `dialog_script` | 改读正确键 |

改完还剩一个更深的问题：**校验拿书面语「否认」去对话里找，而患者只会说「没有」**，
于是永远找不到、每条都判违规。真正的判据是**「这个话题问没问过」** —— 取否定词后面
被否认的那个话题（如「视力模糊」），去对话里找它。

话题匹配还得用**任意二字窗口**：医生问「有没有胸痛」、病历写「否认典型胸痛」，
取前两字「典型」照样误报。

**误报比没有校验更糟** —— 人会学会忽略它，真出事时也就不看了。这几条边界各有一条测试。

| 项 | 门禁 |
| --- | --- |
| 试运行不污染生产 | 试运行后聚合缓存未变、运行日志条数未增 —— 各一条测试 |
| 试运行只收演示病例 | 非演示 ID 返回 4xx |
| 对比并发 | 两次调用并发发起，总耗时接近单次而非两倍 |
| 回归校验确定性 | 同一输入连续两次判定结果一致 |
| 参数边界 | 越界值被服务端拒绝，不是靠界面拦 |
| 失败样本 | 成功时不写 `raw_excerpt`，失败时写且不超过 500 字符 |
| 安全层 | 任何路径都改不了安全层 |
