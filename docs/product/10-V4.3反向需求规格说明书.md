## 0. 这份文档是什么

**它是从既有界面倒推出来的需求书**，不是先有需求再画界面。

之所以要倒推：V4.3 是一个已经打包编译的可运行原型，界面与交互都已定型且被认可，但没有对应的需求文字。没有这份文字，任何人重建时都只能靠看截图猜，而截图看不出交互、状态、数据来源和边界条件 —— 一期已经因此漏做过整块功能（健康档案、病历质控、语音问诊的追问提示）。

**从下一次开始，流程反过来走**：需求 Markdown → UI/UX → 测试用例 → 编码 → 测试 → 部署。这份文档就是那条链路的起点。

### 0.1 两条不可协商的约束

1. **UI/UX 保持原汁原味。** 界面形状、布局、配色、图标、文案、交互节奏一律以 V4.3 为准，不得「优化」。判断依据不是肉眼，是 `npm run fidelity` 的逐元素计算样式比对。
2. **功能可以比原件更强。** V4.3 的「AI」是按关键词匹配预写文案，没有真实推理、没有持久化、没有权限与审计。增强这些不改变界面形状，因此允许 —— 但每一处增强都要在本文档中显式标注。

### 0.2 标注约定

| 标注 | 含义 |
| --- | --- |
| 【原件】 | V4.3 中已存在，形状与行为均须复刻 |
| 【增强】 | V4.3 没有或只是空壳，我们做成真实能力；**不得改变界面形状** |
| 【缺口】 | V4.3 中存在但当前实现尚未覆盖，待排期 |

## 1. 抽取方法与事实源

V4.3 不是静态 HTML，而是**编译打包的 Vue 3 + Element Plus + Pinia + vue-router 单页应用**，1.90 MB 单文件，1 个 `<script>`、0 个外链样式表，全部依赖内联，`axios` 被 mock 适配器接管，**零真实网络请求**（产物里那 12 个外部 URL 全是 XML 命名空间与 Element Plus 报错信息里的文档链接）。

这决定了倒推的方法：不靠看，靠跑。四个脚本，产物全部可复现：

| 脚本 | 产出 | 用途 |
| --- | --- | --- |
| `extract-v43-assets.mjs` | `app.css`（1219 条规则）、`design-tokens.css`、8 份 fixture、`inventory.json` | 静态资产与数据形状 |
| `extract-v43-dom.mjs` | `dom/` 下 30 个界面状态的渲染 DOM、结构骨架、计算样式、截图 | 结构事实源 |
| `split-v43-css.mjs` | 按组件作用域拆分的 CSS + `app-overrides.css` | 样式实现依据 |
| `extract-v43-tabs.mjs` | `tabs/` 下每个标签页的类名、图标、配色规则、结构文案 | 逐页实现参照 |

一次性重跑：`npm run extract`。

**产物不是逐字节可复现的，重跑必然产生 diff**，但都是噪声，不必紧张：
Element Plus 的实例计数器（`el-id-9301-*` → `el-id-7087-*`）每次运行都变；
页头的日期时间与由它算出的天数随当天变；`computed.json` 里的 `width` 会因滚动条
有无浮动一两个像素 —— 这也是还原度比对**不比 width/height** 的原因之一。
判断有没有采歪，看结构与类名，不看 diff 行数。

### 1.1 抽取中踩过的三个坑（写进来避免重犯）

1. **路由守卫**：未登录时任何 hash 都被打回登录页。采集顺序必须是「先抓登录页 → 登录一次 → 之后只改 hash」，全程不整页重载。
2. **动态状态有时间窗**：语音问诊的追问提示浮层约 7 秒后随播放结束消失。首轮采集等了 9 秒，采到的是空状态，导致整块功能从未进入产物。**动态状态必须按原件的时序采集。**
3. **CSS 不能扁平化**：应用样式带 `[data-v-xxxxxxxx]` 作用域属性，同名类在不同组件里声明并不相同（`.his-header` 在工作站是 46px 高、候诊列表是 56px 高）。必须按作用域拆分后放进各 SFC 的 `<style scoped>`。另有一层**不带作用域的 `!important` 覆盖**（把表头改成白底、标题改成深色），漏掉它整个表头会走样。

#### 3.4.2.1 病历的暂存与提交【增强·重要】

**此前这两个按钮是假的**：「提交病历」只弹一句「病历已提交（写入本地库并留审计）」，
实际不落库、不留审计、刷新即失；「暂存」连处理函数都没有。伪造的成功文案是最不该
出现的一种缺陷 —— 它让医生对系统建立错误的信任，而错误的信任比明确的缺失更危险。

| 端点 | 门禁 | 用途 |
| --- | --- | --- |
| `POST /api/emr/record/stash` | **不过门禁** | 「还没弄完，先存着」 |
| `POST /api/emr/record/submit` | 主诉非空 + 红线闭环 | 落库 + 审计 + 写回主档 |
| `GET /api/emr/record/{id}` | — | 读回最近一次，刷新后恢复 |

- **暂存刻意不过红线门禁。** 它的用途正是保存未完成的工作；拿门禁拦住暂存，
  等于逼医生要么一次做完、要么丢掉已经写的内容。
- **提交的红线门禁在服务端。** 与诊断回写共用 `_assert_red_alerts_closed` ——
  各写一份的话，哪天规则改了必然漏一处，而漏掉的那处就是能绕过红线的入口。
- 每次保存递增版本、旧版保留，病历改动可追溯。

### 3.4.2.3 一次就诊的「结束」【增强】

**此前系统里没有「就诊结束」这个概念。** `in_queue` 字段存在，但除了种子数据，
没有任何地方会把它置为 false —— 于是「今日候诊 6 人」永远是 6，医生看完全部
患者，队列纹丝不动。「接诊下一位」也只是跳路由，不改变任何状态。

一次就诊没有终点，这个系统就只是个查看器，不是工作台。

| 动作 | 队列 |
| --- | --- |
| 暂存病历 | **不出队** —— 它的语义就是「没弄完」 |
| 提交病历 | **出队**，本次就诊完成 |
| 患者管理 ·「重新接诊」 | 放回队列 |

- 出队后患者仍在**患者管理**页可见，标记为「已完成」。两个列表口径本就不同：
  `/patients` 只给在队列的，`/patients/manage` 给全部并带 `in_queue`。
- 提交后前端**刷新队列**，否则计数不变，看着像没生效。
- **必须有「重新接诊」这条退路。** 出队是不可逆的单向操作 —— 误点一次，
  医生的列表里就再也找不到这个人了。

### 3.4.2.2 红色风险处置与质控审阅的留痕【增强】

同一类问题：确认按钮上写着「已处置并**留痕**」，而处置只改前端内存。
它又门控着病历提交 —— 于是**医生刷新一次页面，得把所有红线重新处置一遍**。

- `POST /api/emr/alerts/handle`：落患者主档 + 审计。落主档而不只留审计，
  是因为**下次打开要能恢复** —— 审计是给事后查的，恢复现场需要能读回的状态。
- 已处置列表随 `report-summary` 带回（`handled_alerts`），刷新即恢复，不额外请求。
- `POST /api/emr/record/qc-review`：只留痕，**不清除遗漏**。审阅代表看过，
  不代表病历改好了。
- 落库失败时**不标记为已处置** —— 否则界面放行了提交，服务端门禁却仍会拦，
  医生会看到一个自相矛盾的系统。

### 3.4.2.4 时间轴必须反映本次操作【增强】

**此前时间轴纯粹取种子**：医生开了医嘱、提交了病历，它纹丝不动。
一条不反映当前操作的时间轴没有任何用处，只是一张装饰图。

而这些动作在**审计日志里本来就全都有**，接上即可：

- 种子 = 历史记录，审计 = 本次操作，两段合起来才完整。审计条目带 `source: "audit"`，
  界面可区分「今天做的」与「历史」。
- **白名单控制**：审计里还有内部记账（发布配置、回滚等），混进时间轴只会稀释信噪比。
- **详情写成人话**，不是把审计的 JSON 贴上去 —— 「共 2 段」而不是 `{"fields":[...]}`。

第一版白名单写了 `comorbidity_consultation` / `nutrition_consultation`，
而实际记的是 `request_consultation` —— **拼错的键只是永远匹配不到，不会报错**，
于是会诊永远上不了时间轴。已加一条测试：白名单里的 action 必须真实存在于代码中。

### 3.4.3 阳性结果的展开态

【原件】`.result-list-item` **可点**：点某一条，列表让位给该条详情。

```text
div.result-panel
├── div.result-panel-header
│   ├── span.rp-title       未展开「⚠ 阳性结果 (N)」/ 展开「📊 {名称}」
│   └── el-button(link,small,primary)  展开时才有：「← 查看全部」
├── div.result-detail       展开时
│   ├── rd-type     「🔬 检查结果」/「🧪 检验结果」
│   ├── rd-content  检查取 result，检验取「值 单位（参考: x）」
│   └── rd-extra[.abnormal|.normal]   结论；含「异常」「偏高」时标红
└── div.result-list-wrap    未展开时；空态 .no-abnormal「暂无阳性结果」
```

数据形状按原件对齐 `{id, type, label, detail, extra}`，顺序**检查在前、检验在后**。
检验的 `extra` 缺省是「偏高」而非把数值再抄一遍。

注意：**展开后列表被详情顶掉，所以「再点同一条收起」这条路在原件里也走不通** ——
`ue()` 里那段 toggle 逻辑够不着，回列表只能靠「← 查看全部」。实现保留 toggle
以防布局变动，但测试按真实可达路径写。

| 🔬 检查 | **`examinations`（已做的检查）+ 本次新开的检查医嘱** | 检查项目/类型/日期/结论 |
| 🧪 检验 | `lab_results` | **指标名称**/结果/参考/趋势 |

早先「检查」页只过滤「`category === 'exam'` 的医嘱」，而种子医嘱一条都没有
`category` —— 于是患者明明做过心电图、眼底照相、颈动脉超声，这一页永远是空的
（角标 0，原件是 3）。**检查记录的正主是 `examinations`，医嘱表里只有本次新开的。**
新开的还没有结果，结论写「待出结果」。

【增强】开嘱、检查、转诊、住院四个写入动作全部落本项目自己的库并留审计，**不触达真实 HIS**；响应结构保持与 V4.3 一致。ID 由服务端按前缀稳定生成（`R0001`/`E0001`），而非 V4.3 的 `"R" + Date.now()`（同毫秒会撞号、重启会回退）。

#### 4.3.1 质控明细与审阅

【原件】点「查看全部 N 处遗漏 ›」展开逐条明细：

```text
div.rc-qc-detail
├── div.qc-item[.error|.warning|.info]   点击 → 跳到对应那一段病历
│   ├── span.qc-icon   ❌ error / ⚠️ warning / ℹ️ info
│   └── div.qc-body    qc-field「【既往史】」+ qc-issue
└── el-button(warning, plain, small, width:100%)  「我已审阅质控提醒」
```

【增强】每条遗漏由服务端给出 `field` / `field_key` / `issue` / `type` 四个字段，
不是一句拼好的 `text`：

- `field_key` 让界面**点一条就跳到那一段**病历去改。只给整句文案，医生就得自己在七段里找。

  【增强】原件的跳转只做 `scrollIntoView`。目标段本来就在视野里时，滚动等于没动，
  医生完全不知道点上没有 —— 我们补了 1.6 秒的 `.record-node.focused` 高亮做反馈，
  只改边框与底色，不动尺寸与布局。**类名与样式必须成对**：只挂类不配 CSS，
  测试照样绿，线上点下去纹丝不动 —— 这个坑本轮真踩过，已加一条断言样式存在的测试。
- `type` 决定图标。三级混成一种图标，医生分不出哪条必须处理、哪条只是建议。
  映射：红线（未经问诊的否定）→ `error`；整段未采集 → `warning`；标准项缺失 → `info`。
- `text` 仍保留，「病历风险与遗漏」那一栏按整句渲染。

【增强·重要】**「我已审阅」只收起明细并记一次确认，不清空遗漏清单。**
审阅代表医生看过，不代表病历改好了。把遗漏一并抹掉，等于用一次点击给红线消音，
下一个接手的人再也看不到。这一条有专门的测试盯着。

无遗漏时不出明细，也不出「我已审阅」按钮。

#### 4.4.1 诊断命令（在 Copilot 输入框里打）

**上一版规格把「修改诊断」「设为主诊断」记成了两个二级动作按钮，是错的。**
它们在原件里根本不是按钮，是 Copilot 聊天里的自然语言命令。按按钮去实现，会做出
一套原件没有的界面，而真正的入口反倒还是缺的。

【原件】七条命令，冒号可中可英可省：

| 命令 | 行为 |
| --- | --- |
| `查看诊断` | 列出全部，`★` 标主诊断，附 ICD，并列出可用命令 |
| `添加诊断：xxx [ICD]` | 新增。ICD 可选，按 `^[A-Za-z]\d` 识别 |
| `删除诊断：xxx` | 删除 |
| `设为主诊断：xxx` | 设主诊断 |
| `修改诊断：A 为 B` | 改名 |
| `清空诊断` | 清空全部 |
| `确认诊断` / `诊断确认` / `确认并回写诊断` / `回写诊断` | 触发回写 |

【原件】名称是**双向模糊匹配**（全等 → 互相包含）：医生打「高血压」要能命中
「高血压3级」，复制粘贴带了后缀也要能命中。

实现要点，每条都对应一个测试：

- **命令在本地结算，不走模型。** 结果必须确定，而且要立刻反映到勾选状态上；
  交给模型的话，「删除诊断」可能被答成一段说明文字，界面纹丝不动。
- **不是命令就原样交还模型。** 匹配一律锚定行首关键词 —— 抢答的代价很大：
  医生问「这个患者要不要抗凝」被当成命令吞掉，就再也拿不到模型的回答了。
- **删掉主诊断后主诊断清空**，不留指向已删条目的悬空引用。
- **改名保留 ICD 与主诊断身份**。
- **第一条诊断自动成为主诊断** —— 回写必须有主诊断，省医生一步。
- **命令不改传入状态**，失败不留脏数据。
- 回写仍走既有门禁（无主诊断、红色风险未闭环一律拦下），命令只是另一个入口。
- **回复一律纯文本，不含 HTML。** 原件用 `<strong>` 加粗是因为它的气泡渲染 HTML；
  我们的气泡渲染纯文本，照抄会把标签原样显示给医生（公网验收时就是这么发现的）。
  改用 `v-html` 更糟 —— 回复里插着诊断名，而名字来自医生输入与模型输出，等于开一个
  XSS 口子。中文用「」强调足够，已加断言无 HTML 的测试。

【增强】命令引入的新诊断（候选列表里没有的）单独留存并与候选合并渲染 ——
否则「添加诊断：xxx」执行完界面上看不见，医生只会以为没生效。

### 5.1 2026-09-03 的偏离原件（均为有意）

**① 删除 `mode-badge.voice`（红色的「语」）。** 两条理由各自成立：

- 它标的是「语音问诊模式」，而一期**没有任何语音识别** —— 全仓零行
  `SpeechRecognition` / `MediaRecorder` / `getUserMedia`。实际形态是一个文本框
  （医生用系统的语音输入法或直接打字）加一段脚本对话回放。
  **标记一个不存在的模式比不标更糟**：它会让人以为系统在录音。
- 红色在本产品是临床风险语义（见 §「红、黄是临床风险语义」一条），
  不得用于模式指示。工作站里红色 = 红色风险 = 未闭环即阻断提交；
  患者姓名旁挂一个红标会和它抢同一个信号。

**② `patient-tab-meta` 改为一行五项**：`性别 · 年龄 · 出生年月 · 就诊号`。

出生年月只到月（`1968-03`）—— 门诊核对身份用不到日，写全会把这一行挤爆，
而这一行右边要留给过敏标记。**就诊号是 `P001` 这类患者 ID，不是身份证号**；
身份证号只在服务端用于推导出生日期，从不下发到前端。

**③ `allergy-badge` 三态**（新增，原件没有）：

| 状态 | 显示 | 依据 |
| --- | --- | --- |
| `confirmed` | 红标 + **过敏原名称** | 只写「有过敏」等于没说，医生还得再点一次 |
| `denied` | 不给任何标记 | 干净就是信息：没有红色说明问过了、没有 |
| `unknown` | 黄标「过敏史未采集」 | **这不是「没有过敏」，是没人问过** |

三态而非两态的理由见 `features/F06-风险管理.md` §2.1。同一套语义与配色
也出现在候诊列表的患者卡片上 —— 医生是在那里挑下一位患者的。

**④ `assistant-toggle` 大卡片 → `assistant-handle` 抽屉把手。**

原来那张卡片占三行、带一段说明文字，把「一个开关」做成了首屏最大的一块内容；
医生每次进来先读三行，读完才发现它只是个展开按钮。改成面板左边线中间
22×56 的把手（`‹` / `›`），靠**位置**表达「这边能拉开」。

问诊结束自动展开的提示，由原来「刚刚自动展开」的文字徽标改为把手闪一次蓝底
（`.attention`，2 秒回落）—— 同样看得见，但不占版面。

**把手在面板内部，贴左内壁**（`position:absolute; left:0`，18×52，
左边直角、右边圆角 8）—— 读起来像从框壁上伸出的一个小舌片，明确属于医生智能体。

> 2026-09-03 改过一次位置。初版做成面板的**兄弟节点**、flex 行里独立一列，
> 那样会在 AI 助手抽屉与面板之间撑出一道空隙，看着像浮在中间、不属于任何一边。

> 放进面板要满足一个约束：`.assistant-panel` 带 `overflow:hidden`（裁圆角），

**医生智能体面板一个像素都不让**，把手纯粹浮在它的左边缘上（`absolute`，不参与布局）。

把手是**收放左边那个 AI 助手**的开关 —— 凭什么让医生智能体的内容缩进去？

**⑤ 删除「AI 助手待问诊后展开」占位卡。** 抽屉收起时，原来在 HIS 与面板之间

### 5.2 问诊按钮组（2026-09-03 重做）

问诊中的 `action-bar` **只剩两个按钮**，各两个字，左次右主：

| 位置 | 类名 | 文案 | 行为 |
| --- | --- | --- | --- |
| 左 | `.ib-secondary`（plain） | **暂停** ⇄ **继续** | 同一个按钮切换，不是两个 |
| 右 | `.ib-primary`（primary） | **生成** | 立刻产出病历与分析，**问诊继续进行** |

四条约束，每条都对应一次改动前的具体毛病：

**① 「继续问诊」→「暂停 / 继续」。** 原来两个按钮，一个「继续问诊」一个
「停止问诊」，两个四字词并排，医生要读完才能分辨。现在一个位置只表达一件事，
文案就是它按下去会发生什么。**两个按钮都是两个字**，宽度对称。

**② 「停止问诊」→「生成」，且不再是红色。** 原来它既结束问诊又触发生成，
两件事绑在一起，医生想中途看一眼病历就只能先把问诊停掉。现在「生成」
**只做生成**（`persist()`，不调 `finish()`）：随时点、可重复点，点完
问诊状态不变，按钮组还在。既然不是破坏性动作，就不该穿红色 ——
红色在本产品是临床风险语义（见 §「红、黄是临床风险语义」）。

**③ 继续 / 暂停 从不禁用。** 生成过程中把暂停灰掉，等于让医生在模型跑
20–30 秒期间对着一排死按钮。这两个键控的是录入，与生成互不相干。

**④ 「报告解读」按钮删除，「鉴别诊断」改为「科室看板」。** 前者的产出
已经在时间轴的「AI 分析」里；后者的内容另行定义（待产品确认），
当前只占位跳转，不接任何数据。

### 5.3 语音问诊状态机

【原件】V4.3 的按钮集合：`● 语音问诊` / `⏸ 暂停问诊` + `📋 补充观察` / `▶ 继续问诊` / `🔄 重新问诊`。

【原件】交互模型：**点一下自动播放本次就诊的对话脚本**，播放中浮出两个浮层：

```text
div.pending-float   position: fixed; right: 308px; top: 105px; width: 220px; z-index: 2100
├── pending-title   pending-dot + 「AI 追问提示」
└── pending-list
    ├── pq-item          当前该问的一条：pq-num(橙色圆形序号) + pq-text
    └── pq-done-list
        └── pq-item.done  已问到的：pq-check ✓ + pq-text（划掉）

div.obs-float       position: fixed; right: 308px; top: 320px; width: 220px; z-index: 2090
├── obs-float-header  obs-float-title「补充观察」+ obs-float-close ✕
└── obs-float-list
    └── obs-float-item × N
```

【原件】补充观察是**动态过滤**的：从候选集里剔掉对话中已经问到的条目（去掉「有无/是否」前缀后取前三字做包含匹配），剩下的才是待观察。空态文案「待患者描述主诉后动态更新」。

【增强】**状态机改为 `idle → playing → awaiting →（医生点结束）→ ended`。** V4.3 播完即结束，那是演示逻辑；作为交互设计有两个问题：

1. 正式环境是连续音频流，根本没有「播完」这个事件。靠静音判断会把医生查体、思考、敲字的停顿误判成结束，把问诊拦腰切断。
2. 结束会触发下游生成（病历 + 全部分析），属于有后果的动作，必须医生确认。

改后 MVP 的状态机与正式环境一致：接 ASR 时只是把「脚本推进」换成「音频流推进」，结束仍然是医生点的。

【增强】追问清单的完成判定改为**语义判定**，不是按轮次顺序划掉。「覆盖」是蕴含关系不是相似关系 —— 「哪一侧肢体无力？」被「右手拿筷子拿不稳，右腿走路也有点拖」完整回答，两句几乎零字面重叠，关键词法与向量相似度都会大面积漏判。

配套要求：
- **追问清单必须是原子问项**（一条只问一件事）。实测同一段对话，原子问项时 15 条判定全对、三次运行完全一致；换成复合问句则稳定判错。难点不在模型能力，在清单本身。
- **判错方向必须安全**：漏标已问 = 医生多扫一眼；错标已问 = 该问的问题再也不提醒。因此规则是「必须引用患者原话，拿不准判未覆盖」，且**降级时不做任何标记**。
- 判定单调（已标记不回退）、增量（只发还开着的问题）、异步非阻塞。
- 医生可手动勾销，模型判错时一键纠正。

### 5.4 浮层关闭后怎么唤回

【原件】**实测行为**（`52-…`/`54-…` 采集态）：

| 关 | 开 | 面板边缘的 `.panel-tips-toggle`（‹ ›）—— 不出浮动按钮 |

> **这张表的条件不能照抄到卡通上**，见下一节末尾「显示条件」。

> 漏掉这一条的后果是死路：医生把两个 × 都点掉后，浮层再也回不来，只能刷新页面。

**`.solo-tips-open-btn` 不实现。** 原件里有它的完整标记与样式（深蓝胶囊，`.float-icon.small`

实测「关抽屉」「关抽屉+关面板」两种组合都不触发。**照着源码实现它，会显示一个原件从不显示的
按钮**，反而偏离原件。判定为死代码，只在此存档。

#### 【增强】圆钮 → D1 卡通（2026-09-03）

「关 / 关」那一格的入口换成了桌面卡通 `AgentMascot.vue`，方案 **D1「微笑」**。
`.ai-float-btn` / `.float-icon` / `.float-ready-dot` 三个类连同样式一并删除。

**位置沿用**（`right:24px; bottom:32px; z-index:2000`）—— 医生上一版在哪找它，
这一版还在哪。换的只是长相：圆钮上的「AI」是个**标签**，说的是「这里有个 AI」；
而这一格真正该传达的是「医生智能体待命中，随时叫它」。一张脸能表达状态，
两个字母不能 —— 原件为此另挂了一个绿色呼吸点，那个点只有「在线」一种含义。

| | 原件圆钮 | D1 卡通 |
| --- | --- | --- |
| 尺寸 | 52×52 圆形 | 56×66（含天线） |
| 内容 | 「AI」两个字母 + 绿色呼吸点 | 圆顶头 + 两眼 + 微笑 + 听诊器 |
| 状态 | 只有「在线」 | 静止微笑 / 分析中闭眼 / 待补问角标 |
| 可拖动 | 否 | **是**，钳在可视区内 |
| 点击行为 | `tipsOpen = true`（只开抽屉） | `panelOpen = true`（**还面板**） |

**点击行为为什么改。** 照搬原件会留一条死路：面板关着、把手长在面板内壁上，
于是抽屉开起来之后**面板再也回不来**。缩起来的是面板，点开就该还面板 ——
这也正是「缩小为一个卡通」的字面意思。抽屉保持医生离开时的样子，不替他做主。

三条设计约束（改之前先读，理由都在 `AgentMascot.vue` 文件头）：

1. **眼睛保持圆点，不做眯眼笑** —— 这个尺寸下眯眼会糊成一条线，读起来像睡着了。
2. **分析中不做旋转风火轮** —— 分析要跑 20–30 秒，一个转半分钟的东西是持续的
   余光干扰，而它就浮在医生桌面上。改成闭眼 + 天线呼吸。
3. **角标数字由外面传进来，卡通自己一个数都不算** —— 它必须和问诊提示浮框
   同源，两处对不上时医生不知道该信哪个。橙色而非红色：红色是临床风险语义，
   「还有几条没问」不是风险。

**拖完那一下不算点击**（阈值 4px）。pointerup 之后浏览器照样派发 click，
不拦的话「把它挪开」永远伴随一次误开面板，医生会得出「这东西不能拖」的结论。

**它退出了还原度门禁。** 那张表比的是「同名 class 的计算样式」，而
`.mascot` 在原件里不存在 —— 留着的话三个选择器全部落进「原件中不存在，跳过」，
**一个什么都不比的场景比没有场景更糟**：它在输出里占一行 ■，看起来像有人在管。
改由 `AgentMascot.spec.ts` 12 条 + `AiEmrFloat.spec.ts` 4 条把守，覆盖比门禁更细。

#### 显示条件：**只要面板关着就出现**

与 AI 助手抽屉开不开**无关**。上面那张原件表的条件是「抽屉与面板都关」，
**不能照抄** —— 原件那个圆钮还的是**抽屉**，抽屉开着时它确实没事可做；
而这只卡通还的是**面板**，条件必须跟着「它还什么」走。

照抄的后果实测过，是一条死路：AI 助手展开着的时候关面板 ——
面板没了、卡通不出（因为抽屉开着）、把手又长在面板内壁上跟着一起没了，
**页面上没有任何东西能把面板点回来**，只能先关掉 AI 助手才冒出卡通。
这正是本节开头那句警告的同一类问题，只是换了个组合。
`AiEmrFloat.spec.ts`「AI 助手开着时关面板，卡通照样出来」钉住这一条。

#### 那个 `×` 要说清自己是「缩成卡通」

图形保持原件的 `×`，但补 `title` / `aria-label`：「缩成卡通（收到右下角，点它可还原）」。

一个光秃秃的 `×` 读起来是「关闭」，而它实际是「最小化」——
缩起来的东西一直在右下角待着。**提这个功能的人自己没找到入口**，
这是最硬的可用性信号，不是文档能绕过去的。

### 5.7 AI 追问提示（2026-09-04 恢复实时形态）

【增强·原件有过、撤过、又回来了】面板**内部右上角**的浮框：这一场该问的列出来，
**问到一条划掉一条**。

#### 三个版本，别弄混

| | V4.3 原件 | 一期首版 | 过渡版 | **现在** |
| --- | --- | --- | --- | --- |
| 时间 | —— | 2026-09-02 撤 | 2026-09-03 | 2026-09-04 |
| 类名 | `.pending-float` / `.pq-*` | 无 | `.hint-float` / `.hf-*` | `.hint-float` / `.hf-*` |
| 何时出现 | 问诊一开始就挂一列 | —— | 点「生成」或「暂停」 | **攒够 3 条对话自动浮出** |
| 内容来源 | 演示脚本写死 | —— | 问诊小结的 `gaps` | **`followup_plan` 岗位** |
| 已问到的 | 打勾划掉 | —— | 不管 | **打勾划掉** |
| 可拖动 | 否 | —— | 否 | **是** |
| 可关闭 | 否 | —— | 是 | 是 |

**为什么撤了又回来。** 撤的理由是「一期没有临床知识库，追问做不准」——
那条理由**对当时的做法成立，对现在这版不成立**：现在的清单来自**这位患者
档案里明摆着的缺口**（「过敏史空着，没人问过」），不是教科书式的鉴别问诊清单
（「问 Levine 征」）。前者不需要任何知识库。提示词里明确禁止列后一类。

#### 结构

```text
div.hint-float[.mini][data-draggable]   面板内 absolute，right 10 / top 78，宽 224，z-index 6
├── hf-head          ← **整条是拖动把手**
│   hf-icon 💡 + hf-title「AI 追问提示」+ hf-spacer
│   + hf-progress「2/8」+ hf-btn（—，缩小）+ hf-btn（✕，关闭）
└── hf-body
    ├── hf-item × N      hf-num（橙色序号）+ hf-text     ← 还没问的
    ├── hf-allclear      「清单里的都问到了 👍」          ← 全划完时
    ├── hf-sep           「已问到 N 条」
    ├── hf-done × N      hf-check ✓ + hf-done-text（灰、划线）  ← title = 患者原话
    └── hf-foot          「供参考，不是必须问的项」
```

**位置在患者信息行下方**（top 78），不是贴着面板顶。那一行是核对身份用的，
最不该被遮 —— 浮框宁可往下挪，也不能盖住姓名和过敏标记。

三态：**展开** / **缩成胶囊**（`.hf-pill`，角标是**还没问**的条数）/ **关闭**
（`hintDismissed`，本次问诊内不再自动弹）。

#### 三条显示规则

**① 已问到的沉底、灰掉、划线，不删除。** 医生要能看见「这条问过了」——
那本身也是信息。直接消失的话清单会莫名其妙变短，医生分不清是问到了
还是模型忘了。原话挂在 `title` 上：想核对「凭什么算问到了」时能当场看到。

**② 角标是「还没问」的条数，不是总数。** 它要说的是「还欠几条」；
写总数的话，全问完了角标还挂着一个 8。

**③ 空清单整个不渲染。** 一个常驻的空浮框只是挡住底下的内容。

`.hf-foot` 那句「供参考，不是必须问的项」是刻意的。撤掉它的那条理由没有失效
—— **措辞压住，它才是提示而不是必办清单**：一个做不准的建议，语气越肯定伤害越大。

#### 展开时机：攒够 3 条对话

不在问诊一开始就弹（那时一条都没划掉，浮框看起来像在催人），
也不在清单全划完时弹（那时它没有任何要说的）。常量
`AUTO_OPEN_AFTER_MESSAGES`，与「有没有还开着的条目」一起构成判据。

#### 判错的方向必须是安全的那边

**这个功能只有一种失败方式值得防：错标已问。**

- 漏标已问 = 医生多扫一眼清单
- 错标已问 = **该问的问题再也不会提醒了**

所以从提示词到运行时到前端，一路都往「宁可不划」的方向兜：

| 层 | 做法 |
| --- | --- |
| 出清单（`followup_plan`） | **原子问项**，一条只问一件事。复合问句会让判定必然出错 —— 患者只答一半，判「已问到」是错的，判「没问到」也是错的 |
| 判覆盖（`followup_coverage`） | 只回「已覆盖」，不回「未覆盖」；每条**必须摘录患者原话** |
| `validate()` | 原话不在对话里的条目**直接丢掉**（丢单条，不整份拒绝 —— 整份拒绝会降级成一条都不标） |
| 前端（`useFollowUp`） | 单调（已划不回退）、非阻塞（同时只允许一个判定在飞）、**不做任何本地兜底判定** |
| 降级 | 一条都不标 |

**一条问了两件事、患者只答了一件 → 不算已覆盖。** 实测错标就是这么发生的：
「降压药具体吃的是什么药、怎么吃的？」患者答「降压药基本在吃」（只答了服法），
整条被划掉，药名从此再也不会被问起。两条坏例子已写进 `followup-coverage/SKILL.md`。

回归集 `followup-prompt.json` 两条用例钉这两件事：`FU-01` 钉原子问项，
`FU-02` 拿「答了一半」的三条当陷阱，判定标中任何一条即不通过。

#### 一次问诊调几次模型

- 清单：**1 次**（`GET /interview/followup/{id}`，问诊开始时并行去取）。
  清单是档案里的缺口，对话推进不会改变它；每轮重算会让条目在医生眼皮底下换来换去。
- 判定：**每攒 2 条对话 1 次**（`POST /interview/followup/coverage`）。
  清单全划完之后不再调用。

`voice/init` **仍然不调模型** —— 「开始问诊」要立刻有反应，清单晚一两秒到不影响
（浮框本来就要攒够 3 条才展开）。

#### 拖动

标题栏整条是把手（内容区要能滚动，不适合当把手）。逻辑在 `useDraggable`，
与桌面卡通共用。两个坑记在那个文件头，这里只记后果：

- **坐标系混用**会让浮框当场跳走 —— 实测从 x=1205 拖一下跳到 x=1966，
  跑出 1440 宽的屏幕，缩小按钮再也点不到。
- **把手里的按钮上按下不能开始拖** —— 否则指针被把手捕获，
  按钮收不到自己的 click，表现为「缩小按钮点了没反应」。

### 5.8 浮窗调宽与缩小键（2026-09-04 新增）

#### 调宽：只有左边线能拉

两个浮窗都**靠右停靠**，右边贴着屏幕 —— 右边线拖不动。
**往左拖 = 变宽**（边线远离右侧锚点），这是唯一容易搞反的地方。

| 浮窗 | 拖的其实是什么 | 默认 | 下限 | 上限 |
| --- | --- | --- | --- | --- |
| 医生智能体 | `.assistant-panel` 的 `width` | 300 | 260 | 560 |
| AI 助手 | `.ai-float-wrapper` 的**总宽** | CSS `left:30%` | 640 | 1800 |

AI 助手是 `flex:1`，自己没有宽度 —— 它的左边线就是 `.ai-float-wrapper`
的左边线。所以拖它调的是**组合总宽**，抽屉实际宽度 = 总宽 − 面板宽。
起始值要运行时量（CSS 给的是百分比，换个屏幕就是另一个数）。

上限还要再受视口限制：屏幕比上限窄时按屏幕来，否则小屏上拉到头会把页面顶出去。

**双击边线 = 恢复默认。** 恢复的做法是把内联宽度清成 `null`（交还给 CSS），
不是写回一个数 —— 这样样式表改了默认宽，双击恢复的也是新的那个值。

边线宽 5px（再窄鼠标够不着，再宽会盖住浮窗圆角），命中区靠 `::before`
往外扩到 11px。**平时完全透明**，悬停/拖动才显形：一条常驻的竖线会把两个
浮窗视觉上切开，而它们本来是连在一起的（`connected-left` / `connected-right`）。

它和抽屉把手（`.assistant-handle`）在同一条边上 —— 把手贴在**面板内壁**、
占中间 52px 且 z-index 更高，两者不抢同一块区域。

#### 缩小键：`—`，不是 `✕`

医生智能体标题栏原来是 `✕`，只靠 `title` 说明它其实是「缩成卡通」。
**不够** —— 提这个功能的人自己都没找到入口，两次问「怎么缩小」。
`✕` 读起来就是「关掉」，没人会点它来「缩小」。**靠 tooltip 补救的语义等于没有。**

改成 `—`（最小化的通用符号，也和追问提示浮框的头部一致）。

**不再给第二个「彻底关掉」。** 医生智能体没有「关掉就没了」这个状态 ——
缩起来的东西一直在右下角（D1 卡通）。两个按钮做同一件事只会让人犹豫点哪个；
真做一个「关了就没」的，就又造出一条回不来的死路。

#### 可达性：缩起来一定点得回来

这一类 bug 咬过三次，**每次成因都不一样**：

| # | 成因 | 表现 |
| --- | --- | --- |
| 1 | 行为不对 | 点卡通只开抽屉，不还面板 |
| 2 | 条件不对 | 抽屉开着时卡通干脆不渲染 |
| 3 | **层级不对** | 卡通渲染了但点不到 —— 抽屉压在上面 |

第三条是这次修的：卡通与 `.ai-float-wrapper` 同为 `z-index:2000`，
同级按 DOM 顺序，抽屉在后面所以压在上面。卡通提到 **2100**。

**前两条单测能覆盖，第三条不能** —— jsdom 不套 scoped CSS，层级问题只有
真浏览器看得见。守在 `scripts/demo-check.mjs`：两种抽屉状态各走一遍
「缩小 → 点卡通 → 面板回来」，用 `.click({timeout})` 的超时当判据
（被挡住时点不动，正好会超时）。

### 5.9 窗口合并/分离、字号、滚动提示（2026-09-04 新增）

#### 合并 / 分离

默认**合并**（就是原来那样：AI 助手 + 医生智能体拼成一整块靠右停靠）。
拖标题栏拖开；拖回去靠近了自动吸附；**双击标题栏一键还原**。

| 规则 | 为什么 |
| --- | --- |
| 合并态下拖任一标题栏，**两个一起走** | 合并的意思就是「它们现在是一个东西」。拖一个另一个不动，那叫叠在一起 |
| 吸附判据：横向缝隙 < 40px **且纵向有重叠** | 只看横向的话，一上一下也会被吸到一起 |
| 吸附前给虚线预告（`.will-snap`） | 没有预告的吸附，看起来像窗口自己乱跑 |
| 钳位钳的是**标题栏**，不是整个窗 | 窗体下半部分出屏只是看不全内容；标题栏出屏就再也抓不住了 |

**分离那一刻必须冻住尺寸。** 两个窗在合并态是 flex 子项 —— 抽屉 `flex:1`、
高度由父容器给。一改成 `position:fixed` 这些约束全没了，它们改按内容撑开：
实测抽屉从 866×985 变成 **1471×1703**，高度直接超出屏幕。
吸附回去与一键还原时要把冻住的尺寸放掉，否则合并态还挂着死宽高。

医生手动调过的面板宽度**优先于**冻结尺寸（样式合并顺序：dock 在前、resize 在后）。

#### 字号：四档，用 `zoom`

小 90% / 标准 100% / 大 115% / 特大 130%。入口是医生智能体标题栏的「Aa」——
放在这一侧是因为**这个窗口关不掉**（AI 助手可以整个关掉），设置该挂在关不掉的那个上。
两个窗共用一个值，各调各的必然会漂。菜单里每个选项**就用它自己的字号显示**，
选之前先看见效果。

**为什么用 `zoom` 而不是改 font-size**：面板字号是满屏写死的 px（11 / 12 / 10.5…，
上百处），逐条改成相对单位既不现实，也会把还原度门禁全部撞红 —— 那张表比的正是计算样式。
而且 `zoom` 连间距一起缩放：只放大字不放大行距，读起来反而更挤。

**挂在内容区，不挂在面板本身**（`.chat-area` / `.tips-tab-body` / `.copilot-tab-bar`）。
面板要承载拖动与调宽的坐标；`zoom` 一旦加上去，指针的 `clientX`（视觉像素）
和写进 `left`/`width` 的值（局部像素）就差一个缩放系数，两个交互立刻算错。
附带好处是**标题栏不跟着放大** —— 它是外壳不是内容。

代价：面板宽度不随字号变宽。但边线现在可以拖（§5.8），医生自己拉开就行。

**标准档不输出 `zoom`**：写 `zoom:1` 会凭空造出一个新的包含块，
让里面 `position:fixed` 的东西改以面板为参照。默认档本来一切正常，不该去动它。

字号存 `localStorage`（设一次就不想再设的偏好，刷新、换病人都不该丢）；
窗口位置只存本次会话（医生按当前这一屏摆的位置，换台机器不一定合适）。

#### 追问清单的「下面还有」

清单常有 8 条而框高只装得下 5–6 条，第 6 条被切一半 ——
**而没有任何东西说明下面还有**。半截字看起来更像排版坏了，不像「可以往下滚」。
字号调大之后更糟。

两个提示一起给，缺一个都不够：

- **底部渐隐**：一眼看出内容被切断了
- **「还有 N 条 ⌄」**：说出还剩多少，点一下翻下去 ——
  只给渐隐的话，医生知道有更多，但不知道值不值得去翻

只数**整条还没露出来**的条目，被切一半的那条不算（它已经看得见了）。
滚到底两个都收起来 —— 一个永远亮着的「还有更多」等于没有。

> **它是卡片下沿的一条独立元素，不是浮在上面的。** 走过两次弯路：
> ① `position:absolute` 浮着 → 压住被切一半的那条；
> ② 给 `.hf-body` 加 `padding-bottom` → **滚动容器的内边距是跟着内容滚的**，
> 不是固定在底边，滚到顶时它在看不见的地方。
> 在流内单开一条才是结构上不可能重叠的做法。

## 5A. HIS 门面（`HisBackdrop.vue`，2026-09-03 新增）

**这一节推翻 `14-桌面端问诊流程与分析门禁.md` §9.2。** 那次是把 HIS 门面**整块撤掉**，
理由是「一个长得像 HIS 的页面容易让人以为已经和院内系统打通了」。理由仍然成立，
但撤掉之后暴露了另一个问题：医生智能体是个**浮窗**，浮窗底下空着一片白，
演示时没人看得出它是浮在医生本来就在用的系统上的 —— 而这正是这个产品的形态本身。

改法不是把担心撤回去，是把它**写在界面上**：

- 门面回来，但**照北大国际医院现行 HIS 仿**（Windows 桌面软件观感：密集小字、
  细边框、蓝色标题条、表格为主），**刻意不用本产品的设计语言**（大圆角、留白、渐变）。
  两者观感越不一样，「医生智能体是浮在 HIS 上的」越清楚。
- 工具栏左侧一枚**常驻、不可关闭**的 `.hb-sim-badge`「界面仿真」。这不是提示，是声明。
  §9.2 的顾虑由它承担。
- **零个 `<input>`**，整层 `user-select:none`。它是道具：划词复制它没有意义，
  只会让人以为能拿来用。填不进东西，就不会有人误以为填进去的会存下来。

交互只做四样，**都不产生任何请求**：标签页切换（费用/检验/检查…）、就诊类型单选、
医嘱行勾选、面板折叠。够医生在演示里点两下有反应，不够让人以为它在工作。

## 9. 验收方式

**界面还原不靠肉眼，靠数值。**

```bash
npm run verify   # 测试 + 构建 + 契约导出 + 还原度逐元素比对
npm run fidelity # 只跑还原度比对（需先 npm run dev）
```

`compare-v43-fidelity.mjs` 把原件与重建版在同一视口下跑起来，逐元素比 `fontSize / fontWeight / lineHeight / color / backgroundColor / padding / borderRadius`。**不比 width/height** —— 两者由内容长度决定，文案变化不是还原度差异。

当前覆盖：候诊列表、门诊工作站、八个标签页、语音问诊播放态、阳性结果展开态、质控明细、浮层唤回钮，
**122 个元素零差异零缺失**（2026-09-03：`＋ 菜单` / `技能管理对话框` 两个场景随功能一并撤掉，
由 146 降到 122 —— 门禁比的是「现在应该长什么样」，留着已删的场景只会让它永远红）；
另有 `npm run coverage` 逐标签页比对类名集合，八页零缺失；八个标签页的自有类名覆盖率均为 100%。

**新做的界面必须同时进这张表**，否则它就落在门禁之外 —— ＋ 菜单三兄弟当初就是这样漏掉的。

> **门禁的等待判据必须是「正的条件」。** 「门诊工作站」场景是第一个需要
> report-summary 产出的（`.dd-*` 鉴别诊断 + `.ra-*` 风险共 13 个元素），
> 而 `settle()` 只保证「遮罩散了、不再显示『智能体分析中』」—— 这两个条件在
> **分析还没开始**时同样成立，它分不清「没算完」和「不该有」。
> 结果就是每次都报「缺失 13 个」，而后面八个标签页场景全绿（轮到它们时分析已经回来了）。
> 同一个坑记过五次，正确写法是等**要比的东西真的在场**（`.dd-card` / `.ra-card` attached），
> 而不是等一段时间或等某个东西消失。

`{id, text, priority, source, done, action_type, category}`，由后端**确定性规则**生成：

- **必须有真实依据才出现。** 无异常检验就不给复查待办、无共病就不给转诊待办。
  凭空列一堆比不列更糟 —— 医生会先学会忽略这个面板，真正要紧的那条也跟着被忽略。
- **`done` 一律为 `false`。** 系统不替医生判断某件事做完了没有。
- 红色预警**逐条**进处置单、优先级「高」、**排在最前**。风险漏报是零容忍红线，

#### 安全边界

**处置单里没有一步到位的写入。** 单条动作与「一键执行」都先弹确认，确认后只
**跳到对应功能区**，真正的写入仍由那一区自己的确认流程负责（含红色风险门禁）。

理由：未确认写回是零容忍红线，而处置单是全局最容易被连点的地方 —— 一个面板上
摆着十几个按钮，手滑一下就可能往病历里写进东西。有一条测试专门守这个：点「一键执行」

| `acute_gastroenteritis` | 急性肠胃炎诊疗指南 | 诊疗指南 |

【增强·换入口】**原件靠在 Copilot 回复里嵌 `<a class="kb-link" data-key="…">` 锚点触发。**
我们的回复来自真实模型且**一律纯文本不渲染 HTML**（见 4.4.1，理由是 XSS），照搬行不通。

改为：**回复完整后**把全文送服务端做关键词匹配，命中的条目以按钮形式挂在气泡下方
（沿用原件的 `.kb-link` 配色）。不改变界面形状，且不需要模型配合输出特定标记。

- **匹配放在服务端** —— 关键词是数据的一部分，应该跟着内容走，不该在前端各处复制。
- **匹配不上就不挂。** 挂七条不相关的比不挂更干扰。
- **流式过程中不匹配**，等回复完整再做 —— 中途文本还不全，会漏掉后半段的关键词。
- **正文按需拉取**：列表只给 `{key, title, keywords}`。正文最长 800 余字，
  列表阶段带上纯属浪费。

#### 为什么这里可以用 `v-html`

词条正文是带结构的 HTML（`h3`/`table`/`ul`/`p`），必须按结构渲染，否则表格会
变成一坨纯文本。与诊断命令的回复不同，这里的内容是**本仓库静态提供的**，
无用户输入或模型输出参与拼接，改动走代码评审。

评审之外还有一道自动化下限：一条后端测试扫描词条正文，出现 `<script>`、
`javascript:` 或内联事件处理器即失败 —— 有人往词条里贴了带 `onclick` 的
HTML，CI 要能拦下来。
