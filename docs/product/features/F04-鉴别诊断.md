# F04 鉴别诊断功能规格

版本：`v0.2-draft`  
集成任务：`differential_diagnosis`  
结果类型：`diagnosis_candidates`  
承载 Agent：`diagnosis_agent`

## 1. 目标与边界

围绕本次就诊问题形成按优先级排序的候选诊断，呈现支持证据、反对证据、缺失信息、风险关联和下一步核实建议，帮助医生拓展并收敛诊断思路。

本功能只生成鉴别诊断建议，不替代医生下诊断，不直接写入正式诊断，不自动开具检查、检验、药物或治疗医嘱。候选项必须由医生显式确认后，才可进入 F05 诊断管理。

## 2. 输入与触发

### 2.1 可用输入

| 数据 | 一期要求 |
| --- | --- |
| 患者与就诊身份 | 患者 ID、就诊 ID、年龄、性别、科室、就诊类型必须齐全 |
| 本次问诊 | 已确认的症状、持续时间、伴随症状、重要阴性症状、体征 |
| 既往资料 | 诊断、手术、用药、过敏、相关检验检查，均带来源和时间 |
| 当前病情概况 | 只接受通过 Schema 与患者/就诊校验的 F02 快照 |
| 专科包 | 内分泌/代谢、普通骨科或普通妇科的规则、术语、禁忌与模板版本 |
| 医生输入 | 医生可指定要回答的诊断问题、排除范围或重点关注方向 |

### 2.2 触发时机

- 医生点击“生成鉴别诊断”；默认不在患者进入工作台时自动执行。
- 关键临床事实变化后，旧结果标记“上下文已变化”，由医生决定是否刷新。
- 风险管理发现新的红色风险时，可发出“建议刷新鉴别诊断”的事件，但不得自动覆盖现有结果。
- 同一患者、同一就诊、同一上下文哈希的重复请求复用结果或幂等执行。

## 3. 输出模型

每个候选诊断至少包含：

| 字段 | 说明 |
| --- | --- |
| `candidate_id` | 本次结果内稳定 ID |
| `name` / `icd_candidates` | 诊断名称与可选 ICD 候选；编码必须标注版本和是否待医生确认 |
| `priority` | `must_not_miss`、`likely`、`possible`、`less_likely`，不显示伪精确百分比 |
| `supporting_evidence[]` | 支持证据及 `source_ref`、数据时间 |
| `opposing_evidence[]` | 反对或不典型证据；没有时写“未获得”，不得写“无” |
| `missing_information[]` | 会改变判断的关键缺失信息，包含建议获取方式 |
| `risk_links[]` | 与 F06 风险项的关联 |
| `next_steps[]` | 问诊、查体或检查建议草稿，标注依据和紧急度 |
| `uncertainty` | 不确定性说明、模型限制与适用边界 |
| `generated_at` / `data_cutoff_at` | 生成时间与数据截止时间 |

排序必须优先考虑“不能漏诊”与临床后果，再考虑常见度；不能简单等同于模型置信度排序。

## 4. UI/UX 要求

- `UX-F04-001` 默认展示“不能漏诊”“较可能”“其他可能”三个分组，每组可折叠；首屏不超过 6 个候选。
- `UX-F04-002` 卡片摘要只展示名称、优先级、一条关键支持证据、一条关键缺失和与风险的关联；完整证据在右侧证据抽屉下钻。
- `UX-F04-003` 候选项提供“加入待排”“设为初步诊断”“暂不考虑”“反馈问题”四个动作；动作后保留原建议。
- `UX-F04-004` 显示数据截止时间、上下文是否过期、Agent/规则包版本和“AI 建议，需医生判断”。
- `UX-F04-005` 对红色风险相关候选使用风险标识，不用整体红底；普通“低可能”不使用灰到不可读的样式。
- `UX-F04-006` 医生可以查看“为什么推荐”和“还缺什么”，技术 Trace 默认隐藏，仅供调试授权角色查看。

## 5. 业务和安全规则

- `BR-F04-001` 候选诊断去重后最多返回 10 条；超过时按分组截断并说明。
- `BR-F04-002` 诊断名称与 ICD 编码分离管理；名称可建议，编码须通过本地术语服务匹配。
- `BR-F04-003` 任何关键支持或反对事实都必须带 `source_ref`；推断必须标注为推断。
- `BR-F04-004` 医生“暂不考虑”的候选在同一上下文内保持状态；新证据出现时允许重新提示并解释变化。
- `SAFE-F04-001` 年龄、性别、妊娠可能性、过敏、生命体征或红色风险缺失时，相关结论必须降级并提出澄清，不得强结论。
- `SAFE-F04-002` 不得将未发生的症状、体征、检查结果或家族史作为证据。
- `SAFE-F04-003` 不得因“常见病”排序压低与当前证据相符的高后果诊断。
- `SAFE-F04-004` 输出中含处方剂量、自动医嘱或确定性治疗指令时，Schema/安全门禁必须拒绝该结果。

## 6. 专科差异

| 范围 | 一期重点 |
| --- | --- |
| 内分泌/代谢 | 低血糖与高血糖急症、甲状腺功能异常、继发性病因、药物相关问题、微/大血管并发症线索 |
| 普通骨科 | 外伤机制、骨折/脱位、感染、神经血管受压、肿瘤/病理性骨折、红旗征 |
| 普通妇科 | 妊娠相关可能、异常子宫出血、盆腔疼痛、感染、扭转/破裂等急症、肿瘤风险 |

专科包只改变问题、规则、术语和模板，不改变统一输出 Schema 与确认流程。

## 7. 失败与降级

- 上下文不足：返回结构化缺失清单，不生成填充式诊断列表。
- 术语服务不可用：展示诊断名称建议，禁用 ICD 确认并标注服务异常。
- Agent 超时或取消：保留医生已有诊断和上一次结果，显示结果时间与“可能已过期”。
- 返回不合规：界面只显示“结果未通过安全校验”和可重试操作，不展示部分不可信内容。

## 8. 验收标准

- `AC-F04-001` 每个候选均可追溯到真实输入证据，并区分事实、推断和缺失。
- `AC-F04-002` 医生可将候选送入 F05，且患者/就诊、名称、优先级、来源和原始结果 ID 保持一致。
- `AC-F04-003` 关键事实修改后旧结果立即显示过期，刷新前不自动改写候选。
- `AC-F04-004` 三个专科 Fixture 均能触发对应的不能漏诊分支和缺失信息提醒。
- `AC-F04-005` 幻觉证据、错误患者、处方剂量和不合规 Schema 均被门禁阻止。
- `AC-F04-006` 生成、查看证据、采纳、拒绝、重新提示与反馈均产生审计事件。

## 9. 待确认

- “不能漏诊”诊断清单、分级和专科规则须由北大国际医院各专科负责人审核。
- ICD 版本、医院诊断字典、术语服务接口及诊断名称规范。
- 是否允许医生配置首屏候选数量和默认展开分组。
