# F05 诊断管理功能规格

版本：`v0.2-draft`  
集成任务：`diagnosis_management`  
结果类型：`diagnosis_management`  
承载 Agent：`diagnosis_agent`

## 1. 目标与边界

把医生确认的初步诊断、次要诊断和待排诊断组织成可管理的问题清单，支持新增、排序、确认、修订、排除和版本追踪，并提示诊断与病历、风险和医嘱草稿之间的不一致。

诊断管理是医生主导的正式业务功能。Agent 可以给出管理建议，但不能自动新增、删除、确诊、排除或写回诊断。一期只模拟向 HIS/EMR 写回。

## 2. 诊断状态模型

| 状态 | 含义 | 允许的主要动作 |
| --- | --- | --- |
| `suggested` | AI 或规则建议，尚未进入医生诊断清单 | 加入初步/待排、拒绝 |
| `provisional` | 医生确认的初步诊断 | 设为主要、修订、转确诊、转待排、删除 |
| `confirmed` | 医生确认的诊断 | 设为主要/次要、修订、标记历史 |
| `rule_out` | 待排诊断 | 补充依据、转初步/确诊、排除 |
| `excluded` | 已排除，仅保留在历史轨迹 | 恢复为待排 |
| `historical` | 既往诊断，不作为本次当前诊断 | 关联共病、恢复为当前 |

主要诊断在任一有效版本中最多一个。删除与排除均为软删除，必须保留原因、操作者和版本。

## 3. 功能需求

- `FR-F05-001` 医生可手工新增诊断，也可从 F04 候选一键带入。
- `FR-F05-002` 支持搜索医院诊断字典，选择标准名称和 ICD 编码，并允许记录医生自由文本补充。
- `FR-F05-003` 支持设置主要/次要顺序、状态、起病时间和关联证据。
- `FR-F05-004` 支持查看每次变更前后差异、来源、理由、操作者和时间。
- `FR-F05-005` 提交前校验主要诊断唯一性、必填项、编码有效性和风险一致性。
- `FR-F05-006` 生成模拟写回回执，并允许在回执失败后安全重试。

## 4. UI/UX 要求

- `UX-F05-001` 使用一份诊断清单，分为“本次诊断”“待排”“既往/已排除”；不另开第二个 AI 诊断面板。
- `UX-F05-002` AI 建议以内嵌提示或候选抽屉进入；送入清单后明确显示“来源于 AI、已由医生确认”。
- `UX-F05-003` 每行显示名称、编码、状态、主次、来源和一致性提示；复杂证据在下钻抽屉展示。
- `UX-F05-004` 修改主要诊断、删除、排除和覆盖冲突均需填写或选择原因；常用原因可快捷选择。
- `UX-F05-005` 模拟写回按钮文案为“提交模拟写回”，确认框和回执均显示目标系统与 `mode=mock`。
- `UX-F05-006` 冲突不是普通 Toast：在对应诊断行显示可处理的问题，并提供“查看差异/保留当前/合并”操作。

## 5. 业务和安全规则

- `BR-F05-001` F04 候选必须经过医生动作才能从 `suggested` 进入诊断清单。
- `BR-F05-002` 同一标准诊断不得重复；同名不同编码或同编码不同名必须提示人工合并。
- `BR-F05-003` 就诊诊断与既往诊断不可因名称相似自动合并。
- `BR-F05-004` 诊断变更后发布 `diagnosis.changed` 事件，通知 F02、F03、F06、F07 检查是否过期；不得自动覆盖其内容。
- `BR-F05-005` 采用 `diagnosis_set_version` 乐观锁；过期版本提交返回逐项差异。
- `SAFE-F05-001` 红色风险未处置时禁止模拟写回诊断；黄色风险必须已阅、处理或留痕。
- `SAFE-F05-002` 患者/就诊校验失败、编码服务异常、版本冲突或 Schema 不合规时禁止写回。
- `SAFE-F05-003` 妊娠状态等关键上下文不明且会改变诊断含义时，须保留待排或提示澄清。

## 6. 一致性检查

提交前至少检查：

1. 诊断与主诉、现病史、体征、检验检查是否存在明显矛盾。
2. 诊断状态是否被病历草稿错误表述为确诊。
3. 主要诊断是否唯一、编码是否有效、排序是否完整。
4. 红/黄风险与诊断清单是否相互引用且处置状态一致。
5. 共病是否被误当成本次主要诊断，或本次重要共病是否遗漏。
6. 当前诊断版本是否与准备提交的病历/医嘱草稿处于同一就诊快照。

一致性检查输出是问题列表，医生可处理、忽略并留因，不自动修改诊断。

## 7. 失败、并发与恢复

- 术语服务失败：允许保留未编码草稿，但禁止提交模拟写回。
- 版本冲突：展示“我的版本/服务器版本/来源”三方差异，医生逐项决定。
- 写回模拟超时：以幂等键查询结果后再允许重试，避免重复回执。
- Agent 不可用：不影响医生手工管理诊断；只隐藏或禁用 AI 建议入口。

## 8. 验收标准

- `AC-F05-001` 手工新增和 F04 带入均能形成可编辑诊断，且来源可追溯。
- `AC-F05-002` 主要诊断唯一、状态流转和软删除规则均可验证。
- `AC-F05-003` 诊断变化能令受影响的病情概况、病历、风险和共病结果标记过期。
- `AC-F05-004` 编码异常、重复诊断、患者错配、版本冲突和未处置红色风险均阻止模拟写回。
- `AC-F05-005` 模拟写回具备幂等性，回执包含请求 ID、版本、目标系统、模式、时间和结果。
- `AC-F05-006` 所有诊断变更均可从审计记录还原前后状态。

- 正式环境 HIS/EMR 写回接口、电子签名与责任边界。
