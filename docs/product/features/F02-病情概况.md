# F02 病情概况功能规格

版本：`v0.2-draft`  
集成任务：`condition_summary`  
结果类型：`condition_summary`

## 1. 目标与边界

在不替代医生阅读原始病历的前提下，以问题为导向汇总本次问诊与历史数据，突出主要问题、近期变化、关键证据、数据冲突和缺失。概况是快速导航和问题清单，不是完整健康档案或自动诊断。

## 2. 触发与刷新

- `FR-F02-001` 进入工作站且患者/就诊绑定完成后自动准备，不阻塞病历编辑；未选择患者时不调用 Agent。
- `FR-F02-002` 问诊确认、关键检验检查到达、诊断或用药变更时，标记“可刷新”，不静默覆盖旧版。
- `FR-F02-003` 医生可手动刷新，界面使用 `context_version` 生成幂等键。
- `FR-F02-004` 正在处理概况时，新上下文到达应将旧任务标记为过期，不并行展示两个“最新”。

## 3. 输入与卡片字段

| 区域 | 必需内容 | 规则 |
| --- | --- | --- |
| 一句话摘要 | 当前主问题、时间和重要背景 | 默认 80–120 个汉字，不以治疗建议收尾 |
| 问题清单 | 问题名、状态、优先级、本次相关性 | 默认展示 3–5 项，可展开 |
| 变化与趋势 | 与可比较历史数据的变化 | 必须显示比较时点和单位 |
| 关键证据 | 数值/文本、来源、时间、状态 | 可跳转原始数据 |
| 冲突 | 冲突字段、各来源值、时间 | 不选择“更合理”的值隐藏冲突 |
| 缺失 | 缺失字段、影响和获取方式 | 区分阻断与非阻断 |
| 元数据 | 数据截至时间、上下文版本、Agent/Mock 版本 | 始终可见 |

## 4. 交互需求

- `UX-F02-001` 总览态只显示摘要、主要问题、最高风险、缺失/冲突数，满足“一页看完”。
- `UX-F02-002` 点击证据在右侧抽屉显示来源摘要、时间和原文定位，不强制跳离当前患者。
- `UX-F02-003` 新旧版本可显示问题新增/移除、数值变化、证据更新和冲突变化。
- `UX-F02-004` 医生可标记“与本次无关”、“数据错误”、“需补充”，这些反馈不修改原始数据。
- `UX-F02-005` 概况不提供“一键确诊”或“一键开嘱”。

## 5. 业务与安全规则

- `BR-F02-001` 只有时间、单位和检测方法可比的数据才能生成趋势。
- `BR-F02-002` 历史诊断、既往异常和本次活动问题必须使用不同状态。
- `BR-F02-003` 证据引用不存在、越权或过期时，对应结论必须降级为不可采信或不展示。
- `SAFE-F02-001` 患者/就诊不匹配、数据时间未知、核心证据无来源时，概况不能进入 `ready`。
- `SAFE-F02-002` 新概况不得覆盖医生正在编辑的病历，只能发布为新的 AI 结果版本。

## 6. 失败与降级

- 历史数据不可用：仅基于本次就诊生成，永久显示“未包含历史资料”。
- 部分数据源超时：不等待非关键源，在缺失清单中标识；关键源超时则澄清或失败。
- Agent 失败：展示可阅读的原始资料导航，不伪造静态 AI 摘要。
- 非法 Schema：不展示临床内容，只显示安全错误和重试/人工路径。

## 7. 验收标准

- `AC-F02-001` 每个关键事实可定位到来源类型、时间和原始记录。
- `AC-F02-002` 冲突 Fixture 同时展示两个值及来源，不静默选择其一。
- `AC-F02-003` 刷新时旧版可回看，并能查看最小变化摘要。
- `AC-F02-004` 在原 HTML 默认桌面工作台中，不进入二级详情即可看到摘要、主问题、最高风险和缺失/冲突；不得为满足本条改变原布局。
- `AC-F02-005` 患者切换后，前一患者延迟返回的概况被 API 层与 UI 层同时拒绝。

## 8. 专科包差异

- 内分泌代谢：突出血糖趋势、低血糖、并发症筛查、血压/血脂/肾功能。
- 骨科：突出疼痛部位、功能影响、神经学表现、外伤和红旗征象。
- 妇科：突出年龄/绝经状态、姊娠可能、出血模式、筛查与病理/检查跟踪。

上述专科规则只是产品字段与 Mock 覆盖范围，临床阈值与阻断规则待专科医生签字。
