# F07 共病管理功能规格

版本：`v0.2-draft`  
集成任务：`comorbidity_management`  
结果类型：`comorbidity_plan`  
承载 Agent：`comorbidity_agent`

## 1. 目标与边界

从本次问题、既往诊断、用药、检验检查和长期随访信息中识别与当前诊疗相关的共病，形成问题清单、相互影响、管理缺口和行动建议草稿，减少专科门诊“只看当前主诉而漏掉重要慢病”的风险。

本功能不替代慢病随访系统，不自动确认历史诊断，不直接开医嘱、处方、转诊或随访任务。所有行动建议须由医生选择，并由对应业务系统执行。

## 2. 共病纳入规则

一期纳入同时满足以下条件的疾病或健康问题：

1. 存在可追溯的既往诊断、用药、检查或医生本次确认依据；
2. 对本次诊断、检查、用药、手术/操作风险或随访计划有影响；
3. 仍处于活动期、控制状态不明，或虽稳定但需要在本次决策中考虑。

无证据的“可能共病”进入待核实清单，不进入已确认共病。已治愈或纯历史问题默认折叠，但与本次决策相关时可重新呈现。

## 3. 输出模型

| 字段 | 说明 |
| --- | --- |
| `problem_id` | 共病问题稳定 ID |
| `name` / `status` | 名称与 `confirmed`、`suspected`、`historical`、`resolved` |
| `relevance` | 与当前主诉、诊断、用药、检查或操作的关系 |
| `control_status` | `controlled`、`uncontrolled`、`unknown`，必须有依据 |
| `evidence[]` | 诊断、用药、检验检查和医生确认的来源引用 |
| `interactions[]` | 疾病-疾病、疾病-用药、用药-用药或检查禁忌影响 |
| `care_gaps[]` | 缺失监测、复查、依从性、并发症筛查或转诊信息 |
| `suggested_actions[]` | 澄清、复核、监测、转诊或随访建议草稿 |
| `risk_links[]` | 与 F06 风险项关联 |
| `data_cutoff_at` | 评估使用的数据截止时间 |

“控制不佳”必须有明确阈值、时间窗或医生判断来源；不能仅因一次历史异常值下结论。

## 4. 功能需求

- `FR-F07-001` 自动形成“与本次相关”“待核实”“稳定/历史”三组问题清单。
- `FR-F07-002` 医生可确认、纠正、隐藏、恢复或手工新增共病，并记录原因。
- `FR-F07-003` 展示共病对本次诊疗的具体影响，不做泛化健康科普。
- `FR-F07-004` 展示管理缺口和行动建议草稿，医生可选中后复制到病历或形成模拟任务。
- `FR-F07-005` 诊断、用药、检验或风险状态变化时，相关结果标记过期并说明原因。
- `FR-F07-006` 对多病共存的关键冲突进行去重、排序和风险升级。

## 5. UI/UX 要求

- `UX-F07-001` 默认只展开与当前决策有关的问题；稳定/历史共病折叠，避免信息淹没。
- `UX-F07-002` 每张卡片首屏展示“为什么现在相关、控制状态、一个主要缺口、一个主要动作”。
- `UX-F07-003` 疾病相互影响以双向关系清楚表述，例如“肾功能影响药物选择”，不用难以解释的综合分数。
- `UX-F07-004` 行动按钮表述为“加入问诊问题”“复制到处理意见”“创建模拟随访”“暂不处理”，不使用暗示已执行的文案。
- `UX-F07-005` 来源和时间在证据抽屉展示；过期数据在卡片摘要中明确提示。
- `UX-F07-006` 与红/黄风险相关的共病显示风险状态，但处置动作跳转到 F06 的唯一权威风险项。

## 6. 业务和安全规则

- `BR-F07-001` 共病问题与 F05 诊断共享标准术语，但状态和业务语义独立，不自动互转。
- `BR-F07-002` 医生确认/纠正优先于 Agent 新结果；重新评估不得无提示覆盖。
- `BR-F07-003` 建议的监测、转诊和随访均为草稿，进入其他系统前必须二次确认。
- `BR-F07-004` 对同一管理缺口的多来源建议必须合并并保留来源。
- `BR-F07-005` 专科阈值、监测周期和指南版本必须进入规则包版本。
- `SAFE-F07-001` 不得基于姓名相似、一次异常值或过期用药记录直接确认共病。
- `SAFE-F07-002` 存在相互作用或器官功能禁忌的高风险建议必须同步上报 F06。
- `SAFE-F07-003` 患者/就诊错配、来源缺失、时间语义错误和自动执行动作均由门禁阻止。

## 7. 专科一期场景

| 范围 | 共病管理重点 |
| --- | --- |
| 内分泌/代谢 | 高血压、血脂异常、肥胖、心肾血管并发症、甲状腺与代谢互相影响、多药管理 |
| 普通骨科 | 糖尿病/骨质疏松对愈合与感染风险的影响，抗凝、肾功能和慢病用药对检查/操作的影响 |
| 普通妇科 | 妊娠可能、贫血、代谢异常、血栓风险、肿瘤史及慢病用药对妇科诊疗的影响 |

一期评测既要覆盖单一共病，也要覆盖三种以上问题并存时的排序、去重和相互作用。

## 8. 失败与降级

- 历史数据不足：显示“可用资料不足”并列出需要核实的信息，不生成全量阴性结论。
- 用药或检验数据源不可用：标记受影响的共病判断和行动建议，不隐藏数据缺口。
- Agent 超时：保留医生维护的问题清单和上一次结果，标记可能过期。
- 模拟任务创建失败：保留选中的建议，回执显示失败，不误标为已安排。

## 9. 验收标准

- `AC-F07-001` 共病纳入均有来源和与本次就诊的相关性说明。
- `AC-F07-002` 已确认、待核实、稳定/历史分组与医生纠正能跨重新评估保持。
- `AC-F07-003` 共病与诊断、用药、检查及风险的相互影响可追溯且去重。
- `AC-F07-004` 行动建议只能形成草稿或模拟任务，不得被标记为真实执行。
- `AC-F07-005` 三专科 Fixture 均覆盖至少一个控制状态判断、一个管理缺口和一个交互风险。
- `AC-F07-006` 过期数据、错误患者、单次异常值误判和 Agent 不可用均有正确降级行为。

## 10. 待确认

- 医院已有慢病管理、随访和转诊系统的接口与权威数据边界。
- 哪些共病必须在门诊病历中体现、哪些仅作为工作台提醒。
