## UI/UX 基线约束

一期已经确认直接沿用最早的 [`AI-HIS门诊模块V4.3.html`](../../../references/ui-demo/AI-HIS门诊模块V4.3.html)，页面布局、视觉风格和交互路径不重新设计。

本目录中的 `UX-Fxx-nnn` 只定义功能必须展示的信息、状态和操作，不授权创建新版工作台或改变原 HTML。文档出现“卡片”“抽屉”“工作区”“侧边栏”等词时，应先映射到原 HTML 既有组件；无法承载的差异必须先确认。品牌内容按已确认要求由“惠每”替换为北大医疗/北京大学国际医院，其他视觉保持不变。

## 统一编号

- `FR-Fxx-nnn`：功能需求。
- `BR-Fxx-nnn`：业务规则。
- `UX-Fxx-nnn`：界面与交互要求。
- `SAFE-Fxx-nnn`：临床安全硬约束。
- `AC-Fxx-nnn`：可验证的验收标准。
- `TC-Fxx-nnn`：测试用例，收录于 `docs/testing/`。

## 通用产品约束

1. 所有 Agent 结果是草稿或建议，不是医嘱或最终诊断。
2. 界面必须同时显示患者、就诊、数据截止时间、Runtime/Agent 版本和医生确认状态。
3. 任务结果必须通过患者/就诊二次校验、Schema 校验与安全门禁后才能进入 UI。
4. 医生编辑内容不得被刷新、重试、超时、患者切换或 Agent 新结果覆盖。
5. 一期只进行模拟写回；页面、回执和审计均必须明示 `mode=mock`。
6. 红色风险必须处置或经授权的强制忽略流程后才能继续关键提交；黄色风险必须已阅、处理或留痕。
7. 页面结构和操作路径沿用最早 HTML；长证据、历史和技术 Trace 复用其既有详情组件展示。
