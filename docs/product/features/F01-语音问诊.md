# F01 语音问诊功能规格

版本：`v0.3-draft`  
日期：`2026-08-29`  
主责：产品功能开发条线  
集成任务：`voice_interview`  
结果类型：`interview_note` / `clarification_request`

UI 状态、字段和交互细则以 [`06-F01-F03语音问诊与病历生成UI需求规格.md`](../06-F01-F03语音问诊与病历生成UI需求规格.md) 为准。

## 1. 目标与非目标

目标是在医生明确开始录音后，将医患对话转为可复核的逐句转写和结构化病史，并对会影响安全或后续功能的缺口提出最少必要追问。

非目标：后台常开录音、患者声纹识别、自动确认病史、自动写入正式病历、以大模型代替专业 ASR 服务。

## 2. 用户、前置与数据

- 可执行角色：当前就诊授权医生。
- 前置：医生已登录，`patient_id` 与 `encounter_id` 已锁定，麦克风权限可用。
- 必需上下文：科室/专科包、已知主诉、过敏、长期用药、特殊状态、问诊模板版本。
- 音频保存、留存时间和是否进入评测集必须依医院规则配置，默认不进入训练集。

## 3. 主流程

1. 医生点击“语音问诊”，页面显示录音用途、设备和当前患者。
2. 医生开始录音，系统生成 `session_id`，持续显示红色录音指示和时长。
3. 转写流返回后，按医生/患者/家属/未知主体分段，附时间戳与置信标记。
4. 对话逐条出现时，左上角“AI 追问提示”根据已出现内容更新已覆盖项、漏问项和下一句建议。
5. 医生可暂停、继续、纠错、删除本段或结束；所有修改保留原文和操作日志。
6. 结构化提取同步更新，不替代原始转写；关键缺口进入澄清区。
7. 医生结束后确认结构化结果，才可发布为已确认问诊上下文；随后自动调用 F03 生成可复核的电子病历草稿。

任务编排固定为 `voice_interview → record_generation`。F03 不得在 F01 结果可用前抢跑；问诊与病历生成是两个可独立审计、失败和重试的任务。

## 4. 界面与交互需求

- `UX-F01-001` 录音状态在抽屉关闭后仍必须在顶部安全条可见，防止误录。
- `UX-F01-002` 逐句转写必须显示说话主体、时间戳、原文、低置信标记和纠错入口。
- `UX-F01-003` 结构化区按主诉、现病史、既往史、用药、过敏、家族史和专科字段分组，标记来源段落。
- `UX-F01-004` 阻断问题与建议问题分区显示；记录跳过建议问题的操作，阻断问题不可无理由跳过。
- `UX-F01-005` 转写和结构化区各自有空、加载、中断、重连和结束状态。
- `UX-F01-006` 医患对话固定承载于最右侧医生智能体；AI 追问提示紧贴医生智能体左侧悬浮。提示必须随对话轮次更新，已覆盖项显示完成状态，并给出当前最优先的一句建议追问。
- `UX-F01-007` 问诊结束前智能笔记显示等待状态；结束后按“转写结构化 → 病历生成”顺序展示过程和结果。
- `UX-F01-008` 问诊完成后保留右侧完整对话，中间智慧诊疗的病历/智能笔记自动显示主诉、现病史、既往史、个人史、过敏史、体格检查、辅助检查和初步诊断。
- `UX-F01-009` 对话气泡同时使用颜色和“医生/患者/家属”文字标签；低置信内容提供纠错入口。
- `UX-F01-010` 追问提示至少具有 `pending/active/done/blocking` 四种状态，同一时刻只突出一个最高优先级建议。
- `UX-F01-011` 医生向上查看历史消息时不得被新消息强制拉回底部；回到底部后恢复自动跟随。
- `UX-F01-012` Mock 演示点击功能即进入逐轮播放，不设置“生成 Mock 效果”按钮；运行模式只在详情或审计中显示。
- `UX-F01-013` 问诊中和暂停时提供“补充观察”；选中项以医生来源的 `【补充观察】…` 回显，独立于语音转写和 AI 追问提示。

## 5. 字段与业务规则

- `BR-F01-001` 未提及的内容不得生成“否认”、“无”或阴性病史。
- `BR-F01-002` 否定、时间、程度、解剖部位、陈述主体必须作为独立结构化属性，不只保存为文本。
- `BR-F01-003` 低置信片段默认不能进入已确认病历字段；医生纠错后可解锁。
- `BR-F01-004` 患者切换时立即停止录音，将未确认会话标记为待处理，不得迁移到新就诊。
- `BR-F01-005` 方言、噪声或说话人分离能力不足时，必须显示能力限制并允许人工录入。
- `BR-F01-006` 内科、骨科、妇科使用同一 UI 布局，但必须加载不同的对话脚本、专科追问集和阻断规则。
- `BR-F01-007` 重新问诊创建新会话和结果版本；旧结果可审计，不得与新版本合并成同一个“最新结果”。
- `BR-F01-008` 补充观察必须携带来源、操作者、时间和 patient/encounter/session；同一会话去重，进入后续问诊结构化和病历生成上下文。

## 6. 安全、权限和审计

- `SAFE-F01-001` 过敏、姊娠状态、意识/呼吸/胸痛/神经功能等专科包设定的关键缺口必须阻断发布“已完整问诊”。
- `SAFE-F01-002` 录音必须有显式开始/结束操作、可见指示和会话级审计。
- `SAFE-F01-003` 任何未确认转写不得直接改变正式诊断、医嘱或风险处置。
- 审计事件：`recording_started/paused/resumed/stopped`、`segment_corrected/deleted`、`clarification_answered/skipped`、`interview_confirmed`。

## 7. 失败与降级

| 情况 | 产品行为 |
| --- | --- |
| 无麦克风权限 | 说明开启方式，保留人工录入和固定音频 Mock 入口 |
| ASR 网络中断 | 暂停发送，保留本地已取得段落；重连后不重复段落 |
| 说话人无法分离 | 标记“主体待确认”，禁止结构化字段自动确认 |
| Agent 超时 | 转写仍可使用，结构化与追问降级为人工模板 |
| 结果 Schema 非法 | 不展示结构化内容，保留原转写与医生修改 |

## 8. 验收标准

- `AC-F01-001` 开始、暂停、继续、结束与重新录制均有可见状态且不丢已保存段落。
- `AC-F01-002` 医生可逐句纠错，查看原文、修改值、修改人和时间。
- `AC-F01-003` 未提及病史的测试对话不生成任何虚构阴性事实。
- `AC-F01-004` 关键缺口使结果进入 `needs_clarification`，补充后使用新结果版本继续。
- `AC-F01-005` 设备、网络、超时、非法 Schema 与患者切换用例均不丢失医生已录入内容。
- `AC-F01-006` 固定 Mock 对话中医生与患者内容逐条出现，追问提示至少更新两次，问诊未结束时不存在病历生成结果。
- `AC-F01-007` 最后一轮对话结束后自动产生八类病历草稿字段，生成前后状态在 UI 中可辨认。
- `AC-F01-008` 页面不存在中间独立语音问诊工作区；对话位于医生智能体，生成后的八类病历字段位于智慧诊疗智能笔记。
- `AC-F01-009` 内科、骨科、妇科 Fixture 均在同一布局下播放对应专科对话并更新专科追问。
- `AC-F01-010` 追问提示存在待问、当前建议、完成和阻断状态；问诊成功完成后自动消失。
- `AC-F01-011` 补充观察可在问诊进行中和暂停时选择，回显后不跳过既定对话轮次，患者切换后不串用。
