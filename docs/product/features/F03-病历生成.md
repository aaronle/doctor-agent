# F03 病历生成功能规格

版本：`v0.3-draft`  
日期：`2026-08-29`  
集成任务：`record_generation`  
结果类型：`record_draft`

UI 状态、字段和交互细则以 [`06-F01-F03语音问诊与病历生成UI需求规格.md`](../06-F01-F03语音问诊与病历生成UI需求规格.md) 为准。

## 1. 目标与边界

将已确认的问诊信息和可追溯临床事实，按医院与专科模板组织为可编辑的门诊病历草稿，减少书写时间并保留医生最终决定权。

不自动签名、不自动写回、不生成未确认阳性/阴性事实、不将待排诊断表述为确诊。一期处理建议只是病历草稿文本，不生成医嘱或处方。

## 2. 模板和字段

| 字段组 | 一期必需能力 |
| --- | --- |
| 主诉 | 症状/问题 + 主要时间，支持医生直接编辑 |
| 现病史 | 起病、演变、伴随症状、诊疗经过、重要阴性病史（仅限已确认） |
| 既往史 | 既往疾病、手术和长期用药来源明确，不将历史无记录当作“无” |
| 个人史 | 烟酒、职业、暴露等按专科模板展示；未问则留空或待补 |
| 过敏史 | 作为一期固定独立字段；“未询问/无记录”不得转换为“无过敏” |
| 专科字段 | 妇科月经/婚育/姊娠状态，骨科疼痛/神经功能，内分泌用药/低血糖/并发症等 |
| 体征与体格检查 | 只使用本次已记录值或医生确认文本 |
| 辅助检查 | 带时间、单位、来源；历史结果不写成本次结果 |
| 初步诊断/处理意见草稿 | 明确确诊/待排、医生确认前不得写回 |

`template_id`、`template_version`、`specialty_package_id` 和每个字段的必填性必须进入任务上下文和审计。

## 3. 交互流程

1. 医生选择整份生成或按段生成；默认保留已编辑正式草稿。
2. AI 结果进入段落级草稿层，显示来源、缺失、不确定性和校验状态。
3. 医生可对单段执行采纳、合并、编辑、拒绝或重新生成。
4. 采纳后内容进入医生草稿，保留 AI 原文与医生最终文本的差异。
5. 提交前执行必填、事实一致、数据时间、未处理红/黄风险、待澄清项和患者身份校验。
6. 一期生成模拟写回回执，完整记录字段版本与医生确认。

从 F01 自动进入本功能时，不再要求医生额外点击“生成”。右侧保留完整问诊对话，中间智能笔记从等待态切换为生成态，成功后展示八类固定字段。若 F01 存在阻断缺口，则 F03 只能生成部分草稿并标记 `needs_input`，不能显示为完整病历。

## 4. UI/UX 要求

- `UX-F03-001` 主体始终是医生病历草稿；AI 草稿使用侧边栏或行内建议，不占用第二套完整病历表单。
- `UX-F03-002` 每段展示“已生成/已编辑/已采纳/已拒绝/需补充”状态。
- `UX-F03-003` 差异视图区分 AI 原文、医生新增、医生删除和字段来源，不用风险红色表示普通文本删除。
- `UX-F03-004` “全部采纳”只处理未编辑字段；如将覆盖医生内容，按字段列出并二次确认。
- `UX-F03-005` 未保存编辑在离开患者、关闭页面和重新生成前必须明确提示。
- `UX-F03-006` 固定展示主诉、现病史、既往史、个人史、过敏史、体格检查、辅助检查、初步诊断八类字段；无可靠内容时显示待补充，不省略字段结构。
- `UX-F03-007` 每个字段提供独立编辑和单字段送回医生草稿动作；送回不等于正式 HIS 写回。
- `UX-F03-008` 问诊完成前显示等待态，生成中显示明确进度，成功、部分成功和失败可区分。
- `UX-F03-009` 重新问诊不会静默删除医生已编辑草稿；新结果以新版本进入差异比较。
- `UX-F03-010` 医生确认的补充观察必须进入相应病历段落并显示来源；不得把观察自动改写成患者自述或检查结果。

## 5. 业务和安全规则

- `BR-F03-001` 每个 AI 生成字段必须包含 `source_refs`；无来源的格式连接词可例外，临床事实不例外。
- `BR-F03-002` 同一字段的新 AI 结果不能自动替换医生编辑版本。
- `BR-F03-003` 过期、作废、预备或其他就诊数据在生成文本中必须显式说明时间语义。
- `SAFE-F03-001` 幻觉临床事实、过敏错误、患者串用、未确认写回为零容忍门禁。
- `SAFE-F03-002` 红色风险未处置或阻断澄清未完成时，禁止“提交病历”，但允许继续编辑和暂存。
- `BR-F03-004` 任务输入中的 patient、encounter、session、context version 必须与当前页面一致，否则拒绝展示。
- `BR-F03-005` 每个临床字段都必须携带 `source_refs`；缺失来源的字段不得进入可采纳状态。
- `BR-F03-006` 补充观察以 `observation_id` 进入 `source_refs`；与其他来源冲突时保留双方并标记冲突。

## 6. 并发、版本和恢复

- 草稿使用 `record_version` 乐观锁；过期提交返回差异，不盲目覆盖。
- 自动暂存与手动暂存共用幂等键，显示最后成功保存时间。
- Agent 失败或取消不回滚医生草稿。
- 浏览器异常关闭后，允许恢复最后服务端草稿；未上传的本地文本是否恢复待隐私规则确认。

## 7. 验收标准

- `AC-F03-001` 整份与单段生成均可用，且不改变其他段落。
- `AC-F03-002` 采纳、部分采纳、编辑、拒绝、恢复 AI 原文均有差异和审计记录。
- `AC-F03-003` 虚构体征、未提及阴性病史和过期检验冒充本次的 Fixture 均被校验阻止。
- `AC-F03-004` 刷新、超时、取消、重试和患者切换不丢失已暂存医生内容。
- `AC-F03-005` 提交只产生 `mode=mock` 回执，回执显示目标系统、模式、版本、时间与结果。
- `AC-F03-006` F01 完成后自动进入生成，成功结果严格包含八类字段，其中过敏史为独立字段。
- `AC-F03-007` 完成状态保留右侧完整对话、隐藏追问提示并显示重新问诊入口。
- `AC-F03-008` 内科、骨科、妇科共用同一字段布局，但内容和专科字段规则随专科包变化。
- `AC-F03-009` F01 中选定的补充观察出现在 F03 对应病历字段和来源映射中，可从病历定位回观察记录。
