# 桌面端问诊流程与分析门禁

设计稿：Figma **AI 门诊工作站 · 一期设计系统** → 页面 `06 · 桌面端问诊流程`
`https://www.figma.com/design/c79Yrkq4MOgwjN3dulIvO7`

这是对 V4.3 的**有意偏离**（原件一进来两侧全开），与撤下 AI 处置单、
专项评估默认折叠同类，理由与代价都记在这里。

---

## 1. 为什么改

改之前，八个 AI 标签页的结论是在医生跟患者说第一句话**之前**就算好的 ——
打开工作站即并发跑四个岗位，上下文只有种子档案，不含任何本次问诊内容。

代码里早就写着这个事实（`finishAndGenerate` 上方的注释）：

> 病情概况、鉴别诊断、风险、共病都是**打开工作站时**算好的，也就是在问诊之前。

两个后果：

1. **锚定。** 医生还没开口，屏幕上已经摆着「首选诊断 2型糖尿病 90%」。
   人一旦看过一个答案，问诊就容易变成找证据支持它，而不是鉴别。
   这是临床上真实存在的危害路径，不是体验问题。
2. **问诊显得可有可无。** 分析已经出来了，医生不点「结束问诊」，那一场对话就白做 ——
   而那恰恰是最想验证的能力。

顺带解决第三个：首屏不再需要干等 18–20 秒，那段并发计算藏在医生说话的时间里。

## 2. 什么锁、什么不锁

**按「证据从哪来」分，不是按「重要不重要」分。**

| 一进来就给 | 为什么 |
| --- | --- |
| 硬规则红色风险 | 纯代码判定，不依赖模型也不依赖问诊。**危急值不能等** |
| 预警评估页 | 同上 |
| 阳性结果 / 检查检验 | HIS 已有数据，见 §2.1 |
| 健康档案 / 时间轴 | HIS 已有数据，见 §2.1 |
| 医嘱管理的**已开医嘱** | 患者主档 |
| 专项评估目录 | 静态字典 |
| 医生智能体（Copilot） | 对话本身就是入口 |

| 问诊后才给 | 为什么 |
| --- | --- |
| 智慧诊疗（病情概要 + 鉴别诊断） | 模型基于本次问诊推断 |
| 病历管理（病历草稿） | 同上 |
| 诊断管理 | 同上 |
| 共病管理 | 同上 |

> 医嘱管理里的**推荐用药 / 推荐检查**是模型产出，锁着时显示「待问诊后生成」，
> 与已开医嘱区分开。

### 2.1 客观数据当初挂错了出口（已修）

第一版上线后实测发现：**时间轴、检查记录、健康档案概览锁着时全是空的。**

原因不是设计错，是它们当初图省事挂在了 `report-summary` 这一个出口上 ——
而那个请求现在要等问诊。数据本身跟模型无关。

已拆出 `GET /api/emr/objective/{id}`（检查记录 + 时间轴，确定性、毫秒级），
入场时与红线、就诊状态一起并发拉。前端 store 提供 `examinations` / `timeline`
两个合并来源：有分析时用分析里的（可能更全），没有就用单拉的那份。

**教训**：「这块数据锁不锁」取决于它从哪来，而不是它显示在哪一页。
判断前先看它实际经过哪个出口。

### 2.2 「暂无风险项」是误导（已修）

预警评估页原本只渲染 `summary.risk_assessments`。锁着时那是空的，界面显示
**「暂无风险项」** —— 它读起来像「已评估、没风险」，而实际是**根本还没评估**。
这两种状态对医生的意义完全相反。

已改：这一页渲染「硬规则红线 + 模型风险」合并去重；未解锁且无硬规则命中时，
文案改为「硬规则已扫描，未发现危急值与过敏冲突。模型风险评估待问诊后生成 ——
这不等于『无风险』，只是还没评。」

**锁着的标签页留在原位、压暗、加 🔒，整页让位给说明卡。**

- 不让它消失：消失会让医生以为系统没这功能（与移动端 ＋ 菜单里那三个
  「工作站专属」同一个道理）。
- 不显示空面板：空面板会让人以为「分析跑失败了」，而不是「还没到时候」。

## 3. 状态机

```text
① 进入 ──开始问诊──▶ ② 问诊中 ──结束问诊──▶ ③ 已生成
  │                                              │
  └──────── 跳过问诊（标「未含问诊」）───────────▶ ┘
                                                 │
                            ◀──继续问诊（可逆）───┘
```

状态存在患者主档 `payload.analysis_unlock = {reason, at}`，**刷新后要能恢复** ——
否则医生问完一轮、刷新一下，八页又锁回去了。

`reason` 是闭集 `{interview, skipped}`，它决定界面标「含本次问诊」还是「未含问诊」。

### 契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/emr/visit-state/{id}` | `{interview_done, analysis_unlocked, unlocked_by, unlocked_at}` |
| POST | `/api/emr/analysis/unlock` | `{patient_id, reason}`。留审计 + 事件 |
| GET | `/api/emr/red-alerts/{id}` | 硬规则红线。**纯代码、毫秒级**，不触发四岗位并发 |

`voice/complete` 走完会**自动**以 `reason=interview` 解锁 —— 那是主路径，
跳过是例外。

### 结束问诊要把问诊期的东西全部收掉（2026-09-02 修）

> **这两个浮层已于同日整体撤掉，见 §9.1。** 下面这段记录保留：它讲的是
> 「两个同类元素判据不一致就会只坏一个」，那个教训与浮层在不在无关。

问诊中有两个浮层：「AI 追问提示」与「补充观察」。点完「结束问诊」，
**补充观察还挂在屏幕上**，盖着病历区，看着像问诊没结束。

两个浮层的显示判据不一样，所以只坏了一个：

| 浮层 | 原判据 | 结果 |
| --- | --- | --- |
| AI 追问提示 | `voice.active`（状态机派生） | 结束即消失，一直是对的 |
| 补充观察 | `voice.showObservations`（`start()` 里置 true，只有关闭按钮会清） | 结束后不消失 |

改法不是在 `finish()` 里补一句 `showObservations = false`，而是把判据本身补全：

```ts
// showObservations 只表示「医生有没有把它收起来」，不表示它现在可不可见
const observationsVisible = computed(() => active.value && showObservations.value)
```

放在 composable 里而不是模板里 AND 一下 —— **桌面与移动共用这一份**，
模板各写各的迟早会漏掉一处，这次漏的就是一处。

由此保住的两个行为，都有测试钉着：

- 结束后点「继续问诊」，浮层跟着回来（`active` 恢复）。
- 医生自己收起过的浮层，继续问诊时**不擅自弹回来** —— 「收起」是明确意图，
  不该被状态变化覆盖。

移动端同一个问题的另一种形态：`MobileVoiceSheet` 结束后不收起，
整张单子（追问清单 + 补充观察 + 继续问诊）留在屏幕上。已改为结束即 `emit('close')`。

### 顺带修：没录到内容时点结束，状态机不收尾

`finishAndGenerate` 原本写的是 `if (voice.messages.value.length) await voice.finish()`。
医生一句都没录就点结束，`finish()` 整个被跳过 —— 分析解锁了、病历也生成了，
状态机却停在 `awaiting`，界面仍是一副问诊进行中的样子。

**空判该在 `persist()` 里，不在调用方。** `finish()` 负责的是收尾
（停定时器、置 `ended`、收起浮层），这几件事跟有没有录到内容无关。

## 4. 跳过路径不能少

复诊、患者不配合、医生已自行问完 —— 这些情况下分析不能因此永远出不来。

二次确认里把后果讲清楚，而不是一句「确定吗」：

- 只用 HIS 已有资料，不含本次问诊
- 结果标注「未含问诊」
- 病历草稿里无出处的段落一律写「未采集」，不替患者编答案
- 随后仍可点「开始问诊」，问完重算一次

### 跳过时**不借用演示脚本**

`latest_dialog` 原本在没有真实 `VoiceSession` 时回落到种子演示脚本。
工作站这条路改成 `seed_dialog_fallback=False`：

> 拿一段医生从没做过的对话去生成「病情概要」「鉴别诊断」，比不给分析更糟 ——
> 那是把演示数据当成了本次问诊的事实。

回归集与控制台试运行仍保留回落（默认 `True`）：那些场景本来就不会有
`VoiceSession`，且它们需要对话来判「未问诊不写否认」。

## 5. 差点漏掉的一个洞

**把分析的加载时机往后挪，就必须把写回门禁补上。**

原本 `_assert_red_alerts_closed` 取「硬规则 + 缓存里的模型红线」。分析锁着时
模型红线还不存在，而七个种子病例又都不命中硬规则（只在过敏冲突与危急值时触发），
于是「未处置红线数」为 0，**门禁放行** —— 医生可以在从没跑过风险分析的情况下
提交病历、回写诊断。

改之前一进来就跑分析，红线总是在的；把时机挪后等于把门禁的分母改小了。

现在：**分析未生成即 409**，文案指向两条出路。

```
本次就诊尚未生成 AI 分析，风险未经评估，已阻断提交。
请先完成问诊，或选择「跳过问诊，直接分析」。
```

暂存**不受此门禁** —— 它的用途就是「还没弄完，先存着」。

前端的 `redAlerts` 也改成「硬规则 + 模型」合并去重，不再只取 summary。

## 5.1 移动端一度整个漏了门禁（已修）

门禁是后加的，移动端分析页比它早。第一版上线后实测：

- 对话页 **0 张开场卡** —— 医生进来是一片空白
- 分析页八块**全是 0**，且没有任何解释 —— 只会以为「跑失败了」

已补齐：对话页锁着时给一张说明卡（写清原因 + 开始问诊 / 跳过两条出路，
并指明「记录」页现在就能看）；分析页受门禁的四块给出原因而不是干放一个 0；
跳过解锁后同样如实标「未含问诊」。

**教训记在这里**：加一层跨页的门禁时，「哪些页受影响」要按**数据来源**盘一遍，
不能只改自己正在看的那个端。

## 6. 当前的一个空窗

**七个种子病例一条硬规则红线都不命中**（`hard_rule_alerts` 只在过敏冲突与
危急值时触发）。所以红线横幅虽然接好了、有测试守着，演示时不会出现。

这不影响安全性 —— 第 5 节那道「未生成分析不得写回」才是这一阶段真正在起作用的门。
但如果要演示红线路径，需要给某个病例加一条危急值（如血钾 6.8 mmol/L）。
**这属于造演示数据，等产品决定。**

## 7. 门禁脚本要跟着改

受门禁的四页在问诊前取不到任何元素，`compare-v43-fidelity.mjs` 与
`check-v43-coverage.mjs` 都要先把取样患者推进到「问诊已完成」。

走 `voice/complete` 而不是 `analysis/unlock`：前者会落一份真实 `VoiceSession`，
上下文里就有对话，产出的内容量与原件可比；后者是「跳过」，没有对话，
分析会明显更薄，比的就不是同一个东西了。

改完实测：**146 元素零差异零缺失、八个标签页零类名缺失。**

## 9. 三处大改（2026-09-02）

### 9.1 撤掉「AI 追问提示」与「补充观察」

这两块给的是「接下来该问什么」的**临床建议**，而一期没有临床知识库支撑。
**建议错一条的代价大于不给建议** —— 何况它出现在医生正在问诊的那一刻，
干扰最直接。产品决策，不是技术限制。

同一条原则贯彻到底，所以 `voice/turn`（手动补问时「取下一句追问建议」）
也一并撤了：它和被撤的两块是同一类东西，只是从常驻改成了按需。

**手动补录保留** —— 记录患者原话是纯事实，没有准不准的问题。
`askManual` 改名 `recordPatientUtterance`，不再发请求，内容随「结束问诊」落库。

连带三处：

| 改动 | 原因 |
| --- | --- |
| `voice/init` 不再调模型 | `voice_plan_agent` 的全部产出就是这两份清单。没有消费方后，留着那次调用等于每点一次「开始问诊」白花 7.3 秒与一次真实模型费用，换一份直接丢掉的输出 |
| `/voice/coverage` 删除 | 只为追问清单的「已问到」判定服务 |
| 控制台 voice 岗位改指 `voice_summary_agent` | 它才是产品路径上真正在跑的那个（问诊小结，归纳对话里实际说过的内容，有出处） |

`voice/init` 的 `questions` / `observations` 字段**保留但恒为空**：形状不变，
且没人能顺手接回去而不被发现。有测试钉着这一点，也钉着两个端点不许复活 ——
这类东西很容易因为「先接上看看」而复活，而复活时不会有人重新问一遍
「现在有知识库了吗」。

### 9.2 HIS 门面整块撤掉

这套界面复刻的是 V4.3 演示件，**不是北大国际医院的真实 HIS**，而链接会被
转发出去 —— 一个长得像 HIS 的页面很容易让人以为「已经和院内系统打通了」。

撤掉：左侧患者头像栏、门诊病历表单、医嘱面板、阳性结果、转诊 / 住院。
`WorkstationView.vue` 从 768 行降到 366 行。

**病历没有消失。** AI 助手里本来就有自己那一份（「病历 AI 生成」那一栏），
它才是 AI 草稿的落点与「确认后写回」的发生地。撤掉的是那份仿真的 HIS
数据展示，留下的是 AI 真正产出的东西。

页头保留一条**常驻、不可关闭**的标识：「演示环境 · 未接入任何院内 HIS」。
它不是提示，是声明。

### 9.3 AI 助手改成医生智能体的可展开扩展

| 时机 | 行为 |
| --- | --- |
| 进入工作站 | **只有医生智能体**，AI 助手收起 |
| 问诊中 | 仍收起，但开关一直在，医生想现在看就点 |
| 结束问诊 | **自动展开**，并标「刚刚自动展开」 |
| 任何时候 | 可手动开合 |

默认收起的理由与问诊门禁同源：病历、鉴别诊断、风险、共病都由这一场问诊推导，
问诊前先把结论摆出来，会让医生把「模型基于旧资料的猜测」当成本次判断 ——
界面不该反过来把门禁的结论提前展示。

开关做成**一整块带说明文字的卡片**（`.assistant-toggle`），不是原来那个
`‹ ›` 小箭头：它要承担「AI 助手是医生智能体的延伸」这个意思，一个箭头
承担不起，而且医生第一次用时根本不知道那里可以点。
收起态虚线灰框、展开态实线蓝框加蓝底，两态差别一眼可辨。

### 9.4 两道界面闸跟着收窄

撤掉的部分不再复刻 V4.3，留在门禁里只会每次报「缺失」——
而**「缺失」的含义应该是「漏做了」，不是「有意没做」**。

- 门诊工作站场景的选择器收窄到 AI 助手内部（页头与身份条保留）
- 「阳性结果展开态」整个场景移除
- 「语音问诊播放中」摘掉 `.pending-*` / `.pq-*` 六个类
- 两个脚本的 `ensureAiFloat` / `ensureFloat` 改用 `.assistant-toggle` 先展开抽屉，
  否则抽屉不在 DOM 里，八页会被报成「全缺」
