# Agent 岗位与调优 Mockup 详细规格

版本：`v0.1-draft`  
主责：Agent 岗位定义和调优条线  
当前策略：先完成岗位、上下文、输出、评测和 Mock；后续逐步接入真实模型、Skills 和 AgentScope。

## 1. 本条线的当前交付

当前不要求六个 Agent 达到生产精度，但必须先把“什么时候调用、拿什么上下文、允许做什么、返回什么、怎样评测”定义清楚。

一期前期交付包括：

- 六张 Agent 岗位卡。
- 七个产品任务到六个岗位的映射。
- 上下文装配规则。
- 结构化输出规则。
- Mock 结果与错误场景。
- 评测数据集格式和评分规范。
- 零容忍安全门禁。
- 版本回归报告模板。

## 2. 统一岗位卡模板

每个 Agent 必须维护以下字段：

| 字段 | 含义 |
| --- | --- |
| `agent_id` / `version` | 稳定岗位标识与版本 |
| 目标 | 对医生完成的临床任务负责 |
| 非目标 | 明确不承担的任务 |
| 调用条件 | 自动事件、医生主动调用和前置状态 |
| 输入 | 必需、可选和禁止输入 |
| 上下文策略 | 数据范围、时效、裁剪、冲突处理 |
| 允许能力 | Skills、MCP 和知识范围 |
| 输出 | `semantic_result_v1` 的具体字段 |
| 禁止行为 | 临床与技术红线 |
| 澄清规则 | 哪些缺口必须询问，哪些可以降级 |
| 失败路径 | 超时、工具失败、缺数据和非法结果 |
| 质量指标 | 准确性、完整性、安全性和可用性 |
| 责任人 | 临床、技术、评测和集成负责人 |

## 3. A1 语音问诊智能体

### 3.1 岗位目标

将医患对话转成可复核转写和结构化病史，识别最少必要的追问。

### 3.2 调用条件

- 医生主动开始语音问诊。
- 医生对某一病历段落发起“补充问诊”。
- 不允许在无明确录音状态时后台运行。

### 3.3 必需上下文

- 当前患者和就诊身份。
- 当前科室与专科问诊模板。
- 已知主诉、过敏、长期用药和特殊状态。
- 实时音频转写段落及时间戳。

### 3.4 输出

- 说话人分离后的转写段落。
- 医学实体、否定、时间、主体、程度和关系。
- 结构化主诉与病史字段。
- 低置信片段。
- 阻断与非阻断澄清问题。

### 3.5 禁止行为

- 把未提及内容补为阴性病史。
- 把家属陈述当成患者自述。
- 删除低置信原文或音频定位信息。
- 未经医生确认直接写入正式病历。

### 3.6 Mock 场景

- 内分泌典型问诊。
- 骨科疼痛部位与红旗追问。
- 妇科隐私与妊娠状态澄清。
- 噪声导致低置信转写。
- 关键症状漏问后进入澄清。

### 3.7 指标

- 医学实体 Precision/Recall/F1。
- 否定、时间和主体识别准确率。
- 关键红旗信息召回率。
- 医生逐句纠错率。
- 虚构阳性/阴性事实：零容忍。

## 4. A2 病情概况智能体

### 4.1 岗位目标

形成问题导向的病情概况，突出本次变化、关键证据、冲突和缺失。

### 4.2 调用条件

- 打开患者就诊。
- 问诊结束。
- 关键检验检查、诊断或用药更新。
- 医生主动刷新。

### 4.3 上下文

- 本次问诊与病历。
- 纵向诊断、用药、检验、检查和生命体征。
- 数据来源、时间、状态和版本。
- 专科问题清单模板。

### 4.4 输出

- 一句话摘要。
- 按临床优先级排序的问题清单。
- 纵向变化和趋势。
- 关键证据引用。
- 数据冲突与缺失。

### 4.5 禁止行为

- 跨患者混用数据。
- 把过期数据写成当前事实。
- 静默合并冲突来源。
- 用长篇背景淹没当前主问题。

### 4.6 指标

- 关键事实覆盖率。
- 证据可追溯率。
- 事实一致率。
- 冲突识别召回率。
- 冗余率和医生阅读时间。

## 5. A3 病历生成智能体

### 5.1 岗位目标

将已确认事实组织为符合专科模板的门诊病历草稿。

### 5.2 调用条件

- 医生主动生成整份病历。
- 医生生成或刷新单个段落。
- 问诊结束后只提示可生成，不自动写回。

### 5.3 上下文

- 已确认结构化问诊。
- 病情概况和证据引用。
- 医生已有输入。
- 专科模板、术语和字段约束。

### 5.4 输出

- 分段病历草稿。
- 每个段落的来源映射。
- 不确定性和待补字段。
- 模板、术语、事实一致性校验结果。

### 5.5 禁止行为

- 生成未证实体征或结果。
- 把待排诊断写成确诊。
- 覆盖医生已有内容。
- 自动写回。

### 5.6 指标

- 字段完整率。
- 事实一致率。
- 来源覆盖率。
- 医生修改距离/修改率。
- 幻觉事实：零容忍。

## 6. A4 诊断智能体

### 6.1 岗位目标

同时承载两个任务：

- 鉴别诊断：候选、证据和下一步。
- 诊断管理：主诊断、次诊断、待排诊断和变更原因。

### 6.2 调用条件

- 病情概况就绪。
- 关键检查结果回传。
- 医生主动调用。
- 诊断列表发生变化。

### 6.3 上下文

- 病史、体征、检验检查。
- 当前诊断、用药和风险。
- 专科知识、诊断标准、ICD 术语。
- 数据时间和证据等级。

### 6.4 鉴别诊断输出

- 候选诊断及排序。
- 支持与反对证据。
- 缺失信息。
- 建议补充问诊/检查。
- 必须排除的高风险诊断。

### 6.5 诊断管理输出

- 主诊断草稿。
- 次诊断草稿。
- 待排诊断。
- 诊断变化与原因。
- ICD 编码候选。

### 6.6 禁止行为

- 替医生确认诊断。
- 把置信度当作临床概率。
- 把待排改成确诊而无医生动作。
- 隐藏反对证据或关键缺失。

### 6.7 指标

- 关键候选召回率。
- Top-K 排序质量。
- 支持/反对证据一致率。
- 确诊与待排区分准确率。
- 高危诊断漏项：零容忍门禁集为 0。

## 7. A5 风险管理智能体

### 7.1 岗位目标

全程旁路识别患者安全风险，并在其他 Agent 结果进入产品前进行安全校验。

### 7.2 触发

- 患者/就诊身份建立或变化。
- 过敏、用药、生命体征、检验检查更新。
- 病历或诊断草稿变化。
- 任一 Agent 生成结果。

### 7.3 上下文

- 身份、过敏、用药、生命体征。
- 检验检查、诊断和病历草稿。
- 红旗规则、药品规则和特殊人群规则版本。

### 7.4 输出

- 风险级别。
- 规则或模型来源。
- 证据和数据时间。
- 建议动作。
- 是否阻断及确认要求。

### 7.5 禁止行为

- 用低置信模型结果覆盖确定性红线规则。
- 在证据不足时把红色风险静默降级。
- 把风险提示直接变成医嘱。

### 7.6 指标

- 红旗召回率。
- 误报率。
- 风险可行动性评分。
- 规则覆盖率。
- 身份、过敏和强制红线漏报：0。

## 8. A6 共病管理智能体

### 8.1 岗位目标

识别影响本次诊疗的共病与特殊状态，提供有优先级的管理建议。

### 8.2 触发

- 病情概况完成。
- 诊断或长期用药变化。
- 医生主动调用。

### 8.3 上下文

- 问题清单、长期诊断和长期用药。
- 检验趋势和随访记录。
- 年龄、妊娠等特殊状态。
- 本次主诉与诊疗目标。

### 8.4 输出

- 共病及当前状态。
- 与本次就诊的关系。
- 管理缺口和目标。
- 建议动作、随访、转诊/会诊。
- 优先级和证据。

### 8.5 禁止行为

- 忽略本次主诉优先级。
- 输出与本次无关的大量泛化建议。
- 未经医生确认直接生成转诊或医嘱。

### 8.6 指标

- 相关共病覆盖率。
- 无关建议率。
- 建议可执行性。
- 主诉优先级一致率。
- 医生采纳/暂不处理/无关反馈分布。

## 9. 上下文五层结构

| 层级 | 内容 | Mock 阶段 |
| --- | --- | --- |
| L1 任务上下文 | 当前功能、医生意图、触发、输出 Schema | 真实生成 |
| L2 就诊上下文 | 主诉、问诊、体征、诊断、医嘱、最新结果 | Fixture |
| L3 患者纵向上下文 | 历史病历、慢病、过敏、长期用药、趋势 | Fixture |
| L4 专科知识上下文 | 规则、指南、模板、术语、红旗清单 | Mock 版本化知识包 |
| L5 运行上下文 | Agent/Skill/MCP 版本、权限、预算、Trace | 真实生成 |

上下文原则：最小充分、来源清晰、时间明确、冲突显式、权限受控。

## 11. 评测数据集结构

每条评测样本建议包含：

```json
{
  "case_id": "endo_t2dm_0001",
  "dataset_version": "endo_eval_v0.1",
  "specialty": "endocrinology",
  "scenario": "t2dm_follow_up",
  "difficulty": "typical",
  "risk_tags": ["poor_glycemic_control"],
  "input_context": {},
  "task_type": "condition_summary",
  "gold_result": {},
  "must_include": [],
  "must_not_include": [],
  "hard_gate_labels": [],
  "scoring_rubric": {},
  "clinical_reviewers": [],
  "provenance": {},
  "deidentification_status": "verified"

```

### 11.1 样本类型

- 典型病例。
- 边界病例。
- 关键数据缺失。
- 数据冲突。
- 高风险红旗。
- 特殊人群。
- 跨次就诊纵向变化。
- 多共病和用药冲突。
- 工具失败或过期数据。

### 11.2 初期数量建议

每个专科包进入离线门禁前至少 50 例，其中高风险和边界病例不少于 20%。前期 Mock 阶段可先用每科 8–12 例覆盖 UI 与契约，不能把 Mock 样本冒充临床金标准。

## 12. 评分框架

### 12.1 通用评分维度

- 事实准确性。
- 关键内容完整性。
- 证据一致性和可追溯性。
- 时间与主体识别。
- 不确定性表达。
- 临床相关性。
- 输出结构合法性。
- 医生可操作性。

### 12.2 评分方式

- 结构化字段：确定性比较或字段级 F1。
- 排序列表：Top-K Recall、NDCG 或临床分级评分。
- 长文本：临床 Rubric 双人评分，不以单一 LLM Judge 作为最终门禁。
- 安全风险：独立硬门禁，不被总体平均分抵消。
- 医生编辑：修改距离、修改原因和最终采纳率作为线上反馈指标。

## 13. 零容忍门禁

| 门禁 | 标准 |
| --- | --- |
| 患者/就诊身份错配 | 0 例 |
| 伪造临床事实、检验或检查 | 0 例 |
| 未经医生确认写回 | 0 例 |
| 强制红色风险规则漏报 | 0 例 |
| 非法 Schema 进入产品 | 0 例 |
| 越权读取患者数据 | 0 例 |

Mock 阶段也必须用故障注入验证这些门禁是否真正生效。

## 14. 错误分类

每个错误必须归入至少一类：

- 数据缺失。
- 数据错误或冲突。
- 上下文选择错误。
- 专科知识或规则错误。
- 推理/生成错误。
- Skill/MCP 工具错误。
- 输出结构错误。
- 产品映射或展现错误。
- 医生操作或流程理解错误。

错误分类决定由哪条线负责修正，避免所有问题都归为“Prompt 不好”。

## 15. Mock 输出策略

- Mock 结果来自版本化 Fixture，不从前端组件硬编码。
- Fixture 保留来源引用、缺失、冲突、风险和不确定性字段。
- 每次 Mock 调用记录 Agent 版本、场景 ID 和 Trace。
- 同一输入和版本默认返回确定性结果，便于回归测试。
- 可通过测试配置开启延迟、超时、非法 Schema 和随机失败，但生产构建禁用测试开关。

## 16. Worker、岗位与 Sub-agent（待讨论）

以下内容仅用于后续架构讨论，不是已经确认的 AgentScope 实现：

| 概念 | 建议工作定义 | 当前处理 |
| --- | --- | --- |
| Agent 岗位 | 长期稳定、可治理、对任务结果负责的职责主体 | 暂按 6 个岗位建卡 |
| Worker | 某次任务运行中的执行单元，可负责上下文、工具、校验或审计 | 只预留接口，不确定数量和编排 |
| Skill | 稳定、可测试的业务能力 | 优先候选，但目录待讨论 |
| Sub-agent | 主 Agent 委派的独立内部任务主体 | 默认不启用；适用场景待讨论 |

待讨论问题：

- 上下文装配、安全校验、输出校验是 Worker、Skill 还是集成层服务？
- 诊断证据检索是否需要独立 Sub-agent？
- 共病复杂审查是否值得独立上下文和工具策略？
- Sub-agent 是否最多一层，是否禁止直接向产品返回？
- 如何用评测证明 Sub-agent 比 Worker/Skill 更有收益？

在讨论结论形成前，产品和集成契约不得依赖某种内部拆分。

## 17. 调优线 Definition of Done

- 六个岗位都有完整岗位卡和版本。
- 七个任务都有调用条件、最小上下文和结构化输出。
- 三专科都有 Mock 场景和评测样本模板。
- 正常、缺失、冲突、高风险、超时和非法结果可稳定复现。
- 通用指标、岗位指标和零容忍门禁可运行。
- 错误能归因并进入版本化回归集。
- Worker、Skill、Sub-agent 未决内容明确标注“待讨论”。
