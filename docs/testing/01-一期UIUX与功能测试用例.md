## 1. 测试目标

验证一期产品在不改变最早 HTML 主体 UI/UX 的前提下，能够完成候诊列表直达、点击患者进入医生智能体、7 个产品功能、6 个 Agent 的 Mock 集成、人工确认、模拟写回、患者隔离和安全降级。

## 2. 测试范围

- UI 基线与路由。
- 未选择患者和患者绑定。
- 语音问诊、病情概况、病历生成、鉴别诊断、诊断管理、风险管理、共病管理。
- 加载、澄清、成功、过期、失败、降级、编辑、采纳、拒绝和模拟写回状态。
- 内分泌代谢、普通骨科和普通妇科 Mock 数据。
- 患者错配、版本冲突、来源缺失、迟到响应和红色风险门禁。

不在一期自动化验收范围：真实录音留存、真实 HIS/EMR 写回、真实临床阈值正确性、正式 SSO、生产性能容量和真实患者数据。

## 3. 测试环境与通用前置

1. 使用 Mock 环境和去标识化 Fixture，禁止导入真实患者数据。
2. 当前运行模式显示 `mode=mock`，真实写回 Adapter 关闭。
3. AgentScope 可使用 Mock Adapter；失败、超时、非法 Schema 和迟到响应可注入。
4. 每个测试开始前清理浏览器临时状态、当前患者、未完成任务和模拟写回回执。
5. 关键测试同时检查页面结果、API/任务状态、审计事件和患者/就诊 ID。

## 15. 退出标准

一期进入下一阶段前必须满足：

1. `TC-SAFE-*` 全部通过，任何患者串用、红色风险漏显、无因关闭或真实写回均为零容忍。
2. 七个功能的典型、缺失、冲突、风险和失败路径均至少有一个通过用例。
3. 内科、骨科、妇科各至少一个典型病例和一个安全病例完成 UI 演示与结果核对。
4. 当前 HTML 与实现逐屏对照无未经确认的布局、视觉和交互差异。
5. 所有 Mock 写回和任务回执可追溯，医生输入在失败、刷新、重试和患者切换中不丢失。

临床准确性和专科规则上线门槛需在临床专家完成金标准标注后另行签字，不以本 UI 测试代替。
