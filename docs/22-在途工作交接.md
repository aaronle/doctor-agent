## 3. 主题收敛：动了全仓 CSS，这段必须读

### 3.1 障碍

扫描全仓：**1372 处硬编码颜色、303 种色值**，且 `:root` 那套设计令牌**基本没被消费** ——
令牌写 `--blue: #3b6ef5`，但用得最多的蓝是 `#1677ff`（111 次）。
蓝色系长尾极重，前 30 种也只覆盖 67.8%，**逐个枚举替换做不完**。

### 3.2 做法：带回退值的变量替换

```css
/* 替换前 */  .btn { background: #1677ff; }
/* 替换后 */  .btn { background: var(--t-1677ff, #1677ff); }
```

**默认主题不定义任何 `--t-*` 变量**，全部走回退值 → 计算样式与收敛前逐字节相同。
其他主题在 `[data-theme="x"]` 下定义全部变量 → 100% 覆盖，不存在遗漏色块。

实测结果：

```
品牌色替换  401 处 / 73 种  → 生成 2 套主题
状态色跳过  336 处          ← 红/橙/绿，临床语义，绝不纳入
中性色跳过  865 处          ← 本期不做深色主题
```

已验证的六条不变量（`styles/themes.spec.ts` 逐条钉住）：

1. 401 处 `var(--t-X, #Y)` 中 X 全部等于 Y —— 默认态逐字节不变
2. 源码里 0 个状态色被包成主题变量
3. 生成的主题文件里 0 个状态色定义
4. 两套主题各定义 73/73 个变量，无缺漏
5. 不存在 `theme-default.css`
6. 圆角与 `--el-font-size-base` 未被主题触及

### 3.3 分类阈值是量出来的，不是拍的

蓝色相区间里饱和度分布有一段空档：

```
0.10 – 0.48  全是冷灰与墨（#1a2a4a 0.48、#f4f6fa 0.375、#1f2937 0.279 …）
0.48 – 0.90  空的
0.90 – 1.00  全是真品牌蓝（#1677ff 1.0、#3b6ef5 0.903、#eaf1ff 1.0 …）
```

阈值取 `0.6`，落在空档里两边都不误判。

> **第一版用 0.12 是错的**，会把 `#1f2937`（正文墨色）、`#e8ebf0`（分隔线）、
> `#f4f6fa`（页面底色）当成品牌色收敛掉 —— 换主题时正文和背景会跟着变色。
> 琥珀色带上界也从 45° 放宽到 65°，否则 `#fffbeb`、`#fde68a`（色相 48°）会漏成 other。

### 3.4 状态色为什么绝不纳入

红、橙、绿共 336 处排除在外。**理由是临床安全，不是审美**：
医生换成护眼主题后危急值也变绿，那是会出人命的。

配置页的预览区里专门放了一条风险条，作用就是让医生在切换前当场看到红色不变。
`SettingsView.spec.ts` 有一条用例钉住它 —— 删了这块预览测试会失败。

## 4. 三个设计取舍（改之前先看理由）

**① 不沿用 `agent_versions` 的草稿→发布→回滚。** 那套是为「影响所有患者、
出事要追责」设计的；个人偏好影响半径只有本人、无临床后果、是即时生效的单人操作。

**② 只存与默认值的差异。** 以后调整默认值，所有没显式设过该项的医生会跟着变。
存全量会把每个人钉死在他第一次打开配置页那天的默认值上。
「恢复默认」因此是**删行**。

**③ 主键 `actor` 不可信。** 一期没有 SSO，它来自前端 `stores/session.ts` 的医生名，
任何人都能伪造。**不作访问控制依据** —— 伪造的后果仅限于改掉别人的界面颜色。
接 SSO 后换工号，表结构与逻辑都不变。

### 顺带修的一个真 bug

`update()` 原来无条件 `apply(saved.prefs)`。响应体一旦不是预期形状（网关空体、

医生不点配置页的情况下调 `update()`。

一次同步失败的合理后果是「这次没同步上」，不是「界面塌了」。
