# 全面走查与并发修复（2026-09-07）

目标：把整套系统压一遍，修掉真 bug，把手感打磨顺。

结论：**修了 3 个真问题**（其中 1 个是严重的性能缺陷），
新增 `scripts/full-audit.mjs` 作为常设走查，49 项检查。

---

## 一、最要紧的那个：120 并发 → 44 个超时

压测打的是 `telemetry/events` 与 `his/board`，**两个都不调模型**。

```
修复前：120 并发，耗时 30.2s，失败 44 个
修复后：120 并发，耗时  0.3s，失败  0 个
```

慢的不是 AI，是数据库把请求排成了一条队。两个叠加的原因：

### ① 连接池装不下线程池

SQLAlchemy 默认 `pool_size=5, max_overflow=10` 共 15 条，
而 FastAPI 把同步 handler 丢进一个 **40 线程**的池里跑。
第 16 个并发请求开始就在等连接，等满 `pool_timeout=30` 秒。

报错是 `QueuePool limit of size 5 overflow 10 reached, timeout 30.00` ——
但医生那边**没有报错，只有转圈**。

改成 `20 + 40`，并把 `pool_timeout` 压到 10 秒：真拿不到连接时快点失败，
挂着不动谁都不知道发生了什么。

### ② SQLite 跑在回滚日志模式

`journal_mode=delete` 下**读挡写、写挡读**。这个应用绝大多数请求是读
（候诊列表、看板、患者详情），而埋点在持续写。

改 `WAL` 之后读永远不被写挡住。同时：

| PRAGMA | 改成 | 为什么 |
| --- | --- | --- |
| `journal_mode` | `WAL` | 读写解耦 |
| `busy_timeout` | `15000` | 写写仍互斥，等久一点好过抛 `database is locked` |
| `synchronous` | `NORMAL` | 不再每次提交都 fsync；WAL 下仍崩溃安全 |

**PRAGMA 必须挂在 `connect` 事件上，不是启动时设一次。**
`journal_mode` 是库级持久设置，但另外两个是**连接级**的 ——
池扩容出来的新连接得各自设一遍，而扩容恰恰发生在并发高的时候。

### WAL 的两个副作用（都已处理）

- **数据不止一个文件**：主库旁边多出 `-wal` / `-shm`，且主库可能长期只有几 KB
  （实测主库 4 KB / WAL 984 KB）。备份或搬迁必须三个一起拷，
  或先 `PRAGMA wal_checkpoint(TRUNCATE)`。已写进 `deploy/tencent-guangzhou/README.md`。
- **测试清库要连伴生文件一起删**，且**删之前先 `engine.dispose()`**。
  回滚日志模式下删一个还开着的库只是摘掉目录项，已有 fd 照常能用；
  WAL 不行 —— 伴生文件被抽走后，池里的连接下一次用就是 `disk I/O error`，
  而报错文字完全不提 WAL，看起来像磁盘坏了。

## 二、埋点不该和临床请求抢连接

`useTelemetry` 的常规攒批上报带着 `keepalive: true`。那是给
「页面正在卸载」用的，而那一次已经走 `sendBeacon`。

常规上报加它没有好处，却要占 Chromium 的 keepalive 配额（全局 64KB，
生命周期不跟随页面）。已改成**只在卸载分支加**。

## 三、过敏标记的字形不一致

`confirmed` 用 `⚠`（emoji，彩色），`unknown` 用 `?`（ASCII）——
并排看像是后者的图标没加载出来。而同一个信息在科室看板和移动端
都只写文字、不带 `?`，三处对不上。

定案：**危险有图标，信息缺口没有**。`⚠` 表示「有过敏原，会出事」；
「没人问过」是采集缺口，琥珀色已经把它和红色分开了。

## 四、常设走查 `scripts/full-audit.mjs`

与既有两个脚本的分工：

| 脚本 | 回答什么 |
| --- | --- |
| `smoke-prod.mjs` | 页面白不白 |
| `demo-check.mjs` | 演示那条主线还成不成立 |
| **`full-audit.mjs`** | **每一处点下去有没有坏、卡不卡** |

49 项，覆盖桌面全流程（拖动/停靠/字号/全屏/卡通/看板/设置）、
临床主线（门禁→跳过→八页→回写拦截）、切患者、抗乱点、
移动端（安全条/字号/三档/溢出）、其余四个页面。

### 它自己踩过的坑，都记在脚本里了

- **不要调 `demo-reset.mjs`** —— 那个脚本通过 SSH 改**生产库**。
  第一版调了它，等于让一次本地走查改掉了线上演示状态。
  已给 `demo-reset.mjs` 加了 `--yes-production` 确认闸。
- **「解锁后锁标记消失」第一版是空过的** —— 抽屉收起时 `.ttab` 是 0，
  「锁标记 0 个」于是永远成立。改成先断言标签栏在场。
- **门禁与主线要用不同患者** —— 拿同一位来测，第二轮它已被上一轮解锁。
- 慢与坏要分开：分析未在 300s 内返回记为**观测项**；
  「转圈却没有在途请求」才判缺陷 —— 那是死锁不是慢。

### 一次诚实的记录：5 个发现里 4 个是假阳性

第一版跑出 5 个问题，逐条查下来只有 1 个是真的：

| 报的 | 实际 |
| --- | --- |
| 卡通没出现 | 我查的类名错了（是 `.mascot` 不是 `.agent-mascot`） |
| 看板没有行 | 选择器 `table tbody tr` 把 HIS 门面的医嘱表也数了 |
| 拖动位移对不上 | 我拿面板左边当起点算，把半个面板宽也算进了期望值 |
| 进入工作站 28s | 我等的是 `networkidle`，量到的是模型耗时不是首屏（实际 119ms） |
| 过敏字形不一致 | **真的** |

**走查脚本本身也要被怀疑。** 一份噪声大的走查比没有更糟 ——
它会训练人忽略红色。
