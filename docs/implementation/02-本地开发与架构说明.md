# Doctor Agent 本地开发与架构说明

版本：`v0.2`
日期：`2026-08-28`
状态：一期七功能 Mock 产品闭环已实现

## 1. 当前可运行范围

当前代码已实现：

- 本地演示无需登录，打开系统直接进入 `#/outpatient/list` 候诊列表；可通过 `VITE_DEMO_AUTO_ENTRY=false` 关闭自动进入，为正式 SSO 集成保留入口。
- 候诊列表展示六个三专科演示病例；点击患者卡即进入工作站并自动展开医生智能体和智慧诊疗结果。
- 原 V4.3 工作站的左侧门诊病历、中间 AI 助手、右侧医生智能体三栏信息架构。
- 一期七个功能入口及七类正式任务路由。
- 语音问诊的 Mock 录音状态机、分角色转写、低置信提示、人工校正、结构化问诊和澄清项。
- 病情概况的摘要、主要问题、趋势、数据时间、缺失/冲突和医生动作。
- 病历生成的六段草稿、段落级采纳/编辑/拒绝、质量校验和模拟写回回执。
- 鉴别诊断的优先级、支持/反对证据、缺失信息、不确定性和医生决策。
- 诊断管理的唯一主诊断、状态管理、一致性校验和模拟写回回执。
- 风险管理的红/黄分级、证据、阻断门禁和处置状态闭环。
- 共病管理的分组、相关性、照护缺口、相互影响、风险联动和模拟随访。
- 医生点击功能后默认生成正常演示结果；需要澄清、数据冲突、降级、运行失败、Schema 拒绝通过测试接口注入，不在医生界面暴露场景选择器。
- 患者/就诊一致性校验、患者切换清空结果、结果版本、幂等键和审计事件。
- 红色风险未闭环时阻断病历/诊断 Mock 写回；一期不连接真实 HIS 写回。

## 2. 当前架构

```text
Vue 3 Web
  → Product API / Agent Gateway（FastAPI）
    → Task/Result Schema v1
      → Mock Runtime（当前）
      → AgentScope Adapter（后续）
    → SQLite（本机）/ PostgreSQL（Dev、UAT、正式环境）
    → Audit Event / Mock Write Back
```

产品界面只理解任务、结果和卡片契约，不读取 Prompt、模型或 AgentScope 内部字段。

MVP `v0.2` 将当前 Runtime 明确实现为六个版本化 Mock Agent。它们共用同一个 FastAPI 进程和契约，不需要 AgentScope、模型 API 或独立 Agent 容器。

## 4. 首次启动

需要 Node.js 20+ 和 Python 3.11+：

```sh
cd "/Users/leying/Documents/北大医疗/AI Native Systems/projects/doctor-agent"
npm install
python3 -m venv .venv
.venv/bin/python -m pip install -r apps/api/requirements.txt
npm run dev
```

默认地址：

- 产品：`http://127.0.0.1:4173`
- API：`http://127.0.0.1:8000`
- OpenAPI：`http://127.0.0.1:8000/docs`

如果 4173 被其他服务占用，Vite 会选择下一个端口；当前浏览器验证使用 4173。

## 6. 数据库策略

本机默认使用 `sqlite:///./doctor-agent.db`，减少 Mac 首次运行依赖。Dev、UAT 和正式环境设置：

```env
DOCTOR_AGENT_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/doctor_agent
```

当前表包括 `agent_tasks`、`task_events` 和 `audit_events`。正式环境启用 PostgreSQL 前还需增加 Alembic 迁移、医院备份策略、字段级数据分级和留存/删除规则。

## 7. 仍未接入的正式能力

- 医院 SSO、医生权限和真实科室数据。
- AgentScope 鉴权、流式协议、超时、重试、Nacos 和观测接口。
- HIS/EMR/LIS/RIS/PACS/知识库 MCP 与真实临床上下文。
- 真实写回适配器；当前安全门禁固定为 `mode=mock`。
- 真实语音设备与转写服务、正式诊断编码服务和经临床专家签字的专科规则版本。

这些接口均须在已生成的 v1 契约边界内逐步接入；不得让产品组件直接耦合运行平台内部字段。

## 8. 广州 MVP 部署

`deploy/tencent-guangzhou/` 提供面向 `da.aaronhealth.cn` 的单容器定义。镜像使用 Node 构建 Vue，最终仅运行 FastAPI；FastAPI 同源提供前端静态文件和 `/api/v1/*`。SQLite 挂载到 `/opt/doctor-agent/data`，宿主机只暴露 `127.0.0.1:3400`，再由现有 Nginx 终止 HTTPS。

该架构特意不引入 PostgreSQL、Redis、向量数据库、Langfuse、本地模型或 AgentScope，仅用于虚构病例的公开 MVP 体验。
